O botão **Simular Incidente** cria um incidente sem precisar de Sentry, webhook ou assinatura. Foi feito para a demonstração ao vivo e para testar a configuração de uma aplicação: ele monta um payload de **webhook genérico** e o passa pelo [mesmo pipeline](/registro-e-trigger) de um erro real (adapter, deduplicação e regras de acionamento).

::warning
**A simulação pode acionar os agentes de verdade.** Se as regras da aplicação decidirem `trigger`, o incidente vai para a fila e uma investigação **real** começa: clona o repositório, roda o Claude e consome créditos. Para ensaiar a tela ao vivo sem custo, use o `firewatch:replay-run` ou o modo `DRY_RUN` ([Testar sem gastar créditos](/ambiente-e-setup/testar-sem-creditos)). Para só registrar o incidente, desligue **Acionar agentes automaticamente** na aplicação antes de simular.
::

## O endpoint

```http
POST /api/v1/application/{application}/simulate-incident
```

| | |
|---|---|
| Controller | `ApplicationController::simulateIncident()` |
| Middlewares | A pilha do painel (`auth:sanctum`, `ensure-user-active`, `ensure-password-change`) + `throttle:30,1,simulate-incident` |
| Request | `SimulateIncidentRequest` |
| Action | `SimulateIncidentAction` |

### Corpo

Todos os campos são opcionais: um corpo vazio simula o cenário padrão.

| Campo | Regras | Padrão |
|---|---|---|
| `title` | texto, até 512 | `Simulação: erro disparado pelo painel do Firewatch` |
| `stack_trace` | texto, até 20 000 | nenhum |
| `severity` | `debug`, `info`, `warning`, `error`, `critical` | `error` |
| `environment` | texto, até 255 | O **primeiro** ambiente das regras da aplicação, ou `production` |
| `occurrences` | inteiro, 1 a 10 000 | `1` |
| `affected_users` | inteiro, 0 a 1 000 000 | `0` |
| `deduplicate` | booleano | `false` |

O ambiente padrão é escolhido para a simulação **passar** pela regra de ambiente, como um erro real de produção. Se a aplicação tem `environments: ["prod", "hml"]`, a simulação usa `prod`.

### O payload montado

`SimulateIncidentAction::payload()` transforma o pedido num payload do webhook genérico:

```json
{
  "application": "flowstock-back",
  "title": "Simulação: erro disparado pelo painel do Firewatch",
  "severity": "error",
  "environment": "production",
  "occurrences": 1,
  "affected_users": 0,
  "occurred_at": "2026-11-16T19:12:03-03:00",
  "fingerprint": "simulated:019a8f3c-…",
  "context": {
    "simulated": true,
    "simulated_by": "ana@empresa.com.br"
  }
}
```

| Campo | De onde vem |
|---|---|
| `application` | O `monitoring_identifier` da aplicação escolhida |
| `occurred_at` | Agora |
| `context.simulated` | Sempre `true`: marca o incidente como simulado |
| `context.simulated_by` | O e-mail de quem clicou. No `sanitized_payload` ele aparece mascarado como `[email]` |
| `fingerprint` | Depende de `deduplicate` (abaixo) |

### Deduplicação na simulação

| `deduplicate` | Fingerprint | Efeito |
|---|---|---|
| `false` (padrão) | `simulated:<uuid7 novo>` | **Cada clique cria um incidente novo** |
| `true` | `simulated:sha1(<id da aplicação>|<título>)` | Cliques com o mesmo título na mesma aplicação somam ocorrências no mesmo incidente |

Com `deduplicate`, dá para demonstrar o `hold`: com `min_occurrences: 3`, os dois primeiros cliques deixam o incidente "Aguardando ocorrências" e o terceiro aciona os agentes.

### Respostas

| Status | Quando | Corpo |
|---|---|---|
| `201` | Incidente criado | `message: "Incidente simulado criado com sucesso."` |
| `200` | Somado a um incidente existente (`deduplicate`) | `message: "Ocorrência simulada registrada no incidente existente."` |
| `422` | Campo inválido | Erros de validação por campo |
| `422` | Aplicação **inativa** | Erro em `application`: "A aplicação está inativa: ative-a para simular incidentes." |
| `422` | O adapter recusou o payload | Erro em `payload` com a mensagem da [exception](/entrada/payloads-ignorados-e-invalidos) |
| `429` | Mais de 30 chamadas por minuto | O contador é por usuário e só desta rota |

```json
{
  "message": "Incidente simulado criado com sucesso.",
  "data": {
    "created": true,
    "incident": { "id": "9d6f…", "title": "Simulação: erro disparado pelo painel do Firewatch", "status": "queued", "occurrences": 1, … },
    "trigger": { "outcome": "trigger", "outcome_label": "Acionar agentes", "reason": null, "checks": [ … ] }
  }
}
```

`data.incident` usa o `IncidentResource`, o mesmo da lista de incidentes. `data.trigger` é a [decisão das regras](/registro-e-trigger/motor-de-regras#triggerdecision) (ou `null` se o incidente já tinha passado de `received`).

Cada simulação gera o evento `incident_simulated` na [auditoria](/seguranca/auditoria), com o usuário, a aplicação e se o incidente foi criado ou deduplicado.

## O botão no painel

O componente é `components/incident/SimulateIncidentButton.vue`, usado no **Dashboard** e na lista de **Incidentes**. Ele abre um modal:

| Campo | Envia | Observação |
|---|---|---|
| Aplicação (obrigatório) | O id na URL | Lista só aplicações ativas (`useApplications().listActive()`). Com uma só, ela já vem selecionada |
| Título do erro | `title` | O placeholder mostra o título padrão |
| Severidade | `severity` | Padrão `error` |
| Ambiente | `environment` | Vazio deixa o back escolher |
| Stack trace | `stack_trace` | |
| Somar ao mesmo incidente | `deduplicate` | |

O composable `useIncidents().simulate()` remove os campos vazios antes de enviar, para o back aplicar os padrões. `occurrences` e `affected_users` não aparecem no modal, só na API.

Depois do envio:

- **Sucesso**: um toast com a mensagem da API e "`<título>` — `<n>` ocorrência(s)", o modal fecha e a página recarrega a lista (o componente emite `simulated`).
- **Erro**: um toast "Não foi possível simular o incidente" com a mensagem da API.

O toast não mostra a decisão das regras. Para saber se os agentes foram acionados, abra o incidente: ele aparece como **Na fila** (acionado), **Recebido** com o motivo da espera, ou **Ignorado** com o motivo.

## Simulação × webhook de verdade

| | Simular incidente | `POST /api/webhooks/{connector}` |
|---|---|---|
| Autenticação | Sessão do painel | Assinatura ou token do conector |
| Conector | Nenhum | Precisa de um conector de entrada |
| Adapter | `GenericWebhookAdapter` | O do tipo do conector |
| Aplicação inativa | `422` | `202` ignorado |
| Deduplicação | Desligada por padrão (fingerprint único) | Pelo fingerprint da fonte |
| Regras de acionamento | Sim | Sim |
| Pode acionar os agentes | **Sim** | Sim |
| Marcação | `context.simulated: true` | |

Para testar também a **assinatura** e o conector, use o `curl` de [Exemplos de payload](/entrada/exemplos-de-payload#testando-localmente).

## Testes

`tests/Feature/Api/SimulateIncidentApiTest.php` cobre o corpo vazio com os padrões, cliques que criam incidentes novos ou somam com `deduplicate`, campos personalizados, entradas inválidas e aplicação inativa, a decisão das regras na resposta, o `hold` por severidade abaixo do mínimo e o bloqueio para quem não está logado.
