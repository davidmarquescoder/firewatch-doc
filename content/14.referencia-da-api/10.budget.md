Duas rotas atendem a tela **Custos e limites**: uma lê os limites e o gasto do mês, a outra salva os limites. De onde vêm os valores, como o mês bloqueia investigações e como o alerta funciona está em [Budget](/conectores-aplicacoes-budget-e-metricas/budget). Controller: `BudgetController`; regras: `CostBudget`.

| Método | Rota | O que faz |
|---|---|---|
| `GET` | `/api/v1/budget` | Limites em vigor e gasto do mês |
| `PUT` | `/api/v1/budget` | Salva os três limites e confere os alertas na hora |

## O objeto budget

As duas rotas devolvem o mesmo `CostBudget::status()`:

| Campo | Tipo | Conteúdo |
|---|---|---|
| `per_run_usd` | número | Teto por execução (US$) |
| `monthly_usd` | número \| null | Teto mensal. `null` = sem teto |
| `alert_percent` | inteiro | Percentual do teto mensal que dispara o alerta |
| `month` | string | Mês corrente, `AAAA-MM`, no fuso da aplicação |
| `spent_usd` | número | Gasto do mês, com 4 casas |
| `remaining_usd` | número \| null | Sobra do mês, nunca negativa. `null` sem teto |
| `percent` | inteiro \| null | Gasto sobre o teto, arredondado para baixo, até 999. `null` sem teto |
| `runs_count` | inteiro | Runs criados no mês, inclusive os bloqueados |
| `blocked` | booleano | `true` quando a sobra é menor que o mínimo por run |
| `next_run_usd` | número | Teto do próximo run: o menor entre `per_run_usd` e a sobra. `0` se bloqueado |

O que cada campo significa na tela está em [API](/conectores-aplicacoes-budget-e-metricas/budget#api), na página conceitual.

## Ver o budget

```http
GET /api/v1/budget
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

### Request

Sem parâmetros.

### Response

O [objeto budget](#o-objeto-budget).

### Exemplo

```json
{
  "message": "Custos e limites exibidos com sucesso.",
  "data": {
    "per_run_usd": 2,
    "monthly_usd": 50,
    "alert_percent": 80,
    "month": "2026-11",
    "spent_usd": 41.2731,
    "remaining_usd": 8.7269,
    "percent": 82,
    "runs_count": 37,
    "blocked": false,
    "next_run_usd": 2
  }
}
```

## Salvar o budget

```http
PUT /api/v1/budget
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

### Request

Os três campos vão sempre juntos (não é atualização parcial). A validação está no próprio controller.

| Campo | Tipo | Obrigatório | Regras |
|---|---|---|---|
| `per_run_usd` | número | Sim | 0,1 a 100 |
| `monthly_usd` | número \| null | **Presente** | `null` (sem teto) ou 1 a 100 000, e maior ou igual a `per_run_usd` |
| `alert_percent` | inteiro | Sim | 10 a 99 (o alerta de 100% é sempre enviado) |

`monthly_usd` precisa estar no corpo, mesmo que seja `null`. Os valores são gravados com duas casas na tabela `app_settings` (chave `budget`) e, a partir daí, valem no lugar do `.env` ([De onde vêm os valores](/conectores-aplicacoes-budget-e-metricas/budget#de-onde-vêm-os-valores)).

Depois de gravar, a rota roda `checkAlerts()`: se o mês já passou do novo limite de alerta ou de 100%, o `SendBudgetAlert` é despachado na hora ([Alerta percentual](/conectores-aplicacoes-budget-e-metricas/budget#alerta-percentual)). A mudança entra na [auditoria](/seguranca/auditoria) como alteração de **Custos e limites** (log `configuration`), com quem fez.

### Response

O [objeto budget](#o-objeto-budget) já com os novos limites.

### Erros

Nas mensagens de validação (`422`), os campos aparecem com nomes próprios: "teto por execução", "teto mensal" e "alerta". Exemplo, com `monthly_usd` menor que `per_run_usd`:

```json
{
  "message": "O campo teto mensal deve ser maior ou igual a 5.",
  "errors": {
    "monthly_usd": ["O campo teto mensal deve ser maior ou igual a 5."]
  }
}
```

### Exemplo

```http
PUT /api/v1/budget
```

```json
{ "per_run_usd": 1, "monthly_usd": 10, "alert_percent": 85 }
```

Com US$ 9 já gastos no mês:

```json
{
  "message": "Limites de custo atualizados.",
  "data": {
    "per_run_usd": 1,
    "monthly_usd": 10,
    "alert_percent": 85,
    "month": "2026-11",
    "spent_usd": 9,
    "remaining_usd": 1,
    "percent": 90,
    "runs_count": 1,
    "blocked": false,
    "next_run_usd": 1
  }
}
```

Como 90% passa de 85%, o alerta de 85% é enviado logo depois de salvar.

Para desligar o teto mensal:

```json
{ "per_run_usd": 2, "monthly_usd": null, "alert_percent": 80 }
```

A resposta traz `monthly_usd`, `remaining_usd` e `percent` como `null`.

## Observações

- O `PUT` não tem restrição de papel: qualquer usuário logado pode aumentar ou desligar o teto mensal (`BudgetController.php:23`).
- `BudgetController` monta a resposta com `response()->json()` em vez do `success()` da trait `ApiResponse`. O envelope sai igual (`message` + `data`) (`BudgetController.php:17`).
