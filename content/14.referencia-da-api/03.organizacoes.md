O cadastro de organizações veio do template base do back-end. Ele funciona, mas nada do domínio do Firewatch pertence a uma organização e o painel não tem tela para ele. O contexto está em [Organizações e multi-tenancy](/seguranca/organizacoes).

| Método | Rota | O que faz |
|---|---|---|
| `GET` | `/api/v1/organization` | Lista paginada, com `stats` |
| `POST` | `/api/v1/organization` | Cria a organização e o endereço |
| `GET` | `/api/v1/organization/{organization}` | Mostra uma organização, com o histórico |
| `PUT`/`PATCH` | `/api/v1/organization/{organization}` | Edita a organização e o endereço |
| `DELETE` | `/api/v1/organization/{organization}` | Apaga (soft delete) |
| `POST` | `/api/v1/organization/{organization}/upload` | Troca ou remove o logo |

Código: `OrganizationController`, `StoreOrganizationRequest`, `UpdateOrganizationRequest`, `IndexOrganizationResource`, `ShowOrganizationResource`, `AddressResource`, e as actions `CreateOrganizationAction`, `UpdateOrganizationAction`, `CreateAddressAction`, `UpdateAddressAction` e `UploadFileAction`.

Nenhuma rota do grupo checa papel: os Form Requests devolvem `authorize(): true` ([Papéis e permissões](/seguranca/papeis-e-permissoes#o-resto-da-api-aberto-a-qualquer-usuário-logado)). Todo método do controller está dentro de um `try/catch` que transforma qualquer exceção inesperada em `{"message": "<texto da exceção>", "data": []}` com status `500`. A validação (inclusive a do CEP e a do arquivo do upload) roda antes, e responde `422`.

## A organização na resposta

| Campo | Tipo | O que é |
|---|---|---|
| `id` | UUID | |
| `legal_name` | texto | Razão social |
| `trade_name` | texto, nulo | Nome fantasia |
| `business_size` | texto, nulo | `NA`, `MEI`, `ME`, `EPP`, `MEDIUM` ou `LARGE` (`BusinessSizeEnum`) |
| `entity_type` | texto, nulo | `PJ` ou `PF` (`EntityTypeEnum`) |
| `cnpj`, `cpf`, `email`, `phone` | texto, nulo | Sem checagem de formato, exceto o e-mail |
| `logo` | texto, nulo | URL completa do arquivo (`APP_URL/storage/uploads/organizations/logos/{id}/…`) |
| `active` | booleano | |
| `address` | objeto | `id`, `zip_code`, `city`, `state`, `country`, `neighborhood`, `street`, `number`, `complement` |
| `created_at`, `updated_at` | data ISO 8601 | |

O `ShowOrganizationResource` (usado em criar, ver, editar e upload) acrescenta:

| Campo | O que é |
|---|---|
| `activity_logs` | Os registros do `spatie/activitylog` cujo `subject_id` é a organização, crus |
| `activity_logs_timeline` | Os mesmos registros prontos para uma timeline: `id`, `title` ("Organização Criada" ou "Informações atualizadas"), `date` (`d/m/Y H:i`), `icon`, `description` (os campos alterados), `user` (só `id`, `name` e o e-mail em `description`, nunca o registro inteiro do usuário) e `avatar` (o avatar do usuário quando tem `src`, ou `null`) |

## Listar organizações

```http
GET /api/v1/organization
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

**Request**

| Campo | Tipo | Obrigatório | Regras |
|---|---|---|---|
| `per_page` | inteiro (query) | Não | Padrão `10`. Sem validação nem teto |
| `search` | texto (query) | Não | Busca parcial (`like`) só na razão social |
| `page` | inteiro (query) | Não | Página |

**Response**

`data` usa o `IndexOrganizationResource` (sem histórico), em ordem de criação, mais recente primeiro. Vêm também `meta` (paginação) e `stats`:

| Campo de `stats` | O que conta |
|---|---|
| `total` | Organizações não apagadas |
| `active`, `inactive` | Ativas e inativas |
| `pj`, `pf` | Por `entity_type` |

`stats` conta **todas** as organizações, sem aplicar o `search`.

**Exemplo**

GET /api/v1/organization?per_page=1

## Criar organização

```http
POST /api/v1/organization
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `201` |

**Request**

| Campo | Tipo | Obrigatório | Regras |
|---|---|---|---|
| `legal_name` | texto | Sim | Até 255, único |
| `trade_name` | texto | Não | Até 255, único |
| `business_size` | texto | Não | `NA`, `MEI`, `ME`, `EPP`, `MEDIUM` ou `LARGE` |
| `entity_type` | texto | Não | `PJ` ou `PF` |
| `cnpj` | texto | Não | Até 255, único |
| `cpf` | texto | Não | Até 255, único |
| `email` | texto | Não | E-mail válido, até 255, único |
| `phone` | texto | Não | Até 255, único |
| `active` | booleano | Não | Padrão `true`. `false` cria a organização inativa |
| `address` | objeto | Não | Chaves `zip_code`, `city`, `state`, `country`, `neighborhood`, `street`, `number`, `complement`, todas texto até 255 |

Organização e endereço são gravados na mesma transação. O endereço é criado sempre, mesmo vazio quando `address` não vem.

**Response**

`data` é a organização no formato `ShowOrganizationResource`.

**Erros**

| Status | Quando |
|---|---|
| `422` | `address` tem algum campo preenchido mas não tem `zip_code`: "O CEP é obrigatório quando um endereço é informado.", em `errors.address.zip_code` |

**Exemplo**

```http
POST /api/v1/organization
```

```json
{
  "legal_name": "Exemplo Tecnologia Ltda",
  "trade_name": "Exemplo",
  "entity_type": "PJ",
  "cnpj": "12345678000190",
  "address": {
    "zip_code": "01001000",
    "city": "São Paulo",
    "state": "SP"
  }
}
```

```json
{
  "message": "Organização criada com sucesso.",
  "data": {
    "id": "01a1d0e7-…",
    "legal_name": "Exemplo Tecnologia Ltda",
    "trade_name": "Exemplo",
    "entity_type": "PJ",
    "active": true,
    "address": { "zip_code": "01001000", "city": "São Paulo", "state": "SP", "…": "…" },
    "activity_logs": ["…"],
    "activity_logs_timeline": ["…"],
    "…": "…"
  }
}
```

## Ver organização

```http
GET /api/v1/organization/{organization}
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

**Request**

Sem corpo.

**Response**

`data` é a organização no formato `ShowOrganizationResource`, com `activity_logs` e `activity_logs_timeline`. A mensagem é "Organização exibida com sucesso."

## Editar organização

```http
PUT /api/v1/organization/{organization}
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

**Request**

Os mesmos campos de [Criar organização](#criar-organização), todos opcionais (`legal_name` também). As regras de unicidade ignoram a própria organização.

Só os campos enviados mudam. Um campo enviado como `null` é **limpo**, e `active: false` desativa a organização. No endereço, os campos vazios são ignorados: ele só preenche ou troca valores. Uma organização sem endereço ganha um quando `address` vem preenchido. `address` com campos e sem `zip_code` dá o mesmo `422` da criação.

**Response**

`data` é a organização no formato `ShowOrganizationResource`, relida do banco depois de salvar.

**Exemplo**

```http
PUT /api/v1/organization/01a1d0e7-…
```

```json
{
  "trade_name": "Exemplo Tech",
  "address": { "zip_code": "01001000", "number": "200" }
}
```

```json
{
  "message": "Organização atualizada com sucesso.",
  "data": {
    "id": "01a1d0e7-…",
    "legal_name": "Exemplo Tecnologia Ltda",
    "trade_name": "Exemplo Tech",
    "active": true,
    "address": { "zip_code": "01001000", "number": "200", "…": "…" },
    "activity_logs_timeline": [ "…" ],
    "…": "…"
  }
}
```

## Apagar organização

```http
DELETE /api/v1/organization/{organization}
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `204` |

**Request**

Sem corpo.

**Response**

`204 No Content`, sem corpo. A organização recebe `deleted_at` (soft delete); as memberships e o histórico de auditoria continuam apontando para ela.

## Trocar o logo

```http
POST /api/v1/organization/{organization}/upload
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

**Request**

`multipart/form-data`:

| Campo | Tipo | Obrigatório | Regras |
|---|---|---|---|
| `file` | arquivo | Não | `jpeg`, `png`, `jpg`, `gif` ou `svg`, até 1024 KB |

O logo anterior é apagado do disco `public`. Com `file`, o novo arquivo vai para `storage/uploads/organizations/logos/{id}/` e `logo` passa a ser a URL completa. **Sem `file`, o logo é removido** (`logo` fica `null`).

**Response**

`data` é a organização no formato `ShowOrganizationResource`. A mensagem é "Logo da organização atualizada com sucesso."

**Erros**

| Status | Quando |
|---|---|
| `422` | Arquivo de tipo ou tamanho inválido (`errors.file`) |

**Exemplo**

```http
POST /api/v1/organization/01a1d0e7-…/upload
Content-Type: multipart/form-data

file=@logo.png
```

```json
{
  "message": "Logo da organização atualizada com sucesso.",
  "data": {
    "id": "01a1d0e7-…",
    "logo": "http://localhost/storage/uploads/organizations/logos/01a1d0e7-…/a1b2c3.png",
    "…": "…"
  }
}
```

## Observações

- `stats` ignora o `search`; `per_page` não tem teto.
- As regras `unique` não ignoram organizações apagadas: a razão social de uma organização com soft delete não pode ser reaproveitada.
