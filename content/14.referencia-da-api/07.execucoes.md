Uma **execução** (`AgentRun`) é uma rodada do time de agentes num incidente. Cada reexecução cria uma nova. As rotas são só de leitura: o painel as usa na tela do incidente ao vivo. Como os eventos são gravados está em [Streaming](/investigacao/streaming), o relatório em [Resultado e falhas](/investigacao/resultado-e-falhas) e o envio em tempo real em [Eventos e payloads](/tempo-real/eventos-e-payloads).

| Método | Rota | O que faz |
|---|---|---|
| `GET` | `/api/v1/incident/{incident}/runs` | Lista as execuções de um incidente ([Incidentes](/referencia-da-api/incidentes#listar-execuções-do-incidente)) |
| `GET` | `/api/v1/agent-run/{agentRun}` | Mostra uma execução com o resumo do relatório |
| `GET` | `/api/v1/agent-run/{agentRun}/events` | Timeline da execução, em ordem, com retomada por `after` |

## Mostrar execução

```http
GET /api/v1/agent-run/{agentRun}
```

| | |
|---|---|
| Permissão | Qualquer usuário logado |
| Sucesso | `200` |

**Request**: sem corpo. `{agentRun}` é o UUID.

**Response**: `data` é a [execução](#formato-da-execução) com o campo `report`, que só existe nesta rota.

### Formato da execução

| Campo | O que é |
|---|---|
| `id`, `incident_id` | UUIDs |
| `status`, `status_label` | `pending` (Aguardando), `running` (Em execução), `fixed` (Corrigido), `failed` (Falhou), `dry_run` (Simulação) |
| `exit_code` | Código de saída do runner ([Códigos de saída do runner](/investigacao/resultado-e-falhas#códigos-de-saída-do-runner)) |
| `failure_stage`, `failure_reason` | Etapa e motivo da falha, quando houve |
| `work_branch` | Branch criada pelos agentes |
| `model` | Modelo do Claude usado |
| `started_at`, `finished_at`, `duration_seconds` | Tempo da execução |
| `input_tokens`, `output_tokens`, `num_turns` | Consumo informado pelo Claude Code |
| `cost_usd` | Custo em dólar, como **texto** com 4 casas (`"1.0529"`) |
| `team` | Retrato do time que rodou: para cada agente, `id`, `name`, `role`, `slug`, `model`, `tools`, `write`, `commands`, `avatar`, `prompt_sha256` |
| `report` | Só em Mostrar execução. Ver abaixo |
| `created_at`, `updated_at` | Datas do registro |

### O resumo do relatório

O runner grava um relatório completo (`report.json`) no `AgentRun`. A API **não** devolve esse relatório: o `AgentRunResource` monta um resumo com o que o painel mostra e deixa de fora saídas brutas e limites (por exemplo `tests.output_tail`, `git.repository`, `limits`). O `report` é `null` enquanto a execução não tem relatório (por exemplo, `running`).

| Campo | O que é |
|---|---|
| `status`, `summary`, `root_cause`, `fix` | O que os agentes concluíram |
| `risk` | `{level, reason}` |
| `failure` | Detalhe da falha, quando houve |
| `pull_request` | `{title, description}` do PR |
| `changes` | `files` (`path`, `status`, `additions`, `deletions`, `binary`), `files_count`, `additions`, `deletions`, `diff`, `diff_truncated` |
| `tests` | `command`, `status`, `counts`, `summary_line`, `test_added` |
| `flow` | `status`, `violations`, `warnings` e `reproduction` (`{status, command, exit_code}` ou `null`) |
| `git` | `base_branch`, `base_commit`, `work_branch` |
| `policy_denials` | **Quantas** ações a política negou (só o número, não a lista) |

Campos que faltam no relatório vêm `null`. As listas (`files`, `violations`, `warnings`) vêm vazias e os contadores de `changes` vêm `0`.

### Corte do diff

O diff completo fica no banco. Pela API, ele tem no máximo **300 000 bytes** (`AgentRunResource::MAX_DIFF_BYTES`):

- acima disso, `changes.diff` vem com os primeiros 300 000 bytes, cortados sem quebrar um caractere UTF-8 no meio (`mb_strcut`);
- `changes.diff_truncated` é `true` quando a API cortou **ou** quando o próprio runner já tinha marcado o diff como cortado no relatório.

## Listar eventos da execução

```http
GET /api/v1/agent-run/{agentRun}/events
```

| | |
|---|---|
| Permissão | Qualquer usuário logado |
| Sucesso | `200` |

**Request** (query string):

| Campo | Tipo | Obrigatório | Regras |
|---|---|---|---|
| `after` | inteiro | Não | ≥ 0. Só eventos com `sequence` **maior** que esse valor |
| `limit` | inteiro | Não | 1 a 500. Padrão `500` (`AgentRunController::MAX_EVENTS_PER_PAGE`) |

Não é um paginador com páginas: a paginação é por cursor. Os eventos vêm sempre em ordem de `sequence` (crescente, começando em 1).

**Response**: `data` é a lista de eventos. A resposta não tem `meta`; no lugar, traz dois campos:

| Campo | O que é |
|---|---|
| `has_more` | `true` se há mais eventos depois do último devolvido |
| `last_sequence` | `sequence` do último evento devolvido. Sem eventos, repete o `after` enviado (ou `0`) |

Para ler a timeline inteira, chame de novo com `after=<last_sequence>` enquanto `has_more` for `true`. O painel usa a mesma rota para recuperar o que perdeu depois de uma reconexão do WebSocket.

Cada evento:

| Campo | O que é |
|---|---|
| `id`, `agent_run_id` | UUIDs |
| `sequence` | Posição na timeline |
| `agent` | Quem gerou: o slug do agente (`cirurgiao`, `detetive`…) ou `runner` |
| `type`, `type_label` | `thinking` (Pensando), `read_file` (Leu arquivo), `edit_file` (Editou arquivo), `run_command` (Executou comando), `test_result` (Resultado de testes), `message` (Mensagem), `error` (Erro) |
| `content` | Texto do evento, já mascarado |
| `content_truncated` | `true` se o texto foi cortado ao salvar |
| `metadata` | Dados extras por tipo (comando, arquivo, etapa…), já mascarados |
| `tool_use_id` | Id da chamada de ferramenta no stream do Claude, quando o evento vem de uma |
| `occurred_at`, `created_at` | Quando aconteceu e quando foi gravado |

Pela API, `content` e `metadata` vêm **inteiros**, como estão no banco. O corte de 4000 caracteres é só do WebSocket ([O corte do conteúdo](/tempo-real/eventos-e-payloads#o-corte-do-conteúdo)). Aqui, `content_truncated: true` só aparece quando o texto passou de 65 535 caracteres ao ser salvo (`AgentEvent::MAX_CONTENT_LENGTH`), e esse excesso não existe mais em lugar nenhum ([Mascaramento e tamanhos](/investigacao/streaming#mascaramento-e-tamanhos)).

**Exemplo**:


## Observações

- `cost_usd` sai como texto (`"1.0529"`), por causa do cast `decimal:4` do modelo, e não como número (`AgentRun.php:85`).
- O `team` completo vem em cada execução, também na lista de [execuções do incidente](/referencia-da-api/incidentes#listar-execuções-do-incidente) (`AgentRunResource.php:52`).
- O corte do diff é por bytes (`strlen`), enquanto os cortes de eventos são por caracteres (`AgentRunResource.php:75`).
