A trilha de auditoria guarda quem configurou o quê, as ações manuais e o que os agentes fizeram. A API só lê: não existe rota para criar, editar ou apagar registros (`PUT` e `DELETE` em `/api/v1/audit-log/{id}` dão `404`). Como os registros são gravados e mascarados está em [Auditoria](/seguranca/auditoria).

| Método | Rota | O que faz |
|---|---|---|
| `GET` | `/api/v1/audit-log` | Lista paginada dos registros, com filtros |

## Listar registros de auditoria

```http
GET /api/v1/audit-log
```

| | |
|---|---|
| Permissão | Qualquer usuário logado |
| Sucesso | `200` |

**Request** (query string):

| Campo | Tipo | Obrigatório | Regras |
|---|---|---|---|
| `per_page` | inteiro | Não | 1 a 100. Padrão `25` |
| `page` | inteiro | Não | Página do paginador |
| `log` | texto | Não | `configuration`, `incident`, `action` ou `agent` (`AuditLogEnum`) |
| `subject_type` | texto | Não | `connector`, `application`, `agent_profile`, `user`, `organization`, `incident`, `agent_run`, `app_setting` |
| `subject_id` | UUID | Não | Id do item auditado |
| `causer_id` | UUID | Não | Só registros feitos por esse usuário |
| `causer` | texto | Não | Só `system`: registros sem usuário (webhook, fila, agentes, Slack) |
| `event` | texto | Não | Até 64. Igualdade exata: `created`, `updated`, `deleted`, `credentials_updated`, `connector_tested`, `incident_retried`… |
| `search` | texto | Não | Até 255. Procura na `description` (`LIKE`) |
| `from` | data | Não | `created_at` ≥ `from` |
| `to` | data | Não | `created_at` ≤ `to`. Só a data (`2026-11-17`) inclui o dia inteiro, até 23:59:59. Precisa ser ≥ `from` |

Só entram registros das quatro seções da auditoria. A ordem é sempre do mais novo para o mais antigo (`id` decrescente).

**Response**: `data` é a lista de registros e `meta` é o paginador. Cada registro:

| Campo | O que é |
|---|---|
| `id` | Inteiro (não é UUID) |
| `log`, `log_label` | Seção: `configuration` (Configuração), `incident` (Incidentes), `action` (Ações manuais), `agent` (Agentes) |
| `event` | O que aconteceu (`updated`, `connector_tested`…) |
| `description` | Texto do registro. Nas mudanças de modelo, é o próprio evento (`updated`) |
| `subject` | `{type, id, label, deleted}` ou `null`. `type` usa os nomes curtos de `subject_type`. `label` é o nome do item (o título, no incidente; "Execução de dd/mm/aaaa hh:mm", na execução), mascarado. `deleted` é `true` para item removido por soft delete |
| `causer` | `{id, name}` do usuário, ou `null` quando foi o **sistema** |
| `changes` | `{old, new}`: valores antes e depois, só dos campos alterados, já mascarados |
| `properties` | Dados extras do evento (por exemplo `ok` de um teste de conector) |
| `created_at` | Data em ISO 8601 com fuso (`2026-11-17T17:02:42+00:00`) |

Credenciais e senhas não aparecem nos valores: só o nome do campo alterado ([Auditoria](/seguranca/auditoria)).

**Erros**:

| Status | Quando |
|---|---|
| `422` | `log` ou `subject_type` fora da lista, `causer` diferente de `system`, `to` antes de `from` |

## Observações

- `properties` vazio sai como `[]`, não como `{}`: o `?? (object) []` nunca vale porque `properties` é uma coleção vazia, e não `null` (`AuditLogResource.php:47`).
- `created_at` sai em ISO 8601 sem microssegundos e com fuso (`+00:00`), num formato diferente das outras rotas (`…000000Z`) (`AuditLogResource.php:48`).
- Qualquer usuário logado lê a trilha inteira, inclusive quem não tem papel ([Papéis e permissões](/seguranca/papeis-e-permissoes)).
