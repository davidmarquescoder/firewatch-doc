Os perfis são os agentes do time: o orquestrador e os subagentes que o Claude Code recebe a cada execução. O que cada campo faz está em [Papéis e times](/perfis-de-agente), os níveis de acesso em [Níveis de acesso](/perfis-de-agente/niveis-de-acesso) e os prompts que vêm de fábrica em [Prompts padrão](/perfis-de-agente/prompts-padrao).

| Método | Rota | O que faz |
|---|---|---|
| `GET` | `/api/v1/agent-profile` | Lista o time, com filtros e `stats` |
| `POST` | `/api/v1/agent-profile` | Cria um perfil |
| `GET` | `/api/v1/agent-profile/{agent_profile}` | Mostra um perfil, com o arquivo de subagente |
| `PUT`/`PATCH` | `/api/v1/agent-profile/{agent_profile}` | Edita um perfil |
| `DELETE` | `/api/v1/agent-profile/{agent_profile}` | Apaga (soft delete) |

Código: `AgentProfileController`, `StoreAgentProfileRequest`, `UpdateAgentProfileRequest` (regras comuns no trait `AgentProfileRules`), `SaveAgentProfileAction`, `AgentProfileResource`.

Nenhuma rota do grupo checa papel de usuário: qualquer usuário logado lê e altera os perfis ([Papéis e permissões](/seguranca/papeis-e-permissoes#o-resto-da-api-aberto-a-qualquer-usuário-logado)). Toda mudança vai para a [auditoria](/seguranca/auditoria), no log `configuration`.

## O perfil na resposta

`AgentProfileResource`:

| Campo | Tipo | O que é |
|---|---|---|
| `id` | UUID | |
| `slug` | texto | Nome do subagente no Claude Code |
| `name` | texto | |
| `role`, `role_label` | texto | `orchestrator`, `triage`, `investigator`, `tester`, `fixer` ou `writer`, e o rótulo (`Orquestração`, `Triagem`, `Causa raiz`, `Testes`, `Correção`, `Pull Request`) |
| `is_subagent` | booleano | `false` só para `orchestrator` |
| `description` | texto | |
| `avatar` | texto, nulo | Como foi gravado |
| `avatar_url` | texto, nulo | URL absoluta: URLs e `data:` ficam como estão; caminhos viram `APP_URL/<caminho>` |
| `system_prompt` | texto | |
| `allowed_tools` | lista, nula | `null` = todas as ferramentas |
| `command_access`, `command_access_label` | texto | `none`, `read_only`, `tests` ou `full`, e o rótulo |
| `write_access`, `write_access_label` | texto | `none`, `tests`, `code` ou `any`, e o rótulo |
| `model` | texto, nulo | |
| `active` | booleano | |
| `sort_order` | inteiro | |
| `subagent_file` | objeto | Só em criar, ver e editar, e só para subagentes: `name` (`<slug>.md`) e `content` (frontmatter YAML + prompt) |
| `created_at`, `updated_at` | data ISO 8601 | |

## Listar perfis

```http
GET /api/v1/agent-profile
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

**Request**

| Campo | Tipo | Obrigatório | Regras |
|---|---|---|---|
| `search` | texto (query) | Não | Até 255. Busca parcial em `name` ou `slug` |
| `role` | texto (query) | Não | Um valor de `AgentRoleEnum` |
| `active` | booleano (query) | Não | `1`/`0` (a regra `boolean` não aceita `true`/`false` como texto) |

**Response**

`data` é a lista **sem paginação** e sem `meta`, na ordem do time (`sort_order`, depois `name`), sem `subagent_file`. Vem também `stats`:

| Campo de `stats` | O que conta |
|---|---|
| `total` | Perfis da lista (depois dos filtros) |
| `active` | Perfis ativos da lista |

**Exemplo**

```http
GET /api/v1/agent-profile?role=investigator
```

## Criar perfil

```http
POST /api/v1/agent-profile
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `201` |

**Request**

| Campo | Tipo | Obrigatório | Regras |
|---|---|---|---|
| `name` | texto | Sim | Até 255 |
| `slug` | texto | Sim* | Até 64, `^[a-z0-9]+(?:-[a-z0-9]+)*$`, único. *Se vier vazio, é gerado do `name` (`Str::slug`) antes da validação |
| `role` | texto | Sim | `orchestrator`, `triage`, `investigator`, `tester`, `fixer` ou `writer` |
| `description` | texto | Sim | Até 1000 |
| `system_prompt` | texto | Sim | Até 100 000 |
| `avatar` | texto | Não | Até 255 |
| `allowed_tools` | lista | Não | Itens distintos entre `Read`, `Grep`, `Glob`, `Bash`, `Edit`, `Write`, `NotebookEdit`, `Agent`, `TodoWrite`. Lista vazia vira `null` (todas) |
| `command_access` | texto | Não | `none`, `read_only`, `tests` ou `full`. Padrão `none` |
| `write_access` | texto | Não | `none`, `tests`, `code` ou `any`. Padrão `none` |
| `model` | texto | Não | Até 100, `^[a-z0-9.\-\[\]]+$` |
| `active` | booleano | Não | Padrão `true` |
| `sort_order` | inteiro | Não | 0 a 1000. Padrão `0` |

`null` em `active`, `sort_order`, `command_access` ou `write_access` também vira o padrão (`SaveAgentProfileAction`). Um perfil criado sem níveis de acesso não roda comando nem altera arquivo.

**Response**

`data` é o perfil criado, com `subagent_file` quando é subagente.

**Erros**

| Status | Quando |
|---|---|
| `422` em `role` | Já existe um orquestrador ativo e o novo também seria orquestrador ativo: "Já existe um agente orquestrador ativo. Desative-o antes de ativar outro." |
| `422` em `slug` | Fora do padrão: "O identificador deve conter apenas letras minúsculas, números e hífens." |
| `422` em `model` | Fora do padrão: "O modelo informado é inválido." |

**Exemplo**

```http
POST /api/v1/agent-profile
```

```json
{
  "name": "Revisor de Segurança",
  "role": "investigator",
  "description": "Revisa a correção procurando falhas de segurança.",
  "system_prompt": "Você revisa diffs procurando falhas de segurança.",
  "allowed_tools": ["Read", "Grep", "Bash"],
  "command_access": "read_only"
}
```

```json
{
  "message": "Agente criado com sucesso.",
  "data": {
    "id": "01a1c9f0-…",
    "slug": "revisor-de-seguranca",
    "name": "Revisor de Segurança",
    "role": "investigator",
    "is_subagent": true,
    "allowed_tools": ["Read", "Grep", "Bash"],
    "command_access": "read_only",
    "write_access": "none",
    "write_access_label": "Não altera arquivos",
    "model": null,
    "active": true,
    "sort_order": 0,
    "subagent_file": {
      "name": "revisor-de-seguranca.md",
      "content": "---\nname: revisor-de-seguranca\ndescription: \"Revisa a correção procurando falhas de segurança.\"\ntools: Read, Grep, Bash\n---\n\nVocê revisa diffs procurando falhas de segurança.\n"
    },

```

## Ver perfil

```http
GET /api/v1/agent-profile/{agent_profile}
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

**Request**

Sem corpo.

**Response**

`data` é o perfil com `subagent_file` (só para subagentes; o orquestrador não tem). A mensagem é "Agente exibido com sucesso."

**Exemplo**

```json
    }
  }
```

## Editar perfil

```http
PUT /api/v1/agent-profile/{agent_profile}
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

**Request**

Os mesmos campos de [Criar perfil](#criar-perfil). `name`, `slug`, `role`, `description` e `system_prompt` são `sometimes|required`: podem faltar, mas não podem vir vazios. O `slug` não é gerado na edição e continua único, ignorando o próprio perfil. As normalizações do `SaveAgentProfileAction` valem igual (lista de ferramentas vazia vira `null`).

**Response**

`data` é o perfil depois da edição, com `subagent_file` quando é subagente.

**Erros**

| Status | Quando |
|---|---|
| `422` em `role` | O perfil ficaria orquestrador ativo e já existe outro orquestrador ativo. A regra usa o papel e o `active` enviados ou, na falta deles, os atuais |

**Exemplo**

```http
PUT /api/v1/agent-profile/01a1c2bf-…
```

```json
{
  "system_prompt": "Prompt editado no painel",
  "allowed_tools": [],
  "sort_order": 7
}
```

```json
{
  "message": "Agente atualizado com sucesso.",
  "data": {
    "id": "01a1c2bf-…",
    "system_prompt": "Prompt editado no painel",
    "allowed_tools": null,
    "sort_order": 7,
    "…": "…"
  }
}
```

## Apagar perfil

```http
DELETE /api/v1/agent-profile/{agent_profile}
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

**Request**

Sem corpo.

**Response**

`data` é `[]`. O perfil recebe `deleted_at` (soft delete) e sai do time nas próximas execuções. O comando `firewatch:reset-agent-profiles` traz de volta um perfil padrão apagado ([Prompts padrão](/perfis-de-agente/prompts-padrao)).

**Exemplo**

```json
{
  "message": "Agente excluído com sucesso.",
  "data": []
}
```

## Observações

- `active` na listagem usa a regra `boolean`: `?active=true` responde `422` ("O campo active deve ser verdadeiro ou falso."); só `1`/`0` funcionam.
- `lang/pt_BR/validation.php` não tem a chave `enum`: `?role=xyz` (e `role`, `command_access`, `write_access` inválidos no corpo) devolve a mensagem em inglês, "The selected role is invalid."
- `stats` é calculado depois dos filtros (`AgentProfileController.php:43`), então não é o total do time quando há filtro.
- O comentário do `AgentProfileResource` diz que `subagent_file` é "show endpoint only", mas `store` e `update` também chamam `withPreview()`.
- A regra `unique` de `slug` não ignora perfis apagados: o slug de um perfil com soft delete não pode ser reaproveitado por um perfil novo.
