Um conector guarda as credenciais e as configurações de um serviço externo (Sentry, Bitbucket, GitHub, Slack, Jira ou webhook genérico). O que cada tipo pede, os status e o que o teste de conexão confere estão em [Conectores](/conectores-aplicacoes-budget-e-metricas). Controller: `ConnectorController`.

| Método | Rota | O que faz |
|---|---|---|
| `GET` | `/api/v1/connector` | Lista paginada, com `stats` |
| `POST` | `/api/v1/connector` | Cria um conector |
| `GET` | `/api/v1/connector/{connector}` | Mostra um conector |
| `PUT` / `PATCH` | `/api/v1/connector/{connector}` | Atualização parcial |
| `DELETE` | `/api/v1/connector/{connector}` | Soft delete |
| `POST` | `/api/v1/connector/{connector}/test` | Testa a conexão e grava o resultado |

## O objeto conector

Todas as rotas devolvem o conector pelo `ConnectorResource`. As credenciais **nunca** saem em texto: o campo `credentials` é um mapa **chave → configurada?**, com todas as chaves que o tipo aceita (obrigatórias e opcionais). Não existe rota que devolva o valor de uma credencial, nem mascarado ([Credenciais dos conectores](/seguranca/credenciais-dos-conectores#o-que-a-api-devolve)).

| Campo | Tipo | Conteúdo |
|---|---|---|
| `id` | uuid | |
| `type` | string | `sentry`, `bitbucket`, `github`, `slack`, `jira` ou `generic_webhook` |
| `type_label` | string | Rótulo do tipo ("Webhook genérico", "GitHub"…) |
| `name` | string | |
| `settings` | objeto | Configurações não secretas do tipo. `{}` quando vazio |
| `status` | string | `active`, `inactive` ou `error` |
| `status_label` | string | "Ativo", "Inativo" ou "Com erro" |
| `credentials` | objeto | Uma chave por credencial aceita, com `true` (configurada) ou `false` |
| `last_error` | string \| null | Mensagem do último teste que falhou |
| `last_verified_at` | data \| null | Último teste com sucesso |
| `applications_count` | inteiro | Aplicações que usam o conector como repositório |
| `created_at`, `updated_at` | data | |

As chaves de `credentials` por tipo:

| Tipo | Chaves |
|---|---|
| `sentry` | `client_secret` |
| `bitbucket`, `github` | `access_token`, `runner_token` |
| `slack` | `bot_token`, `signing_secret` |
| `jira` | `email`, `api_token` |
| `generic_webhook` | `secret` |

```json
{
  "id": "01a1c5d1-…",
  "type": "bitbucket",
  "type_label": "Bitbucket",
  "name": "Bitbucket Acme",
  "settings": { "workspace": "acme" },
  "status": "active",
  "status_label": "Ativo",
  "credentials": { "access_token": true, "runner_token": false },
  "last_error": null,
  "last_verified_at": "2026-11-17T11:53:02.000000Z",
  "applications_count": 1,
  "created_at": "2026-11-10T14:16:24.000000Z",
  "updated_at": "2026-11-17T11:53:02.000000Z"
}
```

## Listar conectores

```http
GET /api/v1/connector
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

### Request

Parâmetros de query, todos opcionais:

| Campo | Tipo | Obrigatório | Regras |
|---|---|---|---|
| `per_page` | inteiro | Não | 1 a 100. Padrão `10` |
| `search` | string | Não | Até 255. Busca no nome (`like`) |
| `type` | string | Não | Um dos tipos do enum |
| `status` | string | Não | `active`, `inactive` ou `error` |
| `page` | inteiro | Não | Página da paginação |

A ordem é por nome.

### Response

`data` é uma lista de [conectores](#o-objeto-conector), com `meta` da paginação e um bloco `stats`:

| Campo | Conteúdo |
|---|---|
| `stats.total` | Todos os conectores não removidos |
| `stats.active` | Com status `active` |
| `stats.error` | Com status `error` |
| `stats.inactive` | `total − active − error` |

Os `stats` contam **todos** os conectores, sem aplicar `search`, `type` ou `status`.

### Exemplo

```http
GET /api/v1/connector?per_page=2
```

```json
{
  "message": "Conectores listados com sucesso.",
  "data": [
    { "id": "01a1c5d1-…", "type": "bitbucket", "name": "Bitbucket Acme", "status": "active", "credentials": { "access_token": true, "runner_token": true }, "applications_count": 1, "…": "…" },
    { "id": "01a1c56b-…", "type": "jira", "name": "Jira Acme", "status": "active", "credentials": { "email": true, "api_token": true }, "applications_count": 0, "…": "…" }
  ],
  "meta": {
    "current_page": 1,
    "from": 1,
    "last_page": 2,
    "links": ["…"],
    "path": "http://localhost/api/v1/connector",
    "per_page": 2,
    "to": 2,
    "total": 4
  },
  "stats": { "total": 4, "active": 4, "error": 0, "inactive": 0 }
}
```

## Criar conector

```http
POST /api/v1/connector
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `201` |

### Request

Regras do `StoreConnectorRequest`. As regras de `credentials.*` e `settings.*` dependem do `type` enviado.

| Campo | Tipo | Obrigatório | Regras |
|---|---|---|---|
| `type` | string | Sim | Um dos tipos do enum |
| `name` | string | Sim | Até 255, único entre os conectores |
| `credentials` | objeto | Sim | Ver abaixo |
| `credentials.<obrigatória>` | string | Sim | Até 4096 |
| `credentials.<opcional>` | string | Não | Até 4096, pode ser `null` |
| `settings` | objeto | Não | Ver abaixo |
| `status` | string | Não | `active` ou `inactive`. Padrão `active` |

Credenciais e settings por tipo:

| Tipo | Credenciais obrigatórias | Opcionais | Settings |
|---|---|---|---|
| `sentry` | `client_secret` | | `organization` (opcional, até 255) |
| `bitbucket` | `access_token` | `runner_token` | `workspace` (**obrigatório**, até 255) |
| `github` | `access_token` | `runner_token` | `owner` (opcional, até 255) |
| `slack` | `bot_token` | `signing_secret` | `channel` (**obrigatório**, até 255) |
| `jira` | `email`, `api_token` | | `base_url` (**obrigatório**, URL `https`, até 255), `project_key` (**obrigatório**, até 20), `issue_type` (opcional, até 255) |
| `generic_webhook` | `secret` | | Nenhuma |

O `CreateConnectorAction` guarda só as chaves de credencial que o tipo aceita e descarta valores vazios. Chaves desconhecidas são ignoradas sem erro.

### Response

O [conector](#o-objeto-conector) criado, com `applications_count: 0`.

### Exemplo

```http
POST /api/v1/connector
```

```json
{
  "type": "jira",
  "name": "Jira Acme",
  "credentials": { "email": "bot@exemplo.com", "api_token": "token-de-exemplo" },
  "settings": { "base_url": "https://acme.atlassian.net", "project_key": "FW", "issue_type": "Bug" }
}
```

```json
{
  "message": "Conector criado com sucesso.",
  "data": {
    "id": "01a1c6e2-…",
    "type": "jira",
    "type_label": "Jira",
    "name": "Jira Acme",
    "settings": { "base_url": "https://acme.atlassian.net", "project_key": "FW", "issue_type": "Bug" },
    "status": "active",
    "status_label": "Ativo",
    "credentials": { "email": true, "api_token": true },
    "last_error": null,
    "last_verified_at": null,
    "applications_count": 0,
    "…": "…"
  }
}
```

## Mostrar conector

```http
GET /api/v1/connector/{connector}
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

### Request

Sem corpo. `{connector}` é o `id`. Um conector removido (soft delete) responde `404`.

### Response

O [conector](#o-objeto-conector), com `applications_count`.

```json
{
  "message": "Conector exibido com sucesso.",
  "data": { "id": "01a1c56b-…", "type": "jira", "credentials": { "email": true, "api_token": true }, "applications_count": 0, "…": "…" }
}
```

## Atualizar conector

```http
PUT /api/v1/connector/{connector}
PATCH /api/v1/connector/{connector}
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

### Request

Atualização parcial (`UpdateConnectorRequest`): mande só o que muda.

| Campo | Tipo | Obrigatório | Regras |
|---|---|---|---|
| `type` | | | **Proibido**: o tipo não muda |
| `name` | string | Não | Se enviado, não vazio, até 255, único (ignorando o próprio conector) |
| `credentials` | objeto | Não | Mesclado com as credenciais guardadas |
| `credentials.<obrigatória>` | string | Não | Se enviada, não vazia, até 4096 |
| `credentials.<opcional>` | string \| null | Não | Até 4096. `null` ou `""` **remove** a credencial |
| `settings` | objeto \| null | Não | Se enviado, validado pelas regras do tipo e **substitui** o anterior. `null` vira `{}` |
| `status` | string | Não | `active` ou `inactive` |

A mescla deixa o painel trocar um segredo sem conhecer os outros, que a API nunca devolve. O `status` `error` não pode ser posto pela API: só o [teste de conexão](#testar-conexão) o grava.

### Response

O [conector](#o-objeto-conector) atualizado.

### Erros

| Status | Quando |
|---|---|
| `422` | `type` enviado (erro em `type`) |

### Exemplo

Trocar só o token do Jira e desativar o conector:

```http
PATCH /api/v1/connector/01a1c56b-…
```

```json
{
  "credentials": { "api_token": "novo-token-de-exemplo" },
  "status": "inactive"
}
```

```json
{
  "message": "Conector atualizado com sucesso.",
  "data": {
    "id": "01a1c56b-…",
    "type": "jira",
    "status": "inactive",
    "status_label": "Inativo",
    "credentials": { "email": true, "api_token": true },
    "…": "…"
  }
}
```

## Remover conector

```http
DELETE /api/v1/connector/{connector}
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Sucesso** | `200` |

### Request

Sem corpo.

### Response

Soft delete. `data` vem vazio.

```json
{
  "message": "Conector excluído com sucesso.",
  "data": []
}
```

### Erros

| Status | Quando | `message` |
|---|---|---|
| `409` | Alguma aplicação (não removida) usa o conector como repositório | "Este conector está em uso por aplicações. Remova o vínculo antes de excluí-lo." |

Só o vínculo de repositório bloqueia a remoção. Conectores de Slack, Jira e de entrada podem ser removidos a qualquer momento.

## Testar conexão

```http
POST /api/v1/connector/{connector}/test
```

| | |
|---|---|
| **Permissão** | Qualquer usuário logado |
| **Throttle** | `throttle:10,1,connector-test` (10 por minuto) |
| **Sucesso** | `200`, também quando o teste falha |

::warning
Esta rota chama o serviço externo de verdade (exceto Sentry e webhook genérico, conferidos localmente) e **altera** o conector: `status`, `last_error` e `last_verified_at`. Também grava `connector_tested` na [auditoria](/seguranca/auditoria).
::

### Request

Sem corpo.

### Response

Um teste que falha é um resultado válido: a resposta é `200` com `result.ok: false`. A `message` do envelope muda com o resultado.

| Campo | Conteúdo |
|---|---|
| `result.ok` | `true` se a conexão foi confirmada |
| `result.message` | Texto para o painel, sem valores de credencial |
| `result.remote` | `false` quando o teste foi só local (Sentry e webhook genérico) |
| `result.details` | Fatos não secretos (repositórios, `runner_token: "read_only"`, `team` do Slack, `slack_error`…). `{}` quando não há |
| `connector` | O [conector](#o-objeto-conector) já com o resultado gravado |

| Resultado | `message` | `connector.status` |
|---|---|---|
| Sucesso | "Conexão testada com sucesso." | `active` (um `inactive` continua `inactive`) |
| Falha | "O teste de conexão falhou." | `error` (um `inactive` continua `inactive`) |

O que cada tester confere e as mensagens de falha estão em [Testar conexão](/conectores-aplicacoes-budget-e-metricas#testar-conexão).

### Erros

| Status | Quando |
|---|---|
| `429` | Mais de 10 chamadas no minuto. O contador é por usuário e só desta rota |

### Exemplo

Webhook genérico com o segredo configurado (teste local):

```http
POST /api/v1/connector/01a1c7f3-…/test
```

```json
{
  "message": "Conexão testada com sucesso.",
  "data": {
    "result": {
      "ok": true,
      "message": "Segredo configurado. Conectores de entrada são confirmados quando o primeiro evento assinado chegar.",
      "remote": false,
      "details": {}
    },
    "connector": {
      "id": "01a1c7f3-…",
      "type": "generic_webhook",
      "status": "active",
      "credentials": { "secret": true },
      "last_error": null,
      "last_verified_at": "2026-11-17T14:02:11.000000Z",
      "…": "…"
    }
  }
}
```

Slack com token recusado:

```json
{
  "message": "O teste de conexão falhou.",
  "data": {
    "result": { "ok": false, "message": "…", "remote": true, "details": { "slack_error": "invalid_auth" } },
    "connector": { "status": "error", "last_error": "…", "…": "…" }
  }
}
```

## Observações

- Os `stats` da listagem ignoram os filtros: com `?type=slack`, `stats.total` continua contando todos os conectores (`ConnectorController.php:36`).
- Um `type` ou `status` inválido na listagem devolve a mensagem em inglês, "The selected type is invalid.", porque o `lang/pt_BR/validation.php` não tem a regra `enum`. A página [Internacionalização](/backend/internacionalizacao) diz que a resposta seria a chave crua `validation.enum`; na execução local veio o texto em inglês (`ConnectorController.php:32`).
- Nenhuma rota de conectores restringe por papel: qualquer usuário logado cria, edita, testa ou remove conectores, inclusive trocando credenciais (`StoreConnectorRequest.php:18`, `UpdateConnectorRequest.php:22`).
