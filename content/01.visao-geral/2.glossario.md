Cada termo traz o **nome no painel** (português) e o **nome no código** (inglês), porque tabelas, classes e enums do back-end usam inglês e a interface usa português.

## Incidente

::badge
`Incident` · `App\Models\Incident\Incident`
::

Um **erro único** de uma aplicação. Várias ocorrências do mesmo erro (mesmo *fingerprint*, na mesma aplicação) somam no mesmo incidente em vez de criar um novo. Um incidente que ficou em silêncio por mais de `FIREWATCH_INCIDENT_REOPEN_AFTER_HOURS` horas (padrão **72 h**) volta como um incidente novo.

Guarda o payload original e o **payload sanitizado** (com dados sensíveis mascarados, o único que vai para o painel e para o modelo), a severidade, as ocorrências, os usuários afetados, o link do PR, a chave do Jira e a data de cada etapa.

O incidente percorre um ciclo de vida com transições controladas:

::mermaid
---
code: |
  stateDiagram-v2
    direction LR
    [*] --> received
    received --> queued: trigger
    received --> ignored: ignore
    received --> failed
    queued --> investigating
    investigating --> fixing
    fixing --> testing
    testing --> fixing
    testing --> pr_opened
    queued --> failed
    investigating --> failed
    fixing --> failed
    testing --> failed
    failed --> queued: reexecutar
    pr_opened --> [*]
    ignored --> [*]
caption: Status do incidente (IncidentStatusEnum). pr_opened, failed e ignored são terminais; failed pode voltar para a fila por reexecução manual.
---
::

| Status | No painel | Significado |
|---|---|---|
| `received` | Recebido | Registrado, aguardando a decisão do trigger (ou os limites mínimos). |
| `ignored` | Ignorado | O trigger decidiu não investigar. Terminal. |
| `queued` | Na fila | Job criado, esperando um slot de runner livre. |
| `investigating` | Investigando | Runner no ar; agentes na triagem e na causa raiz. |
| `fixing` | Corrigindo | Agentes escrevendo o teste e a correção. |
| `testing` | Testando | Correção pronta; suíte sendo validada e PR sendo aberto. |
| `pr_opened` | PR aberto | Pull Request aberto. Terminal. |
| `failed` | Falhou | Terminou sem PR, com um *failure kind*. Pode ser reexecutado. |

## Aplicação

::badge
`Application` · `App\Models\Application\Application`
::

Um **sistema monitorado** que o FireWatch pode corrigir. Liga o mundo do monitoramento ao mundo do código:

- **Identificador no monitoramento**: como a aplicação aparece no Sentry ou no webhook (ex.: `flowstock-back`). É por ele que um evento recebido encontra sua aplicação.
- **Repositório**: conector de repositório (Bitbucket ou GitHub), slug do repositório e branch base.
- **Runner**: imagem Docker do runner (com a stack da aplicação), comando de instalação e comando de testes (`auto` detecta pelo repositório).
- **Regras de acionamento**: o JSON que o [Trigger](#trigger) avalia.
- **Ativa / inativa**: aplicações inativas têm seus incidentes ignorados.

## Conector

::badge
`Connector` · `App\Models\Connector\Connector`
::

Uma **integração externa** configurada pelo painel. Tem tipo, nome, credenciais e configurações extras. As credenciais ficam no banco **criptografadas** (cast `encrypted`) e nunca voltam pela API em texto puro.

| Tipo | Papel | Credenciais |
|---|---|---|
| `sentry` | Entrada de eventos | `client_secret` |
| `generic_webhook` | Entrada de eventos | `secret` |
| `bitbucket` | Repositório e PRs | `access_token` (+ `runner_token` opcional, somente leitura) |
| `github` | Repositório e PRs | `access_token` (+ `runner_token` opcional) |
| `slack` | Notificações e comando `/firewatch` | `bot_token` (+ `signing_secret` para o comando) |
| `jira` | Cards | `email`, `api_token` |

## Perfil de Agente

::badge
`AgentProfile` · `App\Models\AgentProfile\AgentProfile`
::

A **definição de um agente do time**, editável pelo painel: nome, papel, avatar, prompt de sistema, ferramentas permitidas, nível de acesso a comandos e a arquivos, e se está ativo. A cada execução, os perfis ativos viram o prompt de sistema do orquestrador e os subagentes passados ao Claude Code (`--agents`).

| Agente | Papel (`AgentRoleEnum`) | Etapa do fluxo |
|---|---|---|
| Chefe de Plantão | `orchestrator` | Orquestra todas as etapas (é a sessão principal do Claude Code) |
| Sentinela | `triage` | 1. Triagem e escopo |
| Detetive | `investigator` | 2. Causa raiz (somente leitura) |
| Advogado do Diabo | `tester` | 3. Teste que reproduz o bug · 5–6. Valida a suíte |
| Cirurgião | `fixer` | 4. Correção mínima |
| Escrivão | `writer` | 7. Título e descrição do PR |

## AgentRun

::badge
`AgentRun` · `App\Models\AgentRun\AgentRun`
::

**Uma execução do time de agentes** para um incidente. Um incidente pode ter várias (cada reexecução cria uma nova). Guarda início, fim, duração, tokens de entrada e saída, custo em US$, teto de custo da execução, branch de trabalho, o time escalado e o **relatório final** (JSON) devolvido pelo runner.

Status: `pending` (Aguardando), `running` (Em execução), `fixed` (Corrigido), `failed` (Falhou) e `dry_run` (Simulação).

## AgentEvent

::badge
`AgentEvent` · `App\Models\AgentEvent\AgentEvent`
::

**Um passo registrado** de uma execução: o que um agente fez, quando e com qual conteúdo. É a matéria-prima da timeline ao vivo e da auditoria. Cada evento tem o agente que o emitiu (um subagente, `chefe-de-plantao`, `runner` ou `firewatch`) e um tipo:

`thinking` · `read_file` · `edit_file` · `run_command` · `test_result` · `message` · `error`

## Runner

::badge
`firewatch-runner` · `App\Services\Runner\DockerRunner`
::

O **container Docker descartável** onde os agentes trabalham, um por execução. Contém git, Claude Code CLI e os runtimes da aplicação (PHP + Node na imagem base; outras stacks por imagens derivadas). Clona o repositório, instala as dependências, roda o Claude Code, confere o fluxo obrigatório, roda a suíte e devolve **eventos NDJSON** no stdout e um **relatório final**.

Roda sem capabilities, com limite de CPU, memória, processos e tempo, numa rede interna sem internet, saindo só pelo proxy Squid.

## Trigger

::badge
`TriggerRulesEngine` · `EvaluateIncidentTriggerAction`
::

O **motor de regras** que decide, para cada incidente recebido, o que fazer. Avalia as regras da aplicação e combina os resultados:

| Decisão | Efeito |
|---|---|
| `trigger` (Acionar agentes) | Incidente vai para `queued` e o job de investigação é disparado. |
| `hold` (Aguardando limites) | Incidente fica em `received` até atingir os mínimos (novas ocorrências reavaliam). |
| `ignore` (Ignorar) | Incidente vai para `ignored`. |

Regras avaliadas: aplicação ativa, acionamento ligado, ambientes aceitos, padrões de título ignorados, severidade mínima (padrão `error`), ocorrências mínimas (padrão 1) e usuários afetados mínimos (padrão 0). `ignore` vence `hold`, que vence `trigger`.

## Budget

::badge
`CostBudget` · tela **Custos e limites**
::

O **controle de custo** das execuções com o Claude. Tem três valores, editáveis pelo painel:

- **Teto por execução** (`per_run_usd`, padrão US$ 2): repassado ao runner como `CLAUDE_MAX_BUDGET_USD`.
- **Teto mensal** (`monthly_usd`, opcional): quando o que resta do mês fica abaixo do mínimo de uma execução, novas investigações não começam e falham com o kind `budget`. O teto da execução também é reduzido ao que sobra do mês.
- **Alerta** (`alert_percent`, padrão 80%): ao passar desse percentual (e de 100%), o time é avisado uma vez por mês.

## Slot

::badge
`RunnerSlots`
::

Uma **vaga de execução simultânea** de runner. O limite é `FIREWATCH_RUNNER_MAX_CONCURRENT` (padrão **2**), controlado por *locks* no Redis. Um job que não consegue um slot volta para a fila a cada 30 s com o motivo "Aguardando um runner livre". Se nenhum slot liberar em 180 min, o incidente falha com o kind `stale`.

## Failure Kind

::badge
`IncidentFailureKindEnum`
::

A **classificação do motivo** de um incidente que terminou como `failed`. Vem do código de saída do runner (traduzido pelo `FailureClassifier`) ou do próprio FireWatch, e cada kind tem um rótulo e o próximo passo sugerido para o time.

| Kind | No painel | Origem típica |
|---|---|---|
| `configuration` | Configuração inválida | Runner código 2 ou erro ao subir o container |
| `clone` | Falha ao clonar o repositório | Runner código 3 |
| `install` | Falha ao instalar dependências | Runner código 4 |
| `ai_error` | Erro no Claude | Runner código 5 (chave inválida, limite de gasto…) |
| `tests_failed` | Testes não passaram | Runner código 6 |
| `no_fix` | Causa ou correção não encontrada | Runner código 7 |
| `flow_violation` | Fluxo obrigatório não cumprido | Runner código 8 (sem teste, ou teste que passa sem a correção) |
| `timeout` | Tempo esgotado | Runner código 124 ou timeout do FireWatch |
| `out_of_memory` | Memória esgotada | Runner código 137 |
| `cancelled` | Execução interrompida | Runner código 143 |
| `runner_error` | Erro no runner | Runner código 1 ou desconhecido |
| `internal` | Erro interno do FireWatch | Exceção no job |
| `stale` | Execução sem resposta | Nenhum slot livre a tempo, ou execução abandonada |
| `delivery_blocked` | Correção não enviada | Correção pronta, mas barrada antes do PR |
| `dry_run` | Execução de teste | `FIREWATCH_RUNNER_DRY_RUN` ligado |
| `budget` | Teto de custo atingido | Teto mensal esgotado |

::note
`tests_failed`, `no_fix` e `flow_violation` são **falhas dos agentes** (eles rodaram, mas não entregaram uma correção aceitável). Os demais indicam que a investigação quebrou antes ou ao redor deles.
::
