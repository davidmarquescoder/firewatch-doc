::

`redis:latest`, `phpmyadmin/phpmyadmin` e o `CLAUDE_CODE_VERSION=latest` do runner não têm versão fixa: um rebuild pode trazer uma versão nova. Para builds reprodutíveis, fixe a tag.
::

## Runner · `firewatch-runner`

Imagem base `firewatch-runner:latest`, contrato **v1** (label `br.com.firewatch.runner.contract`).

| Peça | Versão | Observação |
|---|---|---|
| Base | `php:8.5-cli-bookworm` (Debian 12) | Build arg `PHP_VERSION` |
| PHP | **8.5.12** | Extensões: bcmath, exif, gd, intl, pcntl, pdo_mysql, pdo_pgsql, redis, sockets, zip |
| Composer | **2.11.2** | |
| Node.js | **22.23.5** | Build arg `NODE_VERSION`; npm, pnpm e Yarn 1 via corepack |
| git | **2.39.5** | |
| Claude Code CLI | **2.1.322** | Build arg `CLAUDE_CODE_VERSION` (padrão `latest`) |
| Ferramentas | tini, jq, ripgrep, curl, openssh-client | |
| Stack Python | `firewatch-runner:python` | Imagem derivada em `docker/runner/stacks/python` |

O modelo do Claude é definido por `FIREWATCH_CLAUDE_MODEL`; vazio, vale o padrão do Claude Code. A autenticação usa `FIREWATCH_ANTHROPIC_API_KEY` ou `FIREWATCH_CLAUDE_CODE_OAUTH_TOKEN`.

## Integrações externas

| Integração | Como o FireWatch fala com ela |
|---|---|
| Sentry | Webhooks da integração (Internal Integration), assinados com `Sentry-Hook-Signature` |
| Bitbucket Cloud | API REST 2.0, token de acesso (`x-token-auth` no clone) |
| GitHub | API REST, token (`x-access-token` no clone) |
| Slack | Web API com bot token; slash command com signing secret |
| Jira Cloud | API REST com e-mail + API token; descrições em ADF |
| Anthropic | Claude Code CLI dentro do runner, saindo só por `api.anthropic.com` |
