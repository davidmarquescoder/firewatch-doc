O banco é **MySQL 8.3**, criado por 22 migrations. As tabelas se dividem em três grupos:

| Grupo | Tabelas |
|---|---|
| **Domínio do FireWatch** | `connectors`, `applications`, `incidents`, `agent_runs`, `agent_events`, `agent_profiles`, `app_settings` |
| **Usuários e organização** (herdadas do template) | `users`, `settings`, `organizations`, `organization_memberships`, `addresses` |
| **Infraestrutura** (Laravel e pacotes) | `activity_log`, `notifications`, `permissions`, `roles`, `model_has_permissions`, `model_has_roles`, `role_has_permissions`, `personal_access_tokens`, `sessions`, `password_reset_tokens`, `cache`, `cache_locks`, `jobs`, `job_batches`, `failed_jobs` |

Convenções comuns a quase todas as tabelas próprias:

- Chave primária **UUID** (`$table->uuid('id')->primary()`, `HasUuids` no modelo).
- `created_at`/`updated_at` e, na maioria, **soft delete** (`deleted_at`).
- Status, tipos e níveis guardados como **string** e convertidos para **enums** pelo cast do modelo (o banco não tem `ENUM`).
- Credenciais e payloads brutos **criptografados** com o cast `encrypted:array` (coluna `text`/`longText`).

A cadeia principal é **conector → aplicação → incidente → execução → evento**. Cada incidente pertence a uma aplicação; cada execução (`agent_runs`) pertence a um incidente; cada passo dos agentes (`agent_events`) pertence a uma execução.

Duas ligações não têm chave estrangeira, de propósito:

- **`agent_profiles` → `agent_runs`**: a execução guarda em `team` uma **cópia** dos perfis como estavam no início (incluindo o hash do prompt). Editar ou apagar um perfil depois não altera o histórico.
- **`app_settings` → `agent_runs`**: o teto de custo vigente é copiado para `agent_runs.budget_usd` quando a execução começa.

### Comportamento ao apagar

| Relação | Ao apagar o pai |
|---|---|
| `connectors` → `applications.repository_connector_id` e `issue_tracker_connector_id` | `SET NULL` (e a API recusa apagar um conector em uso, com `409`) |
| `applications` → `incidents.application_id` | `RESTRICT`: uma aplicação com incidentes não pode ser apagada fisicamente (o soft delete funciona) |
| `incidents` → `agent_runs.incident_id` | `CASCADE` |
| `agent_runs` → `agent_events.agent_run_id` | `CASCADE` |
