Os valores ficam no banco como **string** e são convertidos pelos casts dos modelos. O **rótulo** vem da constante `LABELS` do enum e é o que a API devolve em `<campo>_label`.

## IncidentStatusEnum

`App\Enums\Incident\IncidentStatusEnum` · coluna `incidents.status` · padrão `received`

| Valor | Rótulo | Terminal | Significado |
|---|---|---|---|
| `received` | Recebido | | Registrado; aguardando a decisão do trigger ou os limites mínimos |
| `ignored` | Ignorado | ✓ | O trigger decidiu não investigar |
| `queued` | Na fila | | Job criado, esperando um slot de runner |
| `investigating` | Investigando | | Runner no ar: triagem e causa raiz |
| `fixing` | Corrigindo | | O Cirurgião começou a corrigir |
| `testing` | Testando | | Validação da correção e abertura do PR |
| `pr_opened` | PR aberto | ✓ | Pull Request aberto |
| `failed` | Falhou | ✓ | Terminou sem PR; ver `failure_kind`. Pode voltar para a fila |

Métodos: `isTerminal()`, `open()` (os não terminais), `canTransitionTo()` e `timestampColumn()`. As transições estão em [Máquina de estados](/modelo-de-dados/maquina-de-estados).

## IncidentSeverityEnum

`App\Enums\Incident\IncidentSeverityEnum` · coluna `incidents.severity` · padrão `error`

| Valor | Rótulo | Peso (`rank()`) | Significado |
|---|---|---|---|
| `debug` | Debug | 0 | Diagnóstico, sem impacto |
| `info` | Informativo | 1 | Evento informativo |
| `warning` | Alerta | 2 | Algo inesperado, mas o sistema segue |
| `error` | Erro | 3 | Falha de uma operação. **Mínimo padrão do trigger** |
| `critical` | Crítico | 4 | Falha grave |

O peso compara severidades (`isAtLeast()`) na regra `min_severity` e ao deduplicar: uma ocorrência mais grave **eleva** a severidade do incidente.

## IncidentFailureKindEnum

`App\Enums\Incident\IncidentFailureKindEnum` · coluna `incidents.failure_kind` (só em `failed`)

| Valor | Rótulo | Origem | Próximo passo sugerido (`nextStep()`) |
|---|---|---|---|
| `configuration` | Configuração inválida | Runner código 2, ou erro ao subir o container | Revisar a configuração da aplicação e dos conectores |
| `clone` | Falha ao clonar o repositório | Runner código 3 | Conferir o token e o slug do repositório |
| `install` | Falha ao instalar dependências | Runner código 4 | Conferir o comando de instalação |
| `ai_error` | Erro no Claude | Runner código 5 | Conferir a credencial e o saldo da API |
| `tests_failed` | Testes não passaram | Runner código 6 | Investigar manualmente |
| `no_fix` | Causa ou correção não encontrada | Runner código 7 | Investigar a partir da causa provável |
| `flow_violation` | Fluxo obrigatório não cumprido | Runner código 8 | Investigar manualmente |
| `timeout` | Tempo esgotado | Runner código 124, ou timeout do Laravel | Reexecutar ou investigar |
| `out_of_memory` | Memória esgotada | Runner código 137 | Aumentar `FIREWATCH_RUNNER_MEMORY` |
| `cancelled` | Execução interrompida | Runner código 143 | Reexecutar |
| `runner_error` | Erro no runner | Runner código 1 ou desconhecido | Ver logs do `runner-worker` |
| `internal` | Erro interno do Firewatch | Exceção no job | Ver logs do `runner-worker` |
| `stale` | Execução sem resposta | Sem slot a tempo, ou execução abandonada | Conferir se o `runner-worker` está no ar |
| `delivery_blocked` | Correção não enviada | Relatório barrado antes do PR | Revisar pelo painel |
| `dry_run` | Execução de teste | `FIREWATCH_RUNNER_DRY_RUN` ligado | Desligar o `DRY_RUN` |
| `budget` | Teto de custo atingido | Teto mensal esgotado | Aumentar o teto ou aguardar o mês seguinte |

`isAgentFailure()` é verdadeiro para `tests_failed`, `no_fix` e `flow_violation`: os agentes rodaram, mas não entregaram uma correção aceitável. Os demais indicam falha antes ou ao redor dos agentes.

## TriggerOutcomeEnum

`App\Enums\Incident\TriggerOutcomeEnum` · não é coluna: resultado do `TriggerRulesEngine`

| Valor | Rótulo | Peso | Efeito no incidente |
|---|---|---|---|
| `trigger` | Acionar agentes | 0 | `received` → `queued` e job disparado |
| `hold` | Aguardando limites | 1 | Continua `received`, com o motivo em `status_reason` |
| `ignore` | Ignorar | 2 | `received` → `ignored` |

Cada regra avaliada devolve um resultado; a decisão final é o de **maior peso** entre as regras que não passaram. Um `ignore` vence qualquer `hold`.

## AgentWriteAccessEnum

`App\Enums\AgentProfile\AgentWriteAccessEnum` · coluna `agent_profiles.write_access` · padrão `none`

| Valor | Rótulo | Pode alterar |
|---|---|---|
| `none` | Não altera arquivos | Nada |
| `tests` | Só arquivos de teste | Arquivos reconhecidos como teste (`tests/`, `*Test.php`, `*.spec.ts`…) |
| `code` | Só código da aplicação (não altera testes) | Arquivos que não são de teste |
| `any` | Qualquer arquivo | Tudo dentro do repositório |

Para subagentes, escrever fora do repositório ou em `.git/` é sempre recusado, qualquer que seja o nível.

## AgentCommandAccessEnum

`App\Enums\AgentProfile\AgentCommandAccessEnum` · coluna `agent_profiles.command_access` · padrão `none`

| Valor | Rótulo | Pode executar |
|---|---|---|
| `none` | Nenhum comando | Nada no `Bash` |
| `read_only` | Somente leitura | `git log/blame/show/diff/status`, `ls`, `cat`, `grep`, `find` (sem `-exec`/`-delete`), sem redirecionar para arquivo nem `$(…)` |
| `tests` | Leitura e testes | O de `read_only` + o comando de testes do projeto (`php artisan test`, pest, phpunit, vitest, jest, pytest) |
| `full` | Qualquer comando | Tudo, exceto `git push`, `git merge` e `git pull`, que o guarda recusa para qualquer agente |

### Acesso padrão por papel

| Papel | `command_access` | `write_access` |
|---|---|---|
| `orchestrator` | `full` | `any` |
| `triage` | `none` | `none` |
| `investigator` | `read_only` | `none` |
| `tester` | `tests` | `tests` |
| `fixer` | `tests` | `code` |
| `writer` | `none` | `none` |
