O `entrypoint.sh` vira `/usr/local/bin/firewatch-run` na imagem. É um script Bash com `set -Eeuo pipefail` que define o **contrato** entre o runner e quem o chama, seja o [`DockerRunner`](/investigacao/docker-runner) do Laravel, seja o `launch.sh` no terminal. A versão do contrato fica no label `br.com.firewatch.runner.contract` da imagem (hoje `1`).

## O que entra

### Arquivos em `/runner/input/`

| Arquivo | Variável que muda o caminho | Obrigatório? | Uso |
|---|---|---|---|
| `prompt.md` | `PROMPT_FILE` | Sim, se `PROMPT` estiver vazio | O incidente: vira o `-p` do Claude Code |
| `system-prompt.md` | `SYSTEM_PROMPT_FILE` | Não | `--append-system-prompt-file`: instruções do orquestrador |
| `agents.json` | `AGENTS_FILE` | Não | `--agents`: os subagentes |
| `policy.json` | `POLICY_FILE` | Não | Liga a [guarda de ferramentas](/runner/tool-guard) |

Como o Laravel monta esses arquivos está em [Prompt e RunnerInput](/investigacao/prompt-e-runner-input).

### Variáveis de ambiente

| Variável | Padrão | O que faz |
|---|---|---|
| `REPO_URL` | **obrigatória** | URL HTTPS do repositório. Um `usuario@` embutido é removido quando há token |
| `REPO_USERNAME` | `x-token-auth` | Usuário do clone (Bitbucket: `x-token-auth`; GitHub: `x-access-token`) |
| `REPO_TOKEN_STDIN` | `0` | `1`: lê o token da primeira linha do stdin (espera até 30 s) |
| `REPO_TOKEN` | vazio | Token pelo ambiente. Funciona, mas gera um aviso no stderr: prefira o stdin |
| `BASE_BRANCH` | `main` | Branch clonada |
| `WORK_BRANCH` | `firewatch/run-<timestamp UTC>` | Branch criada para a correção. **Precisa** começar com `firewatch/` e ser diferente da base |
| `GIT_CLONE_DEPTH` | `0` | `0` = histórico completo, que o Detetive usa em `git log` e `git blame` |
| `INSTALL_COMMAND` | `auto` | `auto` (detecta), `none` (pula) ou um comando |
| `TEST_COMMAND` | `auto` | `auto`, `none` ou um comando. É exportado para os agentes como `$TEST_COMMAND` |
| `PROMPT` | vazio | Prompt direto, no lugar de `prompt.md` |
| `ANTHROPIC_API_KEY` / `CLAUDE_CODE_OAUTH_TOKEN` | vazio | Uma das duas é obrigatória fora do dry run. Variáveis vazias são removidas antes do Claude Code |
| `CLAUDE_MODEL` | vazio | `--model` (vazio = padrão do Claude Code) |
| `CLAUDE_MAX_BUDGET_USD` | vazio | `--max-budget-usd`: teto de custo da execução |
| `CLAUDE_ALLOWED_TOOLS` / `CLAUDE_DISALLOWED_TOOLS` | vazio | `--allowedTools` / `--disallowedTools`. O Laravel não usa: quem limita é a política |
| `INSTALL_TIMEOUT` / `CLAUDE_TIMEOUT` / `TEST_TIMEOUT` | `900` / `1800` / `600` | Segundos. `RUNNER_TIMEOUT` ainda vale como nome antigo de `CLAUDE_TIMEOUT` |
| `RUNNER_MAX_DURATION` | `3600` | Tempo total. `0` = sem limite |
| `FIREWATCH_SETUP_PROXY` / `FIREWATCH_AGENT_PROXY` | vazio | Proxy de cada fase ([Egress](/runner/egress)). Vazio = usa a rede do container como está |
| `DRY_RUN` | `0` | `1`: faz tudo até antes do Claude Code e termina com `dry_run` |
| `DIFF_MAX_BYTES` | `1048576` | Diff maior que 1 MB é cortado no relatório |
| `TEST_OUTPUT_TAIL_LINES` | `80` | Linhas finais da saída dos testes guardadas no relatório |
| `CLAUDE_BIN` | `claude` | Binário do Claude Code. Os testes trocam pelo `fake-claude` |

O `runner.env.example` tem a lista comentada para quem roda no terminal.

### stdin

Só o token do repositório, numa linha, e só com `REPO_TOKEN_STDIN=1`. Logo depois da leitura, o script faz `exec 0</dev/null`: **nada mais** lê a entrada padrão, nem o Claude Code nem os agentes. Os motivos estão em [Isolamento](/runner/isolamento#o-token-do-repositório).

## As etapas

Cada etapa muda a variável `STAGE`, que vai em todos os eventos e no `failure.stage` do relatório.

::mermaid
---
code: |
  flowchart TD
    S[setup<br/>valida a configuração] --> C[clone<br/>clona e cria a branch]
    C --> I[install<br/>dependências]
    I --> A[agents<br/>valida agents.json e policy.json]
    A --> CL{DRY_RUN=1?}
    CL -->|sim| F0[finished → report dry_run]
    CL -->|não| CC[claude<br/>Claude Code]
    CC --> FL[flow<br/>fluxo obrigatório]
    FL --> V[verify<br/>suíte completa]
    V --> R[result<br/>confere o relatório do agente]
    R --> F[finished → report fixed]
---
::

| Etapa | O que faz | Falha com |
|---|---|---|
| `setup` | Confere `REPO_URL`, o token do stdin, `WORK_BRANCH` (prefixo `firewatch/`, `git check-ref-format`, diferente da base), o prompt, a credencial do Claude e se os timeouts são inteiros. Inicia o watchdog do tempo total | 2 |
| `clone` | Liga o proxy de setup. Clona com `--branch <base> --single-branch --no-tags` usando `GIT_ASKPASS`, grava o `BASE_COMMIT`, cria a `WORK_BRANCH`, **apaga a credencial** e instala o hook `pre-push` | 3 |
| `install` | Com `auto`, confere os runtimes e detecta o comando. Roda com `timeout`. Arquivos criados pela instalação vão para `.git/info/exclude` e ficam fora do diff. Depois resolve o `TEST_COMMAND` | 4, ou 124 |
| `agents` | Valida `agents.json` (objeto em que cada item tem `description` e `prompt` em texto) e `policy.json` (`version: 1`, níveis conhecidos). Gera o `--settings` com o hook `PreToolUse` | 2 |
| `claude` | Liga o proxy dos agentes e roda o Claude Code com `timeout --kill-after=30`. O stream vai para o stdout e para uma cópia usada no relatório | 5, ou 124 |
| `flow` | Prova o fluxo obrigatório (abaixo). Pulada se o agente não relatou `fixed` | 8, ou 124 |
| `verify` | Roda o `TEST_COMMAND` inteiro de novo, sem confiar no agente | 6, ou 124 |
| `result` | Exige o relatório do agente com `status: fixed` e algum arquivo alterado | 7 |
| `finished` | Emite o resumo e chama `finish 0` | |

Qualquer erro não previsto, em **qualquer** etapa, dispara o `trap ERR`: código 1 com "Erro inesperado na linha N: <comando>" e relatório normal. Os três trechos que esperam um código diferente de zero (o Claude Code, a reprodução do fluxo e a suíte da `verify`) desligam o trap com `unexpected_errors_off` só durante o comando e religam com `unexpected_errors_on` logo depois. Isso é necessário porque o `trap ERR` dispara mesmo com `set +e`. `SIGTERM` ou `SIGINT` dão 143, a não ser que o watchdog do tempo total tenha disparado, e aí é 124.

### A chamada do Claude Code

```bash
claude -p "$PROMPT" \
  --output-format stream-json --verbose \
  --forward-subagent-text \
  --permission-mode bypassPermissions \
  [--model …] [--max-budget-usd …] [--allowedTools …] [--disallowedTools …] \
  [--append-system-prompt-file /runner/input/system-prompt.md] \
  [--agents /runner/input/agents.json] \
  [--settings <hook PreToolUse da guarda>]
```

- `--forward-subagent-text` faz o texto e o raciocínio dos subagentes aparecerem no stream, marcados com `parent_tool_use_id`.
- `--permission-mode bypassPermissions` existe porque não há ninguém para aprovar nada. Quem limita os agentes é a guarda de ferramentas, que um hook aplica mesmo nesse modo.
- Os subagentes vão por `--agents`, que tem prioridade sobre agentes de mesmo nome em `.claude/agents/` do repositório. Nada é escrito no repositório, então nada disso aparece no diff do PR.
- O `--settings` traz `disableAllHooks: false`. Ele tem precedência sobre as configurações do repositório, então um `.claude/settings.json` do repositório não desliga a guarda.

### Detecção automática

| Arquivo no repositório | `INSTALL_COMMAND=auto` | `TEST_COMMAND=auto` |
|---|---|---|
| `composer.json` | `composer install --no-interaction --prefer-dist --no-progress`. Com `artisan` e `.env.example` sem `.env`: também `cp .env.example .env` e `php artisan key:generate` | `php artisan test` se tiver `artisan`; senão `composer test` se houver `scripts.test` |
| `pnpm-lock.yaml` | `pnpm install --frozen-lockfile` | `npm test` se houver `scripts.test` no `package.json` |
| `yarn.lock` | `yarn install --frozen-lockfile` | idem |
| `package-lock.json` | `npm ci --no-audit --no-fund` | idem |
| `package.json` (sem lockfile) | `npm install --no-audit --no-fund` | idem |
| `requirements.txt`, `requirements-dev.txt`, `requirements_dev.txt`, `requirements-test.txt` | `pip install -r <arquivo>` para cada um (só com `python3` na imagem) | `python3 -m pytest` se houver `pytest.ini`, `conftest.py`, `tox.ini`, `[tool.pytest…]` no `pyproject.toml` ou arquivos `test_*.py` |
| `pyproject.toml` / `setup.py` sem `requirements.txt` | `pip install -e '.[test,dev]'` | idem |

Os comandos detectados são encadeados com `&&`. Sem nada detectado, a etapa sai como `skipped`. Sem comando de testes detectado, `TEST_COMMAND` vira `none`: o fluxo obrigatório não consegue provar a reprodução (fica um aviso) e a `verify` é pulada.

## O fluxo obrigatório

Depois do Claude Code, se o relatório do agente diz `fixed`, o runner **prova sozinho** que o agente seguiu "reproduzir com teste → corrigir → validar", sem acreditar no que o agente escreveu:

1. Lista as alterações contra o `BASE_COMMIT` com um índice temporário do git (o índice real não muda), incluindo arquivos novos.
2. Separa **testes** de **código**. É teste o que está em `tests/`, `test/`, `__tests__/`, `spec/` ou `specs/`, ou tem nome de teste: `*Test.php`, `test_*.py`, `*_test.py`, `*_test.go`, `*_test.rb`, `*.test.ts`, `*.spec.js` (e `jsx`, `tsx`, `mjs`, `cjs`, `vue`) e `*_spec.rb`.
3. Registra **violações**: teste removido, nenhum teste alterado, nenhum código alterado.
4. Registra **avisos**, que não bloqueiam e vão em destaque no PR: arquivos sensíveis (`composer.json`/`.lock`, `package*.json`, lockfiles, `requirements*.txt`, `pyproject.toml`, `Dockerfile`, `docker-compose*.yml`, CI, `phpunit.xml`, `Pest.php`, `pytest.ini`, `conftest.py`, configs do jest/vitest/vite, `.env*`) e migrations existentes alteradas.
5. Sem violações e com comando de testes: **volta o código da aplicação** para a base, mantém os testes do agente e roda só os arquivos de teste alterados. **Eles precisam falhar.** Depois restaura a correção. Se a execução for interrompida no meio, o `finish` restaura também.
6. Teste que passa sem a correção vira a violação "O teste passa sem a correção, então não reproduz o erro".

O comando de reprodução acrescenta os arquivos ao `TEST_COMMAND`: direto para `artisan test`, `pest`, `phpunit`, `pytest`, `jest` e `vitest`, e depois de `--` para `npm test`, `yarn test`, `pnpm test` e `composer test`. Outro comando roda a suíte inteira.

Qualquer violação termina com código 8 e "Fluxo obrigatório não cumprido: …". A reprodução estourar o `TEST_TIMEOUT` dá 124.

## O que sai

| Canal | Conteúdo |
|---|---|
| **stdout** | Somente NDJSON: os eventos `type: "runner"` e o `stream-json` do Claude Code. O último evento é sempre o `report` ([Eventos e relatório](/runner/eventos-e-relatorio)) |
| **stderr** | Texto livre: `[firewatch-run] …`, saída do git, da instalação, da reprodução e da suíte. O Laravel guarda as últimas 40 linhas para diagnóstico |
| `/runner/output/report.json` | O relatório final, igual ao do evento `report`. Só é gravado se a pasta existir e for gravável |
| `/runner/output/agent-report.json` | O relatório que o **agente** escreve. O caminho chega a ele em `$FIREWATCH_REPORT_FILE` |
| **Código de saída** | `0` corrigido (ou dry run), `1` erro inesperado, `2` configuração, `3` clone, `4` instalação, `5` Claude Code, `6` suíte falhou, `7` sem correção, `8` fluxo obrigatório, `124` timeout, `143` interrompido |

O significado de cada código no Laravel está em [Resultado e falhas](/investigacao/resultado-e-falhas#códigos-de-saída-do-runner).

### O relatório do agente

O system prompt do Chefe de Plantão manda escrever `$FIREWATCH_REPORT_FILE` com estes campos:

| Campo | Exemplo |
|---|---|
| `status` | `fixed` ou `failed` |
| `summary`, `root_cause`, `fix` | Texto |
| `files_changed` | Lista de caminhos |
| `test_added` | `tests/Unit/…Test.php::test_…` |
| `test_failed_before_fix`, `full_suite_passed` | O que o agente **afirma** |
| `risk`, `risk_reason` | `low`, `medium` ou `high`, com o motivo |
| `pr_title`, `pr_description` | Título e corpo do PR em Markdown |
| `failure_reason` | Por que não corrigiu, quando `status = failed` |

O runner só aceita o arquivo se ele for um objeto JSON. Ausente ou inválido, ele vale `null` e a execução termina com código 7.

## Como tudo termina: `finish`

Toda saída passa por `finish <código> [motivo]`, inclusive as falhas (`fail` emite o evento `failed` e chama `finish`). Ele:

1. desliga os traps e mata o watchdog;
2. decide o status: código diferente de 0 é `failed`, `DRY_RUN=1` é `dry_run` e o resto é `fixed`;
3. restaura o código, se a reprodução do fluxo foi interrompida. Uma falha nessa restauração só gera um aviso no stderr e não impede o relatório;
4. coleta o relatório do agente, as alterações, os testes, as métricas do Claude Code e os limites do container;
5. monta o `report.json`, copia para `/runner/output` e emite o evento `report`;
6. apaga a pasta temporária e sai com o código.

Por isso o relatório sai em **toda** saída do script. A exceção é o container ser morto de fora com `SIGKILL` (o `docker kill` no `hardTimeout()` do Laravel ou o OOM killer). Nesses casos o Laravel monta um relatório próprio.
