O runner é Bash, roda dentro de um container e conversa com o Claude Code. Testar isso de verdade custaria créditos a cada rodada. Por isso os testes trocam **só** a parte cara e mantêm todo o resto real: a imagem, o `launch.sh`, os limites, a rede restrita, o clone, a instalação e a suíte do repositório.

| Script | O que testa | Claude Code | Precisa de |
|---|---|---|---|
| `test/run-scenarios.sh` | O entrypoint de ponta a ponta: cada desfecho, rede, timeouts, fluxo obrigatório | **Falso** (`fake-claude`), exceto em `real_api_401` | `runner.env` apontando para o repositório cobaia |
| `test/run-guard-tests.sh` | A [guarda de ferramentas](/runner/tool-guard) | **Real**, contra uma API falsa | `python3` no host |

Nenhum dos dois gasta créditos. O guia de uso rápido está em [Testar sem gastar créditos](/ambiente-e-setup/testar-sem-creditos#fake-claude-e-cenários). Esta página explica como eles funcionam por dentro.

## fake-claude

`docker/runner/test/fake-claude` é um script Bash que **finge ser o Claude Code**. O runner o usa quando recebe `CLAUDE_BIN=/runner/test/fake-claude`. Ele:

- lê os mesmos argumentos do real e, se houver `--agents`, lista os slugs no `init` como o Claude Code faz (assim o teste confere que os subagentes chegaram);
- emite um `stream-json` no formato do real: `system/init`, `assistant` com `text` ou `tool_use`, `user` com `tool_result` e o `result` final com custo `0`;
- faz o "trabalho" conforme `FAKE_SCENARIO`, com o patch e o relatório gravados da execução real do incidente-001 (`test/fixtures/incident-001.patch` e `incident-001.agent-report.json`).

| `FAKE_SCENARIO` | O que o fake faz |
|---|---|
| `fix` | Aplica o patch inteiro (correção + teste) e copia o relatório `fixed` |
| `break_tests` | Igual ao `fix` e cria `tests/Unit/FirewatchAlwaysFailsTest.php`, que sempre falha |
| `agent_failed` | Não altera nada e escreve um relatório `failed` ("Não foi possível escrever um teste que reproduza o erro") |
| `no_report` | Aplica o patch, mas não escreve relatório |
| `api_error` | Emite o erro sintético "Invalid API key" e um `result` com `is_error: true` e `api_error_status: 401`, e sai com 1 |
| `hang` | Escreve uma mensagem e dorme uma hora |
| `net_probe` | Faz `curl` para `repo.packagist.org`, `api.anthropic.com` e `example.com` e grava os códigos HTTP no `failure_reason` de um relatório `failed` |
| `no_test` | Aplica só a parte `app/*` do patch: corrige sem teste |
| `test_passes_before` | Aplica só `app/*` e cria um teste que sempre passa |
| `unexpected_error` | Altera o primeiro arquivo de código do repositório, deixa ele somente leitura e cria um teste. Na reprodução do fluxo, o runner não consegue reverter o arquivo: é um erro inesperado **depois** do Claude Code. Não usa o patch, então funciona com qualquer repositório |

## run-scenarios.sh

```bash
docker/runner/test/run-scenarios.sh                       # todos
docker/runner/test/run-scenarios.sh api_error no_test     # alguns
```

Para cada cenário, o script chama o `launch.sh` (com a rede restrita) com:

| Argumento | Por quê |
|---|---|
| `--env-file runner.env` | `REPO_URL`, token e branch base do repositório cobaia |
| `-e ANTHROPIC_API_KEY=fake-key-nao-usada -e CLAUDE_CODE_OAUTH_TOKEN=` | **Substitui a credencial real**. Mesmo com uma chave de verdade no `runner.env`, nada é cobrado |
| `-e CLAUDE_BIN=/runner/test/fake-claude -e FAKE_SCENARIO=<cenário>` | Troca o Claude Code pelo fake |
| `-e WORK_BRANCH=firewatch/test-<cenário>` | |
| `-e AGENTS_FILE=… -e POLICY_FILE=…` (fixtures) | Subagentes e política de teste (o time inteiro em `policy.json`) |
| `-e INSTALL_COMMAND=none -e TEST_COMMAND=none` | Nos cenários que não precisam de dependências: rodam em segundos |
| `-e COMPOSER_CACHE_DIR=/cache -v runs/.cache/composer:/cache` | Nos que instalam: cache do Composer entre rodadas |
| `-v test:/runner/test:ro`, `-v examples/incident-001:/runner/input:ro` | O fake, as fixtures e o incidente-001 como entrada |
| Variáveis extras do cenário | Vêm por último e sobrescrevem as anteriores |

| Cenário | Extras | Esperado |
|---|---|---|
| `fix` | instala dependências | exit 0, `fixed` |
| `break_tests` | instala | exit 6, `failed` em `verify` |
| `agent_failed` | | exit 7 |
| `no_report` | | exit 7 |
| `api_error` | | exit 5 |
| `net_probe` | | exit 7. O `failure_reason` mostra que só a Anthropic respondeu |
| `real_api_401` | `CLAUDE_BIN=claude` | exit 5. **Claude Code real** com a chave falsa: a API responde 401 pelo proxy, o que prova a rede e custa zero |
| `timeout_claude` | `FAKE_SCENARIO=hang`, `CLAUDE_TIMEOUT=5` | exit 124, `stage = claude` |
| `timeout_tests` | `FAKE_SCENARIO=agent_failed`, `TEST_COMMAND=sleep 60`, `TEST_TIMEOUT=5` | exit 124 |
| `timeout_total` | `FAKE_SCENARIO=hang`, `CLAUDE_TIMEOUT=600`, `RUNNER_MAX_DURATION=10` | exit 124, "Tempo total de execução excedido" |
| `agents_invalid` | `AGENTS_FILE=…/agents-invalid.json` (subagente sem `prompt`) | exit 2 |
| `policy_invalid` | `POLICY_FILE=…/policy-invalid.json` (`commands: "tudo"`) | exit 2 |
| `no_test` | instala | exit 8 |
| `test_passes_before` | instala | exit 8, `reproduction.status = passed_without_fix` |
| `unexpected_error` | `TEST_COMMAND=true` | exit 1, `failure.stage = flow`, "Erro inesperado na linha …". Garante que o `report` sai mesmo num erro não previsto depois do Claude Code |

Um cenário passa quando **todas** estas conferências batem:

1. o código de saída é o esperado;
2. o `status` do `output/report.json` é o esperado;
3. a **última linha** do stdout é o evento `report` e o `report` dela é **igual** ao arquivo;
4. se o Claude (falso ou real) rodou, o primeiro `init` lista `sentinela` e `detetive`.

A saída é uma tabela com cenário, código, status, veredito e o motivo da falha (ou os arquivos alterados). Cada cenário deixa `stream.ndjson`, `stderr.log`, `workspace/` e `output/` em `docker/runner/runs/test-<data>/<cenário>/`. O script sai com 1 se algum cenário falhar.

::note
`fix`, `break_tests`, `no_test` e `test_passes_before` aplicam o patch do incidente-001, então o `runner.env` precisa apontar para o **repositório cobaia** (`flowstock-back`). Esses quatro instalam dependências e rodam a suíte: levam alguns minutos. Os outros levam segundos.
::

## run-guard-tests.sh

```bash
docker/runner/test/run-guard-tests.sh
```

Duas partes.

### 1. Casos unitários

O script monta, para cada caso, o JSON que o Claude Code mandaria ao hook (`tool_name`, `tool_input`, `cwd` e `agent_type` quando não é a sessão principal), passa ao `firewatch-tool-guard` dentro da imagem com o `fixtures/policy.json` e confere **permitir** ou **recusar**. São 51 casos, entre eles:

| Agente | Chamada | Esperado |
|---|---|---|
| `main` | `rm -rf app` | permitir (`full`) |
| `main` | `git push origin firewatch/x`, `sh -c "git push -f"`, `git -c user.name=x merge …`, `git pull --rebase` | recusar |
| `main` | Write em `/runner/output/agent-report.json` | permitir (`any`) |
| `sentinela` | `Read`; `ls`; `Edit` | permitir; recusar; recusar |
| `detetive` | `git log`, `git blame`, `git show … \| head`, `grep … 2>/dev/null \| sort \| uniq -c`, `find -newer`, `git branch --show-current` | permitir |
| `detetive` | `touch`, `echo x > …`, `cat $(…)`, `git checkout --`, `git branch nova`, `git stash`, `find -delete`, `sed -i`, `ls & rm`, `php artisan test`, `sort -o` | recusar |
| `advogado-do-diabo` | Write/Edit em `tests/…`; `php artisan test --filter=…`; `APP_ENV=testing vendor/bin/pest … \| tail` | permitir |
| `advogado-do-diabo` | Edit em `app/X.php`; Write em `/tmp/x.php`; Write em `tests/../app/X.php`; `migrate:fresh`; `composer require` | recusar |
| `cirurgiao` | Edit em `app/…`; `php artisan test tests/…` | permitir |
| `cirurgiao` | Edit em `tests/…`; Write em `.git/hooks/pre-push`; `git add -A`; NotebookEdit fora das ferramentas | recusar |
| `escrivao` | `git diff`; Write em `PR.md` | recusar |
| `general-purpose`, `intruso` | Qualquer coisa | recusar (fora do time) |

### 2. Integração com o Claude Code real

Os casos unitários provam a lógica do script, mas não que o Claude Code **chama** o hook, manda o `agent_type` certo e respeita a recusa em `bypassPermissions`. Para isso o teste roda o Claude Code de verdade contra uma **API da Anthropic falsa**.

`test/fake-anthropic-api.py` é um servidor HTTP em Python (porta `18090`, ou `FAKE_API_PORT`) que responde ao `/v1/messages` com eventos SSE no formato da API real, seguindo um roteiro:

| Quem pergunta | Como a API reconhece | Resposta |
|---|---|---|
| Sessão principal, primeiro turno | A requisição oferece a ferramenta `Agent` e ainda não há `tool_result` | `tool_use` `Agent` delegando ao `detetive` |
| Detetive | O system prompt contém `SUBAGENT-MARKER` | Em sequência: `Bash touch /tmp/w/pwned`, `Bash git log --oneline -n 1`, `Write /tmp/w/app.php`. Depois "ok" |
| Qualquer outro turno | | Texto "fim" |

Outras rotas (como `count_tokens`) recebem `{"input_tokens": 1}`, e toda requisição vai para um log.

O container roda com `--network host` para alcançar a API no host, cria um repositório vazio em `/tmp/w`, um `agents.json` com o Detetive (com `Write` nas ferramentas, de propósito) e o mesmo `--settings` do runner, e chama:

```bash
ANTHROPIC_BASE_URL=http://127.0.0.1:18090 ANTHROPIC_API_KEY=sk-ant-fake \
  claude -p "comece" --output-format stream-json --verbose \
  --permission-mode bypassPermissions --agents /tmp/agents.json --settings /tmp/settings.json
```

O resultado esperado, comparado exatamente:

```json
{
  "results": [
    {"id": "toolu_s1", "error": true},
    {"id": "toolu_s2", "error": false},
    {"id": "toolu_s3", "error": true}
  ],
  "denials": [
    {"agent": "detetive", "tool": "Bash"},
    {"agent": "detetive", "tool": "Write"}
  ],
  "pwned": false
}
```

Ou seja: o `touch` e o `Write` voltaram como erro e foram registrados como recusas do `detetive`, o `git log` passou, e nenhum dos dois arquivos existe no fim. O `Write` é recusado mesmo estando no `tools` do subagente, porque a política do Detetive tem `write: none`.

## Quando rodar

| Mudança | Rode |
|---|---|
| `entrypoint.sh` | `run-scenarios.sh` (todos) |
| `tool-guard.sh` ou o formato do `policy.json` | `run-guard-tests.sh` e `run-scenarios.sh policy_invalid` |
| `egress/` ou `launch.sh` | `run-scenarios.sh net_probe real_api_401` |
| `CLAUDE_CODE_VERSION` da imagem | Os dois, e compare um `stream.ndjson` real com o `EVENTS.md` |

Os testes do Laravel (`php artisan test`) não sobem o runner: eles simulam o Docker com `Process::fake()`. Os testes desta página são os únicos que exercitam a imagem de verdade.
