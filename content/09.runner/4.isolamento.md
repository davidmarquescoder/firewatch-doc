O runner executa código que ninguém revisou: as dependências do repositório, os testes e o que os agentes decidirem rodar. Por isso ele é tratado como **não confiável** e contido em camadas:

| Camada | Contra o quê | Onde |
|---|---|---|
| Container descartável | Sobras entre execuções | Um container por execução, removido no fim |
| Limites de recursos | Loop, fork bomb, vazamento de memória | Flags do `docker run`/`create` |
| Sem privilégios | Escalada dentro do container | Usuário `runner`, `--cap-drop ALL`, `no-new-privileges` |
| Rede restrita | Exfiltração e download de código | [Egress](/runner/egress) |
| Token fora do alcance dos agentes | Vazamento ou push com a credencial | stdin + `GIT_ASKPASS` + remoção antes dos agentes |
| Sem push | Alteração do repositório pelo runner | Hook `pre-push` + [guarda de ferramentas](/runner/tool-guard) |
| Guarda por agente | Agente fazendo mais do que o papel dele | [Guarda de ferramentas](/runner/tool-guard) |
| Timeouts | Execução travada | Etapas + tempo total + `hardTimeout()` do Laravel |

## launch.sh

`docker/runner/launch.sh` é o `docker run` **de referência**. O [`DockerRunner`](/investigacao/docker-runner) do Laravel monta os mesmos limites (com `docker create` + `cp` + `start`), e o `run-local.sh` e os testes usam o `launch.sh` por baixo.

```bash
docker/runner/launch.sh --env-file docker/runner/runner.env -v <incidente>:/runner/input:ro
```

Stdout, stderr e código de saída são os do runner. Os argumentos extras vão direto para o `docker run`.

| Variável | Padrão | Flag |
|---|---|---|
| `RUNNER_IMAGE` | `firewatch-runner:latest` | Imagem |
| `RUNNER_CPUS` | `2` | `--cpus` |
| `RUNNER_MEMORY` | `4g` | `--memory` e `--memory-swap` |
| `RUNNER_PIDS` | `1024` | `--pids-limit` |
| `RUNNER_NETWORK` | `restricted` | Ver [Egress](/runner/egress#modos-de-rede) |

Sempre, sem variável:

```bash
docker run --rm \
  --label br.com.firewatch.runner=1 \
  --ulimit nofile=4096:8192 \
  --cap-drop ALL \
  --security-opt no-new-privileges \
  …
```

Com `RUNNER_NETWORK=restricted`, o script também sobe o `runner-egress` pelo `docker compose` se ele não estiver rodando. Um valor desconhecido sai com código 2.

## Limites de recursos

| Limite | Padrão | Ao estourar |
|---|---|---|
| CPU | 2 | Fica mais lento, não morre |
| Memória | 4 GB, **sem swap** (`--memory-swap` igual a `--memory`) | O kernel mata o processo: código 137, kind `out_of_memory` |
| Processos e threads | 1024 | `fork` falha dentro do container |
| Arquivos abertos | 4096 (soft) / 8192 (hard) | `EMFILE` no processo |
| Tempo | [Timeouts](/investigacao/timeouts-e-reexecucao) | Código 124 com relatório |
| Disco | **Sem limite** | `--storage-opt size` exige XFS com `pquota` |

O PHP da imagem tem `memory_limit=1G`, abaixo dos 4 GB do container: um teste que estoura memória falha como erro do PHP, não derruba o container. Os limites efetivos vão no relatório em `limits`, lidos do cgroup.

No Laravel os limites vêm de `FIREWATCH_RUNNER_CPUS`, `FIREWATCH_RUNNER_MEMORY` e `FIREWATCH_RUNNER_PIDS` ([Variáveis de ambiente](/ambiente-e-setup/variaveis-de-ambiente)).

## Sem privilégios

| Medida | Efeito |
|---|---|
| `USER runner` (UID 1000) na imagem | Nada roda como root. O Claude Code inclusive recusa `bypassPermissions` como root |
| `--cap-drop ALL` | Nenhuma capability do Linux: sem `chown` arbitrário, sem `NET_RAW`, sem montar nada |
| `--security-opt no-new-privileges` | Um binário setuid não ganha privilégios |
| `tini` como PID 1 | Repassa sinais e recolhe processos órfãos |
| `/runner/input` do root | O runner lê o prompt e a política, mas não consegue reescrevê-los |
| `exec 0</dev/null` | Depois de ler o token, ninguém mais lê o stdin |

## O token do repositório

O token de clone é a credencial mais sensível que entra no runner. O caminho dele:

1. **Chega pelo stdin**, nunca como variável. O ambiente inicial do container continua legível em `/proc/1/environ` (do `tini`) e no `docker inspect`, mesmo depois de um `unset`. Com `REPO_TOKEN_STDIN=1`, o entrypoint lê uma linha do stdin (espera até 30 s) e fecha a entrada padrão.
2. **Vai para o git por `GIT_ASKPASS`**: um script temporário (`chmod 700`) responde usuário e senha. O token nunca entra na URL, no `.git/config` nem nos logs. Um `usuario@` embutido na `REPO_URL` é removido, porque teria prioridade e quebraria a autenticação de tokens como o `x-token-auth` do Bitbucket.
3. **É apagado logo depois do clone**: o script do `GIT_ASKPASS` é removido e `GIT_ASKPASS` e `REPO_TOKEN` saem do ambiente **antes** de instalar dependências ou chamar os agentes, que são os passos que executam código de terceiros.

Quem chama faz a parte dele:

- O **Laravel** escreve o token no stdin do `docker start --interactive` e prefere o `runner_token` (só leitura) do conector ao `access_token` ([DockerRunner](/investigacao/docker-runner#segredos)).
- O **`launch.sh`** tira a linha `REPO_TOKEN=` de cada `--env-file`, grava o resto num arquivo temporário e manda o token pelo stdin com `--interactive -e REPO_TOKEN_STDIN=1`.

Se `REPO_TOKEN` chegar pelo ambiente, o runner funciona, mas avisa no stderr que ele fica legível em `/proc/1/environ`.

::note
A credencial do Claude (`ANTHROPIC_API_KEY` ou `CLAUDE_CODE_OAUTH_TOKEN`) **continua** no ambiente durante toda a execução, porque o Claude Code precisa dela. Um agente com acesso a comandos consegue lê-la. A proteção aqui é outra: na fase dos agentes, a rede só alcança `api.anthropic.com`, e o teto `--max-budget-usd` limita o gasto da execução.
::

## Sem push

O runner **nunca** publica nada: criar a branch remota e abrir o PR é papel do Laravel, com o diff do relatório. Três camadas garantem isso:

1. Sem credencial depois do clone, um `git push` não autentica.
2. O clone ganha um hook `.git/hooks/pre-push` que recusa qualquer ref fora de `refs/heads/firewatch/*` ("firewatch: push bloqueado para …").
3. A [guarda de ferramentas](/runner/tool-guard#git-push-merge-e-pull) recusa `git push`, `git merge` e `git pull` para **todos** os agentes, inclusive o orquestrador com acesso total.

## Achar containers que sobraram

Todo container do runner tem o label `br.com.firewatch.runner=1`. Os criados pelo Laravel têm também `br.com.firewatch.application=<id>` e o nome `firewatch-run-<id do AgentRun>`.

```bash
docker ps -a --filter label=br.com.firewatch.runner=1
```
