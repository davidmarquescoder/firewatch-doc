O **runner** é o container descartável onde os agentes trabalham. Ele clona o repositório da aplicação, instala as dependências, roda o Claude Code com os subagentes, confere o resultado e devolve eventos NDJSON e um relatório final. Tudo fica em `firewatch-back/docker/runner/`:

| Arquivo | Para quê | Página |
|---|---|---|
| `Dockerfile` | Imagem base (PHP, Node, git, Claude Code) | Esta |
| `stacks/` | Imagens por stack, derivadas da base | Esta |
| `entrypoint.sh` | O script de entrada `firewatch-run` | [Contrato do entrypoint](/runner/entrypoint) |
| `EVENTS.md` | Eventos do stdout e formato do `report.json` | [Eventos e relatório](/runner/eventos-e-relatorio) |
| `launch.sh` | `docker run` de referência com limites e isolamento | [Isolamento](/runner/isolamento) |
| `egress/` | Proxy de saída (Squid) e allowlists | [Egress](/runner/egress) |
| `tool-guard.sh` | Hook que limita o que cada agente pode fazer | [Guarda de ferramentas](/runner/tool-guard) |
| `run-local.sh`, `runner.env.example` | Rodar um incidente no terminal | [Testes do runner](/runner/testes) |
| `test/` | Claude falso, API falsa e cenários | [Testes do runner](/runner/testes) |
| `examples/incident-001/` | Incidente de exemplo (prompt, system prompt e `replay.ndjson`) | |

Os comandos de build do dia a dia estão em [Imagens do runner](/ambiente-e-setup/imagens-do-runner). Esta página explica **o que** vai na imagem e **por quê**.

## A imagem base

O `Dockerfile` tem dois estágios. O primeiro (`FROM node:<NODE_VERSION>-bookworm-slim AS node`) só serve de fonte para os binários do Node. O segundo parte de `php:<PHP_VERSION>-cli-bookworm` e monta o resto:

| Camada | O que instala | Por quê |
|---|---|---|
| Pacotes do sistema | `git`, `curl`, `ca-certificates`, `openssh-client`, `jq`, `ripgrep`, `unzip`, `zip`, `tini`, `procps` e os `EXTRA_APT_PACKAGES` | `git` para o clone e para o Detetive, `jq` para o entrypoint e o guarda, `ripgrep` para o Grep do Claude Code, `tini` como PID 1 |
| PHP | As extensões de `PHP_EXTENSIONS` (via `install-php-extensions`), `php.ini-development` e `memory_limit=1G` | O set padrão cobre um app Laravel típico |
| Composer | `composer:2` copiado da imagem oficial | |
| Node | Binários e `node_modules` globais copiados do estágio `node`, `npm`, `npx`, Yarn 1 (corepack) e pnpm (npm global) | Sem `curl \| bash` do NodeSource. Yarn e pnpm são baixados **no build**, porque na fase dos agentes não há registry acessível |
| Claude Code | `npm install -g @anthropic-ai/claude-code@<CLAUDE_CODE_VERSION>` | O CLI que roda os agentes em modo headless |
| Usuário | `runner` (UID e GID `1000`), com `/workspace` e `/runner/output` dele; `/runner/input` existe, mas é do root | O Claude Code recusa `bypassPermissions` como root, e o runner não precisa de mais privilégios |
| Scripts | `entrypoint.sh` → `/usr/local/bin/firewatch-run` e `tool-guard.sh` → `/usr/local/bin/firewatch-tool-guard`, ambos `755` | |
| Git | `user.name "Firewatch Bot"`, e-mail `firewatch-bot@users.noreply.local`, `init.defaultBranch main`, `safe.directory '*'` | Identidade padrão de qualquer commit feito dentro do container |

Variáveis de ambiente fixas da imagem:

| Variável | Valor | Para quê |
|---|---|---|
| `HOME` | `/home/runner` | |
| `DISABLE_AUTOUPDATER` | `1` | O container é descartável: o Claude Code não se atualiza sozinho |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | `1` | Sem telemetria nem chamadas além da API. Na rede restrita, elas seriam recusadas de qualquer forma |
| `COMPOSER_ALLOW_SUPERUSER` / `COMPOSER_NO_INTERACTION` | `0` / `1` | |
| `CI` | `true` | Ferramentas de teste e instalação entram em modo não interativo |
| `TERM` | `dumb` | Menos códigos de cor na saída |
| `COREPACK_HOME` | `/usr/local/share/corepack` | Cache do Yarn baixado no build, legível pelo `runner` |

O entrypoint é `["/usr/bin/tini", "--", "firewatch-run"]`. O `tini` repassa sinais e recolhe processos órfãos, o que importa porque o runner roda `timeout`, `tee` e os processos dos testes como filhos.

O `.dockerignore` exclui tudo, exceto `Dockerfile`, `entrypoint.sh` e `tool-guard.sh`. Os `runs/`, o `runner.env` (com credenciais) e os testes **nunca** entram no contexto do build.

### Labels

| Label | Valor na base |
|---|---|
| `br.com.firewatch.runner.contract` | `1`: versão do contrato de entrada e saída (variáveis, eventos NDJSON e `report.json`). Sobe para `2` só numa mudança incompatível |
| `br.com.firewatch.runner.stack` | `php-node` (cada stack sobrescreve) |
| `br.com.firewatch.runner.php` / `.node` | As versões usadas no build |

## Build args

| Build arg | Padrão | O que muda |
|---|---|---|
| `PHP_VERSION` | `8.5` | A tag `php:<v>-cli-bookworm` |
| `NODE_VERSION` | `22` | A tag `node:<v>-bookworm-slim` |
| `PHP_EXTENSIONS` | `bcmath exif gd intl pcntl pdo_mysql pdo_pgsql redis sockets zip` | Lista separada por espaço. Qualquer nome suportado pelo `install-php-extensions` |
| `EXTRA_APT_PACKAGES` | vazio | Pacotes Debian extras (ex.: `sqlite3 imagemagick`) |
| `CLAUDE_CODE_VERSION` | `latest` | A versão do Claude Code. Fixe para builds reprodutíveis |
| `RUNNER_USER` / `RUNNER_UID` | `runner` / `1000` | Usuário sem privilégios. Mude o UID só se os volumes do `run-local.sh` precisarem de outro dono |

::warning
O formato do stream do Claude Code muda entre versões. O `EVENTS.md` foi escrito com a 2.1.321. Depois de mudar `CLAUDE_CODE_VERSION`, rode o `run-local.sh` com `DRY_RUN=0` num incidente de teste e compare o `stream.ndjson` com o `EVENTS.md` antes de usar a imagem em produção.
::

## Imagens por stack

Para uma linguagem que a base não tem, a imagem **estende** a base em vez de copiá-la. Ela herda o `firewatch-run`, o guarda, o usuário `runner`, o Claude Code e o contrato. O exemplo pronto é `stacks/python/Dockerfile`:

```dockerfile [stacks/python/Dockerfile]
ARG BASE_IMAGE=firewatch-runner:latest
FROM ${BASE_IMAGE}

ARG PYTHON_APT_PACKAGES="python3 python3-venv python3-pip python3-dev build-essential"
LABEL br.com.firewatch.runner.stack="python"

USER root
RUN apt-get update \
    && apt-get install -y --no-install-recommends ${PYTHON_APT_PACKAGES} \
    && apt-get clean && rm -rf /var/lib/apt/lists/* \
    && python3 -m venv /opt/venv \
    && /opt/venv/bin/pip install --no-cache-dir --upgrade pip pytest \
    && chown -R runner:runner /opt/venv

ENV VIRTUAL_ENV=/opt/venv PATH=/opt/venv/bin:${PATH} \
    PIP_DISABLE_PIP_VERSION_CHECK=1 PYTHONDONTWRITEBYTECODE=1

USER runner
```

O virtualenv em `/opt/venv`, do usuário `runner` e já no `PATH`, faz `pip install` e `python3 -m pytest` funcionarem sem root e sem `--break-system-packages`.

### Criar uma stack nova

1. Copie `docker/runner/stacks/python` para `docker/runner/stacks/<nome>`.
2. Mantenha `ARG BASE_IMAGE=firewatch-runner:latest` e `FROM ${BASE_IMAGE}`. Assim dá para construir a stack sobre uma variação da base (`--build-arg BASE_IMAGE=firewatch-runner:php8.4-node20`).
3. Troque `USER root` → instalação → **`USER runner`** no final. Se a imagem terminar como root, o Claude Code recusa rodar.
4. Defina `LABEL br.com.firewatch.runner.stack="<nome>"`.
5. **Não** declare `ENTRYPOINT` nem `CMD`: o da base é o contrato.
6. Instale tudo o que a instalação de dependências e os testes vão precisar **no build**. Na fase dos agentes, a rede só alcança a API da Anthropic ([Egress](/runner/egress)).
7. Se o registry de pacotes da linguagem não estiver em `egress/allowlist-setup.txt`, adicione o domínio (ex.: `proxy.golang.org`) e reinicie o `runner-egress`.
8. Construa a base primeiro e depois a stack:

```bash
docker build -t firewatch-runner:latest docker/runner
docker build -t firewatch-runner:<nome> docker/runner/stacks/<nome>
```

9. Na aplicação, aponte **imagem do runner** para `firewatch-runner:<nome>`. Se a detecção automática do entrypoint não conhecer a stack (ela conhece Composer, npm/pnpm/yarn e pip), preencha o **comando de instalação** e o **comando de testes** (ex.: `go mod download` e `go test ./...`).
10. Teste com `run-local.sh` e `-e DRY_RUN=1` para conferir clone e instalação sem gastar créditos ([Testes do runner](/runner/testes)).

::note
A detecção automática só usa uma stack quando o runtime existe na imagem. Se o projeto tem `composer.json`, `package.json` ou `requirements.txt`/`pyproject.toml`/`setup.py` e falta o runtime correspondente, o runner para na instalação com código 4: "A imagem do runner não tem o runtime exigido pelo projeto: …". Isso aponta direto para a imagem errada na aplicação. Com um comando de instalação explícito, essa checagem não roda.
::
