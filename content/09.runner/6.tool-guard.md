O campo `tools` de um subagente do Claude Code só liga ou desliga uma ferramenta **inteira**. Ele não diz quais comandos o `Bash` pode rodar nem quais arquivos o `Edit` pode alterar. Para o Detetive ler o `git log` sem mexer em nada, ou para o Advogado do Diabo escrever testes sem tocar na correção, o runner usa um **hook `PreToolUse`**: o `tool-guard.sh`, instalado como `/usr/local/bin/firewatch-tool-guard`.

## Como o hook entra

Na etapa `agents`, se existe `policy.json`, o entrypoint:

1. valida a política (`version: 1`, `main` e `agents` como objetos, `commands` em `none`/`read_only`/`tests`/`full` e `write` em `none`/`tests`/`code`/`any`). Inválida, sai com código 2;
2. confere se o guarda existe e é executável;
3. gera um arquivo de settings e passa ao Claude Code com `--settings`:

```json
{"disableAllHooks": false, "hooks": {"PreToolUse": [{"matcher": "*", "hooks": [{"type": "command", "command": "/usr/local/bin/firewatch-tool-guard", "timeout": 30}]}]}}
```

4. exporta para o guarda `FIREWATCH_POLICY_FILE`, `FIREWATCH_REPO_DIR` (`/workspace/repo`) e `FIREWATCH_DENIALS_FILE`.

O hook roda **antes de toda chamada de ferramenta**, de qualquer agente, e vale mesmo com `--permission-mode bypassPermissions`. O `--settings` tem precedência sobre o `.claude/settings.json` do repositório, então o repositório não consegue desligar a guarda com `disableAllHooks`.

## A decisão

O Claude Code entrega ao hook um JSON no stdin com `tool_name`, `tool_input`, `cwd` e, quando a chamada vem de um subagente, `agent_type` (o slug). O guarda escolhe a política:

| Quem chama | Política |
|---|---|
| Sessão principal (sem `agent_type`) | `main` |
| Subagente do time | `agents.<slug>` |
| Qualquer outro agente: os nativos do Claude Code (`general-purpose`, `Explore`, `Plan`…) ou um definido pelo repositório | **Nenhuma: tudo recusado** |

Para permitir, o guarda não escreve nada e sai com 0. Para recusar, ele escreve:

```json
{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "Firewatch: Detetive (detetive) não pode criar nem alterar arquivos."}}
```

O motivo volta ao agente como **erro da ferramenta**, para ele mudar de abordagem, e cada recusa é registrada em `report.policy.denials` com o agente, a ferramenta, o comando ou caminho, o motivo e a hora.

::warning
A guarda **falha fechada**. Qualquer erro interno do script (um `jq` que quebra, uma política ausente) cai no `trap ERR` e recusa a chamada: "erro interno do guarda de ferramentas; chamada recusada por segurança".
::

## 1. Ferramentas

Se a política tem `tools` (uma lista), qualquer ferramenta fora dela é recusada. `tools: null` libera todas. A exceção é o `TodoWrite`, a lista de tarefas do próprio agente, sempre permitido.

## 2. Comandos (Bash)

O nível vem de `commands` (no painel, **acesso a comandos** do perfil):

| Nível | Pode |
|---|---|
| `none` | Nenhum comando |
| `read_only` | Só comandos de leitura |
| `tests` | Leitura + o executor de testes do projeto |
| `full` | Qualquer comando, menos `git push`/`merge`/`pull` |

### O que é leitura

A análise é **conservadora**: na dúvida, recusa. Antes de olhar os programas, o guarda tira só `2>&1`, `2>/dev/null`, `>/dev/null` e `&>/dev/null`. Depois recusa o comando inteiro se ainda houver:

- `>` (redirecionar para arquivo);
- `$(…)`, crases, `<(…)` ou `>(…)` (substituição de comando);
- quebra de linha.

O resto é partido em `;`, `&&`, `||`, `|` e `&`, e **cada trecho** precisa ser de leitura:

| Programa | Aceito quando |
|---|---|
| `ls`, `cat`, `head`, `tail`, `wc`, `grep`, `egrep`, `fgrep`, `file`, `stat`, `pwd`, `echo`, `printf`, `cut`, `diff`, `basename`, `dirname`, `realpath`, `readlink`, `jq`, `true`, `nl`, `tac`, `column`, `which`, `type`, `cd` | Sempre |
| `git` | Subcomando `log`, `blame`, `show`, `diff`, `status`, `grep`, `ls-files`, `ls-tree`, `rev-parse`, `branch`, `shortlog`, `describe`, `cat-file`, `rev-list` ou `reflog` (também depois de `--no-pager`), sem `--output`, `-O` nem `--open-files-in-pager`. `git branch` só para listar (`--show-current`, `-a`, `-r`, `-v`, `--list`, `--contains`…) |
| `find` | Sem `-exec`, `-execdir`, `-ok`, `-okdir`, `-delete`, `-fprint*` nem `-fls` |
| `sed` | Só com `-n` e sem `-i` |
| `sort`, `tree` | Sem `-o`/`--output` |
| `rg` | Sem `--pre` (que executa um programa) |
| `uniq` | Com no máximo um arquivo (o segundo seria a saída) |
| `php` | `php -l` e `php artisan route:list`, `about` ou `--version` |
| `composer` | `show`, `why`, `depends` ou `validate` |

### O que é teste

No nível `tests`, um trecho que não é leitura ainda passa se for o executor de testes. Variáveis no começo (`APP_ENV=testing …`) são ignoradas na comparação:

- o próprio `$TEST_COMMAND`, sozinho ou com argumentos;
- `vendor/bin/pest`, `phpunit` ou `paratest` (com `php` ou `./` na frente);
- `php artisan test`;
- `composer test` / `composer run test`;
- `npm`, `pnpm` ou `yarn` com `test` ou `run test`;
- `npx vitest`/`jest` e `node_modules/.bin/vitest`/`jest`;
- `pytest` / `python -m pytest`.

### git push, merge e pull

Para **todos** os níveis, inclusive `full`, o guarda recusa qualquer `git push`, `git merge` e `git pull`. Aspas, parênteses, chaves e crases viram separadores antes da busca, para pegar também `sh -c "git push -f"`, `(git merge x)` e `/usr/bin/git --no-pager push`. Publicar a correção é papel do Laravel, só em branches `firewatch/`.

## 3. Arquivos (Edit, Write, MultiEdit, NotebookEdit)

O nível vem de `write` (no painel, **acesso a arquivos**):

| Nível | Pode alterar |
|---|---|
| `none` | Nada |
| `tests` | Só arquivos de teste |
| `code` | Só código da aplicação: nenhum teste |
| `any` | Qualquer arquivo, em qualquer lugar |

Para `tests` e `code`, o caminho é resolvido com `realpath -m` (relativo ao `cwd`, sem precisar existir), e:

- precisa ficar **dentro do repositório**. `/tmp/x.php` ou `tests/../app/X.php` são recusados (o segundo resolve para `app/` e falha como "não é teste");
- **nunca** dentro de `.git/` (hooks, config);
- "teste" usa a **mesma regra** do fluxo obrigatório: `tests/`, `test/`, `__tests__/`, `spec/`, `specs/` ou nomes como `*Test.php`, `test_*.py`, `*.test.ts`. Assim o guarda e a verificação nunca discordam sobre o que é teste.

## O time do seeder

Com os perfis padrão, a política fica assim:

| Agente | `tools` | Comandos | Arquivos |
|---|---|---|---|
| Chefe de Plantão (`main`) | todas | `full` | `any` |
| Sentinela | Read, Grep, Glob | `none` | `none` |
| Detetive | Read, Grep, Glob, Bash | `read_only` | `none` |
| Advogado do Diabo | Read, Grep, Glob, Bash, Edit, Write | `tests` | `tests` |
| Cirurgião | Read, Grep, Glob, Bash, Edit, Write | `tests` | `code` |
| Escrivão | Read, Grep, Glob | `none` | `none` |

O Chefe precisa de `any` porque é ele quem escreve o `agent-report.json`, fora do repositório.

## Limitações conhecidas

- **Leitura não é limitada por caminho.** `Read`, `Grep` e `Glob` passam direto pela guarda: um agente lê qualquer arquivo que o usuário `runner` consiga ler, dentro ou fora do repositório. A contenção aqui é a rede, que não deixa o conteúdo sair.
- **Rodar testes executa código do repositório.** Um agente com `commands: tests` que também escreve código (o Cirurgião) consegue, em tese, rodar o que escreveu por dentro da suíte. O isolamento do container e a rede restrita continuam valendo.
- **`commands: full` contorna `write`.** Um agente com Bash livre escreve arquivos pelo shell. Por isso, no time padrão, só o orquestrador tem `full`.
- **A análise de comandos é sintática.** Ela recusa em vez de interpretar, mas não é um sandbox. Ferramentas novas e programas fora da lista de leitura são recusados até alguém incluí-los no `tool-guard.sh`.

Os casos cobertos pelos testes estão em [Testes do runner](/runner/testes#run-guard-testssh).
