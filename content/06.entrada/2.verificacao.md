Toda requisição às rotas de entrada passa pelo middleware `verify-webhook` (`App\Http\Middleware\VerifyIncomingWebhook`) antes de chegar ao controller. Ele resolve o conector pelo UUID da URL, escolhe o verificador do tipo e só deixa passar o que foi assinado com o segredo daquele conector.

## As peças

Todas ficam em `app/Services/Incoming/Verification`.

| Classe | Papel |
|---|---|
| `WebhookVerifier` (interface) | `verify(Request, Connector): VerificationResult`. Contrato: comparar em **tempo constante** e **falhar fechado** (sem segredo configurado, recusa) |
| `WebhookVerifierFactory` | Escolhe a implementação pelo tipo do conector |
| `SentryWebhookVerifier` | Sentry: HMAC do corpo |
| `GenericWebhookVerifier` | Webhook genérico: HMAC com timestamp, ou token |
| `SlackRequestVerifier` | Slack: request signing `v0` |
| `VerificationResult` | Resultado: válido ou não, motivo e método |

### WebhookVerifierFactory

```php [app/Services/Incoming/Verification/WebhookVerifierFactory.php]
public function for(ConnectorTypeEnum $type): WebhookVerifier
{
    return $this->container->make(match ($type) {
        ConnectorTypeEnum::SENTRY          => SentryWebhookVerifier::class,
        ConnectorTypeEnum::GENERIC_WEBHOOK => GenericWebhookVerifier::class,
        ConnectorTypeEnum::SLACK           => SlackRequestVerifier::class,
        default                            => throw new LogicException("Connector type [{$type->value}] does not receive webhooks."),
    });
}
```

O `LogicException` nunca chega ao cliente: o middleware só chama a factory depois de conferir `ConnectorTypeEnum::receivesWebhooks()` (Sentry, webhook genérico e Slack). Conectores de repositório e Jira recebem `404` antes.

### VerificationResult

`final readonly class` com construtor privado e duas fábricas:

| Fábrica | `valid` | `reason` | `method` |
|---|---|---|---|
| `VerificationResult::valid('signature')` | `true` | `ok` | `signature` ou `token` |
| `VerificationResult::invalid('timestamp outside tolerance')` | `false` | O motivo | `null` |

O **motivo é só para o log**: nunca volta para quem chamou (um atacante não aprende o que errou) e nunca contém segredos ou assinaturas. O **método** fica no atributo `webhook_auth_method` da requisição, para quem quiser saber se a chamada veio assinada ou com token.

## O middleware, passo a passo

| # | Verificação | Falhou |
|---|---|---|
| 1 | O conector existe (`Connector::find()`; apagados com soft delete não contam) e o tipo recebe webhooks | `404 Webhook não encontrado.` |
| 2 | O verificador do tipo aceita a requisição | `401 Assinatura do webhook inválida.` + `Log::warning('Incoming webhook rejected')` com `connector_id`, `type`, `reason` e `ip` |
| 3 | O conector não está `inactive` | `403 Conector desativado.` |
| 4 | Guarda o conector em `webhook_connector` e o método em `webhook_auth_method` | |

A ordem 2 → 3 é proposital: o status só é revelado a quem provou ter o segredo. Um conector com status `error` (último teste de conexão falhou) **continua recebendo**: só `inactive` bloqueia.

## Sentry

| | |
|---|---|
| Credencial | `client_secret` da integração interna do Sentry |
| Cabeçalho | `Sentry-Hook-Signature` |
| Cálculo | `hex(HMAC-SHA256(corpo bruto, client_secret))` |
| Anti-replay | Não. O formato do Sentry não assina horário |

A comparação aceita a assinatura em maiúsculas ou minúsculas e ignora espaços nas pontas. Motivos possíveis no log: `connector has no client_secret`, `missing Sentry-Hook-Signature header`, `signature mismatch`.

Para configurar no Sentry: **Settings → Developer Settings → Custom Integrations → New Internal Integration**, com a Webhook URL `https://<firewatch>/api/webhooks/<id do conector>`, ligue **Alert Rule Action** e/ou os recursos `issue`/`error`, e copie o **Client Secret** para o conector.

## Webhook genérico

| | Assinatura (recomendada) | Token |
|---|---|---|
| Credencial | `secret` do conector | `secret` do conector |
| Cabeçalhos | `X-Firewatch-Timestamp: <unix em segundos>` e `X-Firewatch-Signature: sha256=<hex>` | `Authorization: Bearer <secret>` ou `X-Firewatch-Token: <secret>` |
| Cálculo | `HMAC-SHA256("<timestamp>.<corpo bruto>", secret)` | Compara o segredo inteiro (`hash_equals`) |
| Anti-replay | Timestamp até **300 s** de diferença do relógio do servidor (para trás ou para frente) | Não |
| Quando usar | Sempre que a ferramenta conseguir calcular HMAC | Ferramentas que só mandam um cabeçalho fixo. **Só com HTTPS** |

Se o cabeçalho `X-Firewatch-Signature` estiver presente, **só a assinatura** é avaliada: um token válido junto com uma assinatura errada é recusado.

```bash
BODY=$(cat docs/incoming/generic-webhook.example.json)
TS=$(date +%s)
SIG=$(printf '%s.%s' "$TS" "$BODY" | openssl dgst -sha256 -hmac "$FIREWATCH_SECRET" -hex | sed 's/^.* //')

curl -X POST "$FIREWATCH_URL/api/webhooks/$CONNECTOR_ID" \
  -H 'Content-Type: application/json' \
  -H "X-Firewatch-Timestamp: $TS" \
  -H "X-Firewatch-Signature: sha256=$SIG" \
  --data "$BODY"
```

::warning
A assinatura cobre os **bytes exatos** do corpo. Assine a mesma string que vai no `--data`: reformatar o JSON depois de assinar (espaços, ordem das chaves, quebra de linha final) muda o HMAC e dá `401`.
::

O PHP gera a mesma assinatura com `GenericWebhookVerifier::sign($body, $secret, $timestamp)`, usado nos testes. Motivos no log: `connector has no secret`, `missing or invalid X-Firewatch-Timestamp header`, `timestamp outside tolerance`, `signature mismatch`, `missing signature or token`, `token mismatch`.

O **Testar conexão** de um conector de entrada não chama nada externo: confere se o segredo existe e tem pelo menos 16 caracteres.

## Slack

| | |
|---|---|
| Credencial | `signing_secret` do app do Slack (opcional no cadastro, obrigatório para o comando) |
| Cabeçalhos | `X-Slack-Request-Timestamp` e `X-Slack-Signature` |
| Cálculo | `v0=` + `hex(HMAC-SHA256("v0:<timestamp>:<corpo bruto>", signing_secret))` |
| Anti-replay | Timestamp até **300 s** |

É o algoritmo documentado pelo Slack. O método estático `SlackRequestVerifier::sign()` reproduz a assinatura nos testes. Motivos no log: `connector has no signing_secret`, `missing Slack signature headers`, `timestamp outside tolerance`, `signature mismatch`.

O token legado de verificação que o Slack ainda manda no corpo (`token`) **não** é usado nem guardado.
