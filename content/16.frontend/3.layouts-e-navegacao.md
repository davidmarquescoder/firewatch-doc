O painel tem dois layouts e uma moldura de página:

| Peça | Arquivo | Onde |
|---|---|---|
| Layout `default` | `app/layouts/default.vue` | Todas as telas depois do login: sidebar, busca e conteúdo |
| Layout `auth` | `app/layouts/auth.vue` | Só a tela de login |
| `<LayoutAppPage>` | `app/components/layout/AppPage.vue` | Dentro do `default`: a barra do topo, o cabeçalho e o corpo de cada tela |

## As rotas e a autenticação

| Rota | Página | Layout | Acesso |
|---|---|---|---|
| `/` | `pages/index.vue` | nenhum | Redireciona para `/dashboard` (`routeRules`) |
| `/auth/sign-in` | `pages/auth/sign-in.vue` | `auth` | Só visitantes (`guestOnly`) |
| `/dashboard` | `pages/dashboard/index.vue` | `default` | Logado |
| `/incidents` | `pages/incidents/index.vue` | `default` | Logado |
| `/incidents/:id` | `pages/incidents/[id].vue` | `default` | Logado |
| `/applications` | `pages/applications/index.vue` | `default` | Logado |
| `/connectors` | `pages/connectors/index.vue` | `default` | Logado |
| `/agents` | `pages/agents/index.vue` | `default` | Logado |
| `/budget` | `pages/budget/index.vue` | `default` | Logado |
| `/audit` | `pages/audit/index.vue` | `default` | Logado |

Não há middleware próprio. Quem protege as rotas é o **middleware global do `nuxt-auth-sanctum`** (`sanctum.globalMiddleware.enabled: true` no `nuxt.config.ts`): toda página exige sessão, menos as marcadas com `sanctum: { guestOnly: true }` no `definePageMeta`.

```ts [nuxt.config.ts]
sanctum: {
    mode: 'cookie',
    endpoints: {
        csrf: '/sanctum/csrf-cookie',
        login: '/api/v1/auth',
        logout: '/api/v1/auth',
        user: '/api/v1/auth',
    },
    redirect: {
        onLogin: '/dashboard',
        onLogout: '/auth/sign-in',
        onAuthOnly: '/auth/sign-in',
        onGuestOnly: '/dashboard',
    },
    globalMiddleware: { enabled: true },
},
```

::mermaid
---
code: |
  flowchart TD
      A[Navegação para uma rota] --> B{"Página guestOnly?"}
      B -->|sim| C{"Tem sessão?"}
      C -->|sim| D["/dashboard"]
      C -->|não| E[Abre a página]
      B -->|não| F{"Tem sessão?"}
      F -->|sim| E
      F -->|não| G["/auth/sign-in"]
---
::

- Quem não está logado e abre qualquer tela vai para `/auth/sign-in`.
- Quem já está logado e abre `/auth/sign-in` vai para `/dashboard`.
- O login, o usuário atual e o logout usam o mesmo endpoint, `/api/v1/auth`, com métodos diferentes ([Usuários](/referencia-da-api/usuarios)).
- A rota pedida antes do login **não** é lembrada (`keepRequestedRoute` fica no padrão, `false`): depois de entrar, o usuário vai sempre para `/dashboard`.
- Os papéis do usuário não entram na conta: o painel mostra as mesmas telas e botões para todos, e é a API que recusa o que o papel não permite ([Papéis e permissões](/seguranca/papeis-e-permissoes)).

A rota `/` não tem conteúdo próprio. O `routeRules` do `nuxt.config.ts` a redireciona para `/dashboard`:

```ts [nuxt.config.ts]
routeRules: {
    '/': { redirect: '/dashboard' },
},
```

Quem está logado fica no dashboard; um visitante segue para `/auth/sign-in` pelo middleware. É o que acontece ao clicar no logo da tela de login, que aponta para `/`. Sem esse redirecionamento, o visitante via uma página em branco, porque `pages/index.vue` é só um `guestOnly` vazio.

## O layout default

O layout usa os componentes de dashboard do Nuxt UI:

```vue
<UDashboardGroup unit="rem" storage-key="firewatch-sidebar">
    <UDashboardSidebar collapsible resizable … />
    <UDashboardSearch :groups="searchGroups" … />
    <slot />
</UDashboardGroup>
```

### A sidebar

| Opção | Valor | Efeito |
|---|---|---|
| `collapsible` | | Recolhe para só ícones (botão no topo de cada página) |
| `resizable` | `min-size` 14rem, `default-size` 16rem, `max-size` 20rem | O usuário arrasta a borda |
| `collapsed-size` | 4rem | Largura recolhida |
| `storage-key` | `firewatch-sidebar` | Largura e estado recolhido ficam salvos no navegador |

De cima para baixo:

1. **Logo** (`<AppLogo>`), que leva a `/dashboard`. Recolhida, mostra só o ícone.
2. **Botão de busca** "Buscar…", com o atalho **⌘K** / **Ctrl K**.
3. **Menu de navegação** (`UNavigationMenu` vertical), com tooltip e popover quando recolhida. Em telas pequenas a sidebar vira gaveta e fecha sozinha ao escolher um item.
4. **Cartão "Plantão Ativo"**, com um ponto verde pulsando: "Os agentes investigam novos incidentes automaticamente. Nada vai para produção sem sua aprovação." É fixo, não consulta a API. Some com a sidebar recolhida.
5. **Menu do usuário** no rodapé.

### navigation.ts: uma fonte para o menu e a busca

`app/utils/navigation.ts` é a única lista de telas do painel. Dela saem o menu da sidebar e a busca rápida:

| Seção | Tela | Rota | Ícone |
|---|---|---|---|
| Operação | Visão Geral | `/dashboard` | `fa6-solid:chart-diagram` |
| Operação | Incidentes | `/incidents` | `fa6-solid:mosquito` |
| Configurações | Aplicações | `/applications` | `fa6-solid:cubes` |
| Configurações | Time de agentes | `/agents` | `fa6-solid:robot` |
| Configurações | Conectores | `/connectors` | `fa6-solid:puzzle-piece` |
| Configurações | Custos & Limites | `/budget` | `fa6-solid:coins` |
| Configurações | Auditoria | `/audit` | `fa6-solid:clipboard-list` |

Cada link tem também uma `description` ("Erros detectados e o trabalho dos agentes"), que aparece ao lado do nome na busca.

| Função | O que faz |
|---|---|
| `APP_NAVIGATION` | A lista acima, em seções |
| `toNavigationMenuItems(onSelect)` | Converte para o formato do `UNavigationMenu`: um grupo por seção, com o rótulo da seção em cima |
| `findNavigationLink(path)` | O link de uma rota, incluindo sub-rotas (`/incidents/123` → Incidentes) |

Para uma tela nova aparecer no menu e na busca, basta acrescentá-la aqui.

### A busca rápida (⌘K)

`<UDashboardSearch>` abre com ⌘K / Ctrl K ou pelo botão da sidebar. O placeholder é "Para onde você quer ir?". Os grupos são as seções de `APP_NAVIGATION`, com a descrição como sufixo. Com `color-mode`, a busca também oferece trocar entre claro e escuro. Ela só navega entre telas: não procura incidentes nem aplicações.

### O menu do usuário

`<LayoutUserMenu>` (`components/layout/UserMenu.vue`) mostra o avatar (foto ou iniciais), o nome e o e-mail, de `useCurrentUser()`. O menu tem:

- o e-mail, como rótulo;
- **Aparência**: Clara, Escura ou Seguir o sistema;
- **Sair**: chama o `logout` do Sanctum (`DELETE /api/v1/auth`) e volta para `/auth/sign-in`. Se falhar, um toast "Não foi possível sair".

## LayoutAppPage

Toda tela do layout `default` começa com `<LayoutAppPage>`, que monta um `UDashboardPanel` com fundo `bg-canvas`:

```vue
<LayoutAppPage
    id="incidents"
    title="Incidentes"
    description="…"
    :parent="{ label: 'Incidentes', to: '/incidents' }"
>
    <template #toolbar>…</template>
    <template #actions>…</template>
    …conteúdo…
</LayoutAppPage>
```

| Prop / slot | O que faz |
|---|---|
| `id` | O id do painel (padrão `page`) |
| `title` | O fim da trilha e o `h1` do cabeçalho |
| `description` | Texto abaixo do título |
| `parent` | Um nível anterior na trilha, `{ label, to }`. A tela de um incidente usa "Incidentes" |
| `icon` | Aceito, mas não aparece: o bloco do ícone está comentado |
| `#toolbar` | À direita da barra do topo, antes do botão de tema. As telas de incidentes e o dashboard põem ali o `<RealtimeConnectionStatus>` |
| `#actions` | À direita do cabeçalho: "Nova aplicação", "Simular Incidente", o seletor de período… |
| `#header` | Substitui o cabeçalho inteiro. Só a tela do incidente usa, para mostrar badges, título e stack trace |
| padrão | O corpo, numa coluna de até `max-w-7xl`, com espaço entre os blocos |

A barra do topo tem:

- o botão de recolher a sidebar;
- a trilha "Firewatch › [pai ›] Título", feita à mão num `<nav aria-label="Você está em">`;
- o slot `#toolbar`;
- o botão de tema claro/escuro (`UColorModeButton`).

### LayoutSectionCard

`<LayoutSectionCard>` é o bloco padrão dentro de uma tela: um cartão `bg-surface` com título, descrição, ícone e ações à direita. Com `flush`, o corpo fica sem padding, para tabelas e listas que vão de borda a borda. O dashboard usa um por gráfico.

### LayoutComingSoon

`<LayoutComingSoon>` é um aviso "Em construção" com ícone, título e descrição. Nenhuma tela usa hoje: todas as telas do menu já existem.

## O layout auth

A tela de login tem duas colunas a partir de `lg`:

| Coluna | Conteúdo |
|---|---|
| Esquerda | Logo (link para `/`), o formulário no centro (largura máxima `max-w-sm`) e o rodapé "© {ano} Firewatch · Conexão protegida e sessão criptografada" |
| Direita (só em `lg`+) | A vitrine da marca, sempre escura: "Do erro em produção ao Pull Request em minutos.", o `<AuthAgentShowcase>` (uma investigação de mentira, animada, mostrando os agentes passo a passo) e três números fixos: "Teste antes da correção: Sempre", "Merge automático: Nunca", "Aprovação final: Humana" |

Partes da vitrine só aparecem em telas altas: o parágrafo a partir de 800 px de altura, os três números a partir de 980 px.
