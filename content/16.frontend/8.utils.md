Tudo em `app/utils/` é auto-importado e **puro**: não chama a API nem guarda estado. Os componentes chamam `buildTimeline(events)` ou `getSeverity('error')` sem `import`.

| Arquivo | O que tem | Quem usa |
|---|---|---|
| `timeline.ts` | Classificação dos eventos, blocos da timeline, frase da ação, etapas do fluxo | Tela ao vivo |
| `incidentStatus.ts` | Os 8 status do incidente, as abas e os períodos da lista | Lista, badges, dashboard |
| `severity.ts` | As 5 severidades | Lista, cabeçalho do incidente, formulário de aplicação, simulação |
| `diff.ts` | Parser de `git diff` e mini diff de edição | `LiveDiffViewer`, `LiveTimelineEntry` |
| `markdown.ts` | Markdown mínimo, com o HTML escapado | `LiveTimelineEntry` |
| `formatters.ts` | Datas relativas, data e hora, duração, plural | Quase todas as telas |
| `navigation.ts` | O menu e a busca rápida | Layout `default` ([Layouts e navegação](/frontend/layouts-e-navegacao)) |
| `agentCatalog.ts` | Papéis, etapas, ferramentas, níveis de acesso e modelos dos agentes | Time de agentes |
| `connectorTypes.ts` | Os tipos de conector, campos, logos e status | Conectores e aplicações ([Componentes](/frontend/componentes)) |

Vários arquivos são **espelhos do back-end** e dizem isso no comentário do topo ("Espelha app/Enums/…"). Mudou o enum no Laravel, muda aqui também.

## timeline.ts

Os eventos chegam do back-end já normalizados pelo `StreamEventMapper` ([Streaming](/investigacao/streaming)). Este arquivo os transforma em itens de interface.

### classifyEvent(event): TimelineKind

Decide o tipo de cada evento, olhando o `agent`, o `type` e a `metadata`:

| Condição | Tipo |
|---|---|
| `agent = runner` e `metadata.stage = report` | `report` |
| `agent = runner` | `runner` |
| `agent = firewatch` | `error` (se `type = error`) ou `integration` |
| `type = thinking` | `thinking` |
| `type = read_file` com ferramenta `Grep` ou `Glob` | `search` |
| `type = read_file` | `read` |
| `type = edit_file` com ferramenta `Write` | `write` |
| `type = edit_file` | `edit` |
| `type = run_command` | `command` |
| `type = test_result` | `test` |
| `type = error` | `error` |
| `metadata.delegation` | `delegation` |
| `metadata.task = started` | `task_started` |
| `metadata.task` (outro valor) | `task_finished` |
| o resto | `message` |

As constantes `AGENT_RUNNER = 'runner'` e `AGENT_FIREWATCH = 'firewatch'` são os slugs dos dois "agentes" que não são IA.

### buildTimeline(events): TimelineBlock[]

Agrupa os eventos em blocos para a `<LiveTimeline>`:

- **Delegação** vira um bloco próprio (`type: 'delegation'`).
- Eventos seguidos do **mesmo agente** ficam no mesmo bloco (`type: 'agent'`, ou `'system'` para runner e Firewatch).
- **Pensamentos seguidos** viram uma linha só, com `count` (o "(3×)").
- **Testes**: o evento de início e o de fim de um mesmo teste (mesmo `tool_use_id`) viram **uma** linha; o fim vai em `entry.result`. Um fim sem início aparece sozinho.

Cada bloco tem o id `b{sequence do primeiro evento}`, estável entre renderizações.

### describeAction(event): string

A frase curta do cartão "Agora": "Lendo …/app/Services/OrderService.php", "Buscando “OrderService” no código", "Editando …", "Criando …", "Rodando composer test", "Rodando os testes", "Testes passaram", "Pensando…", "Delegando a próxima etapa", "Entregou a etapa". Sem evento: "Aguardando o primeiro passo…".

`shortPath(path, segments = 3)` corta caminhos longos nos 3 últimos pedaços (`…/Services/Order/OrderService.php`).

### deriveFlow(events, roleOf, outcome): FlowStepState[]

Calcula as 8 etapas do `<LiveFlowProgress>` a partir das **tarefas dos subagentes** (`metadata.task = started` e o fim correspondente) e do papel de cada um (`roleOf`, do `useAgentDirectory`):

| Etapa | Regra |
|---|---|
| 1 Triagem, 2 Causa raiz, 4 Correção, 7 Relatório | O estado da tarefa do agente com papel `triage`, `investigator`, `fixer` e `writer`: aberta = `active`, fechada = `done`, fechada com erro = `failed` |
| 3 Teste que falha | A **1ª** tarefa de um agente `tester` |
| 5 Teste passa | A **2ª** tarefa de `tester`: `done` quando um teste passou nela |
| 6 Suíte completa | A 2ª tarefa de `tester`: `done` quando ela fecha ou quando um **segundo** teste passou |
| 8 PR aberto | `done` com `pr_url` ou status `pr_opened`; `active` quando a execução terminou `fixed` |

Ajustes no fim:

- **Execução encerrada**: uma etapa que ficou `active` vira `done` (se corrigiu) ou `failed`. Numa execução `fixed`, etapas que nunca rodaram também contam como `done`.
- **Sem tarefas de subagente** (execuções antigas, numa sessão só): usa o status do incidente: `investigating` → até a etapa 2, `fixing` → 4, `testing` → 6, `pr_opened` → 8.

## incidentStatus.ts

Espelha `IncidentStatusEnum.php`. Cada status tem rótulo, cor do Nuxt UI, ícone, se está **em andamento** e as classes do chip:

| Status | Rótulo | Cor | Em andamento |
|---|---|---|---|
| `received` | Recebido | neutral | não |
| `queued` | Na fila | info | sim |
| `investigating` | Investigando | info | sim |
| `fixing` | Corrigindo | info (chip `primary`) | sim |
| `testing` | Testando | info (chip `primary`) | sim |
| `pr_opened` | PR aberto | success | não |
| `failed` | Falhou | error | não |
| `ignored` | Ignorado | neutral | não |

| Export | O que é |
|---|---|
| `INCIDENT_STATUSES` | A tabela acima |
| `getIncidentStatus(value)` | Uma linha da tabela |
| `IN_PROGRESS_STATUSES` | `queued`, `investigating`, `fixing`, `testing` |
| `INCIDENT_STATUS_TABS` | As abas da lista: Todos, Em andamento, PR aberto, Falharam, Aguardando, Ignorados, cada uma com os status que filtra |
| `INCIDENT_PERIODS` | Todo o período, 24 horas, 7 dias, 30 dias |

A máquina de estados está em [Máquina de estados](/modelo-de-dados/maquina-de-estados).

## severity.ts

Espelha `IncidentSeverityEnum.php`, **em ordem crescente**:

| Valor | Rótulo | Cor | Marcador |
|---|---|---|---|
| `debug` | Debug | neutral | `bg-dimmed` |
| `info` | Informativo | info | `bg-info` |
| `warning` | Alerta | warning | `bg-warning` |
| `error` | Erro | error | `bg-error` |
| `critical` | Crítico | error | `bg-error` com anel |

`SEVERITIES` é a lista; `getSeverity(value)` devolve uma linha. A ordem importa: a severidade mínima das regras de acionamento é escolhida nela, e a lista de incidentes a mostra invertida (Crítico primeiro).

## diff.ts

### parseDiff(diff): DiffFile[]

Lê um `git diff` unificado e devolve um arquivo por `diff --git a/… b/…`:

| Campo | Como sai |
|---|---|
| `path`, `oldPath` | Do cabeçalho `diff --git` |
| `status` | `added` (`new file mode`), `deleted` (`deleted file mode`), `renamed` (`rename from`) ou `modified` |
| `binary` | `Binary files …` |
| `additions`, `deletions` | Contadas linha a linha |
| `lines` | Cada linha com `type` (`add`, `del`, `context`, `hunk`, `meta`), o conteúdo sem o sinal e os números antigo e novo |

Os cabeçalhos de trecho viram uma linha `hunk` com o intervalo e o contexto (`-10,7 +10,9 · function store()`). O cabeçalho do arquivo (`index`, `---`, `+++`) é ignorado. A linha vazia que sobra no fim do diff é removida.

### editPreview(oldText, newText): DiffLine[]

Transforma uma edição do agente (`old_string` → `new_string` da ferramenta Edit) num mini diff: as linhas antigas como `del` e as novas como `add`, sem números. É o trecho que aparece embaixo de "Editou" na timeline.

## markdown.ts

### renderMarkdown(source): string

Um Markdown **mínimo e seguro** para os textos dos agentes. Todo o HTML de entrada é **escapado antes** das transformações, então o resultado só tem as tags que a própria função gera:

| Markdown | Vira |
|---|---|
| `` `código` `` | `<code>` |
| `**negrito**`, `*itálico*` | `<strong>`, `<em>` |
| `[texto](https://…)` | `<a target="_blank" rel="noopener noreferrer">` (só links `http`/`https`) |
| `# título` a `#### título` | `<h4>` |
| `- item`, `1. item` | `<ul>`, `<ol>` |
| ```` ``` ```` | `<pre>` |
| linhas seguidas | um `<p>` |

As classes são Tailwind (`bg-elevated`, `text-highlighted`, `text-primary`…), então o resultado já sai no tema.

Na timeline, o HTML gerado é entregue ao `<MDC>` (`LiveTimelineEntry`). A descrição do PR, na aba Pull Request do `LiveResult`, vai direto para o `<MDC>`, sem passar por aqui.

::note
Um link que não começa com `http://` ou `https://` (um `javascript:`, por exemplo) não vira `<a>`: fica como texto. É o que impede um agente de injetar um link perigoso na interface.
::

## formatters.ts

| Função | Exemplo |
|---|---|
| `formatRelativeTime(value)` | "há 5 minutos", "ontem", "agora mesmo" (abaixo de 1 min) |
| `formatDateTime(value)` | "10/11/2026 14:32" |

## agentCatalog.ts

Espelha os enums dos perfis de agente:

| Export | Conteúdo |
|---|---|
| `AGENT_ROLES` | `orchestrator` (Orquestração, todas as etapas), `triage` (1), `investigator` (2), `tester` (3 e 5–6), `fixer` (4), `writer` (7), cada um com ícone e cores |
| `AGENT_FLOW` | As 7 etapas dos agentes (sem o "PR aberto", que é do Firewatch) |
| `AGENT_TOOLS` | `Read`, `Grep`, `Glob`, `Bash`, `Edit`, `Write`, `NotebookEdit`, `Agent`, `TodoWrite`, com rótulo e ícone; `Bash`, `Edit`, `Write` e `NotebookEdit` marcadas como arriscadas |
| `COMMAND_ACCESS` | Nenhum, Somente leitura, Leitura e testes, Qualquer comando |
| `WRITE_ACCESS` | Nenhum, Só testes, Só código, Qualquer arquivo |
| `AGENT_MODELS` | Padrão, Herdar, `opus`, `sonnet`, `haiku` |

O significado de cada nível está em [Níveis de acesso](/perfis-de-agente/niveis-de-acesso).
