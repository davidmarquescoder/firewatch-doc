O painel do Firewatch é o repositório `firewatch-front`: uma aplicação **Nuxt 4** que só conversa com a API do Laravel. Ele não tem banco, regra de negócio nem rotas de servidor próprias. Tudo o que mostra vem de `/api/v1/*` ([Referência da API](/referencia-da-api)) e do WebSocket do Reverb ([Tempo real](/tempo-real)).

## Stack

| Peça | Versão instalada | Para quê |
|---|---|---|
| Nuxt | **4.6.3** | Framework. Roteamento por arquivos, auto-import de componentes, composables e utils |
| Nuxt UI | **4.12.0** | Componentes (`UDashboard*`, `UCard`, `UForm`, `UTable`, `USlideover`…), tema por cores e `app.config.ts` |
| Tailwind CSS | **4.3.3** | Estilos utilitários. Vem com o Nuxt UI; o `main.css` importa os dois |
| nuxt-auth-sanctum | **3.1.5** | Login por sessão (cookie) no Laravel Sanctum, `useSanctumClient()` e o middleware global de autenticação |
| nuxt-laravel-echo + pusher-js | **1.0.2** | Laravel Echo apontando para o Reverb |
| @nuxtjs/mdc | **0.23.3** | Componente `<MDC>`, que renderiza Markdown (descrição do PR e mensagens dos agentes) |
| motion-v | **2.12.0** | Animações. Hoje só a pasta `components/ui/animated-tabs` usa |
| @nuxt/fonts | 1.2.0 | Módulo de fontes (a Roboto, porém, vem de um `@import` do Google Fonts no `main.css`) |
| @iconify-json/lucide, simple-icons, fa6-solid | | Ícones. `i-lucide-*` na maior parte da interface, `i-simple-icons-*` nas marcas (Jira, Slack…) e `fa6-solid:*` na navegação |
| @nuxt/eslint, vue-tsc, TypeScript | | Lint e checagem de tipos (`pnpm lint`, `pnpm typecheck`) |

Os módulos ativos ficam em `nuxt.config.ts`:

```ts [nuxt.config.ts]
modules: [
    '@nuxt/eslint',
    '@nuxt/ui',
    '@nuxtjs/device',
    '@nuxt/image',
    'nuxt-auth-sanctum',
    'nuxt-laravel-echo',
    '@nuxt/fonts',
    '@nuxtjs/mdc',
],
```

::note
Algumas dependências do `package.json` estão instaladas mas **não são usadas** pelo código em `app/`: `@tabler/icons-vue`, `class-variance-authority`, e os módulos `@nuxtjs/device` e `@nuxt/image` (nenhum `useDevice()` nem `<NuxtImg>`). O `@tanstack/charts` é o motor do `<UChart>` do Nuxt UI, que só o `StatTile` usa, e o `StatTile` não aparece em nenhuma tela hoje: os gráficos do dashboard são HTML e SVG feitos à mão ([Componentes](/frontend/componentes)). Os ícones `tabler:*`, `logos:*` e `lucide-extended:*` usados na interface vêm do Iconify, não do `@tabler/icons-vue`. Essas coleções não estão instaladas como `@iconify-json/*` (só `lucide`, `simple-icons` e `fa6-solid` estão), então o módulo de ícones do Nuxt UI as busca na API do Iconify quando a página abre. Sem internet, esses ícones não aparecem.
::

### Os componentes ui (shadcn-vue / Inspira UI)

O `components.json` na raiz é o arquivo de configuração do **shadcn-vue**, a CLI que copia componentes para dentro do projeto em vez de instalá-los como pacote. Ele aponta os aliases para `@/components/ui` e `@/lib/utils`.

O único componente trazido assim é o **`AnimatedTabs`** (`app/components/ui/animated-tabs/`), da biblioteca **Inspira UI**: abas com transição animada (motion-v), usadas no editor de agentes (`AgentEditorSlideover`). Ele importa o `cn()` do pacote `@inspira-ui/plugins`. O `app/lib/utils.ts` reexporta um `cn` do pacote `cn`, mas nenhum arquivo o importa.

Para o resto, a regra do projeto é usar o **Nuxt UI**: os componentes de `components/ui` são exceção para efeitos que o Nuxt UI não tem.

## Rodar

| Comando | O que faz |
|---|---|
| `pnpm install` | Instala e roda `nuxt prepare` (gera `.nuxt/`) |
| `pnpm dev` | Servidor de desenvolvimento em **`http://localhost:5000`** (`devServer` do `nuxt.config.ts`, escutando em `0.0.0.0`) |
| `pnpm build` / `pnpm preview` | Build de produção e pré-visualização |
| `pnpm lint` | ESLint (`@nuxt/eslint` + `eslint-plugin-better-tailwindcss`) |
| `pnpm typecheck` | `nuxt typecheck` (vue-tsc) |

O `README.md` do repositório ainda é o do template do Nuxt UI e fala em porta 3000. A porta certa é **5000**: é a que o back-end lista em `SANCTUM_STATEFUL_DOMAINS` e `FRONTEND_URL`. Em outra porta, o login por cookie não funciona. O CI (`.github/workflows/ci.yml`) roda `pnpm install`, `lint` e `typecheck` em Node 24 a cada push; não há testes automatizados no front.

### Variáveis de ambiente

| Variável | Valor local | Quem usa |
|---|---|---|
| `NUXT_PUBLIC_SANCTUM_BASE_URL` | `http://localhost:8000` | O navegador: base de todas as chamadas à API e da autenticação do Echo |
| `NUXT_SANCTUM_BASE_URL` | `http://localhost:8000` | O servidor do Nuxt, quando renderiza no servidor |
| `NUXT_PUBLIC_SANCTUM_ORIGIN` / `NUXT_SANCTUM_ORIGIN` | `http://localhost:5000` | Cabeçalho `Origin`/`Referer` que o Sanctum confere |
| `NUXT_PUBLIC_ECHO_KEY` | o `REVERB_APP_KEY` do back-end | Laravel Echo |
| `NUXT_PUBLIC_ECHO_HOST` / `PORT` / `SCHEME` | `localhost` / `8080` / `http` | Onde o navegador acha o Reverb |
| `NUXT_PUBLIC_ECHO_LOG_LEVEL` | `1` | `0` só erros … `3` tudo no console |
| `NUXT_PUBLIC_SITE_URL` | | Não é lido pelo código |

O `.env` local ainda tem as variáveis `REVERB_*` e `VITE_REVERB_*`, herdadas de um template Laravel. O Nuxt não lê nenhuma delas. A configuração do Echo e a diferença entre o host visto pelo navegador e pelo Laravel estão em [Tempo real](/tempo-real).

## Estrutura de pastas

```text
firewatch-front/
├── nuxt.config.ts          módulos, Sanctum, Echo, porta 5000
├── components.json         configuração do shadcn-vue (components/ui)
├── app/
│   ├── app.vue             UApp (locale pt-BR, toaster), título e SEO
│   ├── app.config.ts       cores do tema e ajustes dos componentes do Nuxt UI
│   ├── assets/css/main.css Tailwind, tokens de superfície e de movimento
│   ├── configs/components/ um arquivo por componente do Nuxt UI ajustado
│   ├── layouts/            default (sidebar) e auth (login)
│   ├── pages/              uma pasta por tela
│   ├── composables/        acesso à API e ao WebSocket, estado da tela ao vivo
│   ├── components/         por domínio: live, incident, agent, connector…
│   │   └── ui/             componentes copiados (shadcn-vue / Inspira UI)
│   ├── utils/              funções puras: timeline, status, severidade, diff…
│   └── lib/utils.ts        cn() do shadcn (não usado)
├── server/                 vazio
└── public/favicon.ico
```

Tudo dentro de `composables/` e `utils/` é **auto-importado** pelo Nuxt: as páginas chamam `useIncidents()` ou `formatDuration()` sem `import`. Os componentes também, com o nome da pasta como prefixo: `components/layout/AppPage.vue` vira `<LayoutAppPage>`, `components/incident/RetryInvestigationButton.vue` vira `<IncidentRetryInvestigationButton>`. Quando o arquivo já começa com o nome da pasta, o prefixo não se repete: `components/live/LiveTimeline.vue` é `<LiveTimeline>`.

Não há pastas `middleware/`, `plugins/` nem `stores/`. A proteção das rotas vem do middleware global do `nuxt-auth-sanctum` ([Layouts e navegação](/frontend/layouts-e-navegacao)); o estado compartilhado usa `useState()` dentro dos composables.

### O diretório server/

O Nuxt trata `server/` como o lugar das rotas de API e middlewares do próprio servidor Nitro (`server/api`, `server/routes`, `server/middleware`). No Firewatch a pasta existe, mas está **vazia**: o painel não tem back-end próprio. Toda chamada vai direto do navegador para o Laravel, com o cookie de sessão.

Isso é proposital: as credenciais dos conectores, as regras e o estado ficam num lugar só, o Laravel. Se um dia o painel precisar esconder algo do navegador (um proxy, uma chave), é em `server/` que entra.

## Convenções

- **Textos em português, código em inglês.** Nomes de variáveis, tipos e comentários de código em inglês; tudo o que o usuário lê em português.
- **Componentes pequenos por domínio.** Um componente por responsabilidade, agrupados pela pasta do domínio ([Componentes](/frontend/componentes)).
- **Composables para dados.** As páginas não chamam `$fetch` direto: usam um composable que conhece o endpoint e os tipos ([Composables](/frontend/composables)).
- **Espelhos do back-end.** Listas fixas que existem no Laravel (status, severidade, tipos de conector, papéis dos agentes) são copiadas em `utils/` com um comentário "Espelha …" apontando o arquivo PHP. Mudou o enum no back-end, muda aqui também.
- **Nuxt UI primeiro.** Ajustes visuais vão para `app.config.ts`/`configs/components` em vez de classes repetidas ([Tema e design system](/frontend/tema-e-design-system)).
