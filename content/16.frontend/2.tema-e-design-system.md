O visual do painel vem de três lugares, do mais geral para o mais específico:

| Arquivo | O que define |
|---|---|
| `app/app.config.ts` | As cores semânticas do Nuxt UI e quais componentes recebem ajustes |
| `app/configs/components/*.ts` | O ajuste de cada componente: raio, espaçamento, variantes |
| `app/assets/css/main.css` | Tailwind, as superfícies `canvas`/`surface`, a animação `shimmer` e os tokens de movimento |

A regra é mexer no tema antes de repetir classes: se todo botão precisa de `rounded-md`, isso vai para `configs/components/button.ts`, não para cada `<UButton>`.

## Cores (app.config.ts)

```ts [app/app.config.ts]
export default defineAppConfig({
    ui: {
        colors: {
            primary: 'violet',
            secondary: 'orange',
            neutral: 'zinc',
            success: 'emerald',
        },
        button, input, slideover, select, textarea, inputNumber, inputDate,
        inputTime, selectMenu, modal, separator, card, pageCard, inputMenu, avatar,
    },
});
```

| Cor semântica | Paleta Tailwind | Onde aparece |
|---|---|---|
| `primary` | `violet` | Marca, botões principais, agente em ação, links |
| `secondary` | `orange` | Detalhes da marca (o gradiente da tela de login) |
| `neutral` | `zinc` | Fundos, bordas, textos |
| `success` | `emerald` | PR aberto, testes que passaram, conector ativo |
| `info`, `warning`, `error` | padrão do Nuxt UI (`blue`, `yellow`, `red`) | Na fila/investigando, alertas, falhas |

Os componentes usam sempre o **nome semântico** (`color="primary"`, `text-error`, `bg-success/10`), nunca a paleta direto. Trocar `primary: 'violet'` por outra cor muda o painel inteiro.

Os textos e fundos seguem as classes do Nuxt UI, que já se adaptam ao modo escuro: `text-highlighted` (títulos), `text-toned`, `text-muted` (texto secundário), `text-dimmed` (ícones e rótulos apagados), `bg-default`, `bg-elevated`, `ring-default`.

## Ajustes por componente (configs/components)

Cada arquivo exporta o objeto que o Nuxt UI mescla com o tema padrão do componente (`slots`, `variants`, `compoundVariants`, `defaultVariants`). O `shared.ts` guarda o que os controles têm em comum:

```ts [app/configs/components/shared.ts]
export const controlSizeVariants = {
    xs: { base: 'px-2.5 py-1.5 text-xs gap-1' },
    sm: { base: 'px-3 py-2 text-xs gap-1.5' },
    md: { base: 'px-3 py-2.5 text-sm gap-1.5' },
    lg: { base: 'px-3.5 py-3 text-sm gap-2' },
    xl: { base: 'px-4 py-3.5 text-base gap-2' },
} as const;

export const CONTROL_RADIUS = 'rounded-md';

export const CONTROL_FIELD_OUTLINE =
    'text-highlighted bg-default ring-1 ring-inset ring-default placeholder:text-dimmed hover:ring-muted focus-visible:ring-2 focus-visible:ring-primary';

export const CONTROL_FIELD_SUBTLE = 'bg-elevated ring-default/50 placeholder:text-muted';
```

Assim um `UButton size="md"` e um `UInput size="md"` têm a mesma altura e ficam alinhados numa linha de filtros.

| Arquivo | Componente | Ajuste |
|---|---|---|
| `button.ts` | `UButton` | `rounded-md`, `cursor-pointer`, a escala de tamanhos. Texto branco no `solid` de `primary`, `secondary` e `error`. A variante `outline` com anel interno e foco em `primary` |
| `input.ts`, `textarea.ts`, `select.ts`, `selectMenu.ts`, `inputMenu.ts` | campos | Largura total, `rounded-md`, escala de tamanhos, variantes `outline` e `subtle` do `shared.ts`, ícones em `text-dimmed`. Padrão: `size: 'md'`, `variant: 'outline'` |
| `inputNumber.ts`, `inputDate.ts`, `inputTime.ts` | campos especiais | O mesmo, sem `root: 'w-full'` |
| `card.ts`, `pageCard.ts` | `UCard`, `UPageCard` | `rounded-md`; o `UPageCard` sem sombra |
| `modal.ts` | `UModal` | Fora de tela cheia: `max-w-7xl`, com sombra e anel |
| `slideover.ts` | `USlideover` | `right` com `max-w-lg`, `left` com `max-w-md` e um lado novo, **`large`**: à direita com `max-w-4xl`, usado pelos formulários grandes (aplicação, agente) |
| `separator.ts` | `USeparator` | Uma cor a mais, `custom` (`border-default/30`) |
| `avatar.ts` | `UAvatar` | Escala de tamanhos de `3xs` (16 px) a `3xl` (48 px) |

::note
`configs/components/breadcrumb.ts` existe, mas **não** é importado no `app.config.ts`, então não tem efeito. A trilha do topo das páginas é feita à mão no `LayoutAppPage` ([Layouts e navegação](/frontend/layouts-e-navegacao)).
::

## main.css

```css [app/assets/css/main.css]
@import url('https://fonts.googleapis.com/css2?family=Roboto:wght@400;500;600;700&display=swap');

@import '@nuxt/ui';
@import 'tailwindcss';
@import 'tw-animate-css';

@custom-variant dark (&:is(.dark *));
```

O arquivo carrega o Nuxt UI e o Tailwind 4, mais o `tw-animate-css` (classes `animate-in`, `fade-in`…, que vieram com a configuração do shadcn-vue; nenhum componente do Firewatch as usa hoje). Depois define três grupos de tokens.

### Superfícies: canvas e surface

O conteúdo fica sobre um fundo um pouco mais escuro que os cards, para separar os blocos sem depender só de bordas:

```css
@theme inline {
    --color-canvas: var(--fw-canvas);
    --color-surface: var(--fw-surface);
}

:root, .light {
    --fw-canvas: var(--ui-color-neutral-50);
    --fw-surface: #fff;
}

.dark {
    --fw-canvas: var(--ui-color-neutral-950);
    --fw-surface: var(--ui-color-neutral-900);
}
```

Isso cria os utilitários **`bg-canvas`** (o fundo da área de conteúdo, no `LayoutAppPage`) e **`bg-surface`** (cards, sidebar, `LayoutSectionCard`).

### A animação shimmer

```css
@theme static {
    --animate-shimmer: shimmer 2.5s linear infinite;
    @keyframes shimmer {
        from { background-position: 200% 0; }
        to   { background-position: -200% 0; }
    }
}
```

Vira a classe `animate-shimmer`, uma faixa de brilho que corre da direita para a esquerda. Foi feita para a barra do topo de um incidente ao vivo; essa barra está comentada hoje no cabeçalho da tela do incidente.

### Tokens de movimento

Escala única de durações, curvas e desfoques, no padrão do transitions.dev. Os componentes animados usam esses nomes em vez de valores soltos, por exemplo `var(--duration-slow) var(--ease-smooth-out)` nas etapas do `LiveFlowProgress` e `ease-(--ease-smooth-out)` no destaque de um evento novo da timeline:

| Token | Valor |
|---|---|
| `--duration-stagger` | 40ms (atraso entre itens de uma cascata) |
| `--duration-micro` / `quick` / `fast` | 80 / 150 / 250ms |
| `--duration-medium` / `slow` / `very-slow` | 350 / 400 / 500ms |
| `--ease-smooth-out` | `cubic-bezier(0.22, 1, 0.36, 1)` |
| `--ease-bounce` | `cubic-bezier(0.34, 1.36, 0.64, 1)` |
| `--ease-in-out` | `ease-in-out` |
| `--blur-small` / `medium` / `large` | 2 / 3 / 8px |

O resto do arquivo são variáveis do shadcn (`--background`, `--primary`, `--chart-1`…) **comentadas**. Elas vieram com a configuração do shadcn-vue e não são usadas: as cores vêm do Nuxt UI.

### Fontes

A fonte efetiva é a pilha padrão do sistema do Tailwind (`-apple-system, "Segoe UI", Roboto, …`). O `@import` do Google Fonts baixa a Roboto, que entra nessa pilha nos sistemas sem as anteriores. As linhas que trocariam a fonte (`--font-sans: 'Geist'…`, `--font-display`) estão comentadas.

::note
Vários títulos usam a classe `font-display` (o `h1` do `LayoutAppPage`, o título do incidente, os rótulos da sidebar). Como `--font-display` não está definida, a classe não muda nada. Para dar uma fonte de destaque aos títulos, basta descomentar e definir `--font-display` no `@theme`.
::

## Modo escuro

O Nuxt UI controla o modo de cor (`useColorMode()`), com a classe `.dark` no `<html>`. O usuário troca em dois lugares:

- o botão de sol/lua no topo de cada página (`UColorModeButton` no `LayoutAppPage`);
- o menu do usuário, em **Aparência**: claro, escuro ou sistema.

As superfícies (`--fw-canvas`, `--fw-surface`) têm valores para os dois modos. A vitrine da tela de login é sempre escura (`bg-zinc-950`), independentemente do modo.

## app.vue

`app/app.vue` envolve tudo no `<UApp>`, que dá ao Nuxt UI o idioma e as notificações:

| Configuração | Valor |
|---|---|
| `locale` | `pt_br` (`@nuxt/ui/locale`): textos internos dos componentes em português |
| `toaster` | `position: 'top-center'`, `max: 4`, `duration: 5000`, `expand: false` |
| `<NuxtLoadingIndicator>` | Barra de 4 px no topo, cor `violet`, sem atraso, durante a navegação |
| `<html lang>` | `pt-BR` |
| Título | `"<página> · Firewatch"`; sem título de página, "Firewatch — resposta automática a incidentes" |
| SEO | `description`, Open Graph e Twitter Card com `/og-image.png` (o arquivo não existe em `public/`) |
