O FireWatch é usado em **português**. O back-end roda com `APP_LOCALE=pt_BR` e devolve mensagens, erros de validação e rótulos em português. O inglês existe nos arquivos de tradução, mas hoje não é um idioma completo do sistema.

## Configuração

| Variável (`.env`) | Valor | Efeito |
|---|---|---|
| `APP_LOCALE` | `pt_BR` | Idioma de todas as respostas |
| `APP_FALLBACK_LOCALE` | `pt_BR` | Idioma usado quando a chave não existe no idioma atual |
| `APP_FAKER_LOCALE` | `pt_BR` | Dados falsos das factories e seeders (nomes, CPFs, endereços) |

::note
Sem essas variáveis, o `config/app.php` cai em `en`. Confira se o `.env` veio do `.env.example`.
::

## Arquivos

```text
lang/
├── en/
│   ├── auth.php          20 linhas
│   ├── pagination.php
│   ├── passwords.php
│   └── validation.php    198 linhas
└── pt_BR/
    ├── auth.php          24 linhas
    ├── messages.php      92 linhas   ← só existe em pt_BR
    ├── pagination.php
    ├── passwords.php
    └── validation.php    191 linhas
```

| Arquivo | Para quê |
|---|---|
| `auth.php` | Login e sessão. O `pt_BR` tem chaves a mais usadas pelos controllers de autenticação: `login` ("Seja bem-vindo, :name!"), `logout`, `show`, `verify` e `verified`. |
| `pagination.php`, `passwords.php` | Padrão do Laravel, traduzidos. |
| `validation.php` | Mensagens das regras de validação e a lista `attributes`, que traduz nomes de campo (`first_name` → "primeiro nome", `password_confirmation` → "confirmação da senha"…). |
| `messages.php` | Mensagens próprias da API do FireWatch. Só existe em `pt_BR`. |

## `messages.php`

Organizado em quatro grupos:

| Grupo | Chaves | Uso |
|---|---|---|
| `messages.response.<recurso>.<ação>` | `connector.store`, `incident.retry`, `budget.update`, `agent_run.events`… | Mensagem de sucesso de cada endpoint. Um recurso por bloco (`user`, `organization`, `connector`, `application`, `budget`, `audit_log`, `incident`, `agent_profile`, `metrics`, `agent_run`). |
| `messages.exception.<domínio>.<erro>` | `connector.in_use`, `address.zip_code_invalid`… | Erros de regra de negócio devolvidos com `error()`. |
| `messages.authorization.*` | `generic`, `role.unauthorized` | Falta de autorização. Mensagens com código (`#10000`, `#10001`). |
| `messages.permissions.*` | `view`, `create`, `edit`, `delete` | Falta de permissão sobre um modelo (`:model`), com código `#2000x`. |

Os grupos `authorization` e `permissions` vêm do template e ainda não são usados pelo código do FireWatch.

### Adicionando um endpoint

1. Crie as chaves em `lang/pt_BR/messages.php`, no bloco do recurso:

    ```php [lang/pt_BR/messages.php]
    'response' => [
        // …
        'webhook_delivery' => [
            'index' => 'Entregas listadas com sucesso.',
            'retry' => 'Entrega reenfileirada.',
        ],
    ],
    ```

2. Use a chave no controller:

    ```php
    return $this->success(message: __('messages.response.webhook_delivery.retry'));
    ```

3. Se o endpoint valida campos novos com nomes técnicos, acrescente o nome legível em `attributes` do `lang/pt_BR/validation.php`.

O stub `controller.model.api` já gera as chaves `messages.response.<modelo>.<ação>` nos cinco métodos REST: só falta criá-las no arquivo.

## O que fica fora de `lang/`

Nem todo texto em português passa pelos arquivos de tradução. Três lugares guardam textos diretamente no código, de propósito:

| Onde | Exemplos | Por quê |
|---|---|---|
| Constantes `LABELS` dos **enums** | "PR aberto", "Testes não passaram", "Advogado do Diabo" | O enum é a fonte única do valor e do rótulo. As Resources devolvem `status` + `status_label`, e o painel só mostra. |
| Motivos e explicações gerados pelo domínio | `TriggerRulesEngine` ("Aguardando ocorrências: 2/5"), `FailureClassifier`, `IncidentFailureKindEnum::nextStep()` | São frases montadas com dados do incidente, gravadas no banco (`status_reason`) e enviadas ao Slack e ao Jira. |
| Respostas dos webhooks e mensagens de integrações | "Assinatura do webhook inválida.", textos do Slack e da descrição do PR | Saem para sistemas externos. |

Logs e mensagens de exceção técnicas (`RunnerLaunchException`, `InvalidIncidentTransitionException`) ficam em inglês ou em português conforme o público: o que chega ao time vai em português, o que fica só no log vai em inglês.

## Lacunas conhecidas

::warning
**Regras de validação sem tradução aparecem em inglês.** O `lang/pt_BR/validation.php` não tem 36 regras que existem no `en`, entre elas **`enum`**, `decimal`, `list`, `lowercase`, `uppercase`, `prohibits` e as variações de `missing_*`, `present_*` e `required_if_accepted`. Uma falha dessas regras devolve o texto em inglês que vem com o próprio Laravel.
::

Exemplo real: o FireWatch usa `Rule::enum` em 14 lugares (tipo de conector, status, severidade, papel do agente…). Enviar um tipo de conector inválido devolve:

```json
{
  "message": "The selected type is invalid.",
  "errors": { "type": ["The selected type is invalid."] }
}
```

Duas formas de corrigir, que podem ser combinadas:

1. **Completar o `pt_BR/validation.php`** com as regras que faltam (o pacote da comunidade `laravel-lang/lang` tem a tradução completa). Por exemplo:

    ```php [lang/pt_BR/validation.php]
    'enum' => 'O :attribute selecionado é inválido.',
    ```

2. **Usar `APP_FALLBACK_LOCALE=en`**, para que uma chave ausente em português caia ao menos na mensagem em inglês em vez da chave crua.

Outras lacunas:

- **`lang/en/messages.php` não existe.** Com `APP_LOCALE=en`, as mensagens da API continuam em português (por causa do fallback `pt_BR`), e as chaves `auth.login`, `auth.logout`, `auth.show`, `auth.verify` e `auth.verified` também não têm versão em inglês.
- **Rótulos de enums não são traduzíveis.** Para oferecer o painel em outro idioma, as constantes `LABELS` precisariam passar a usar chaves de tradução.

## Painel

O painel Nuxt tem seus próprios textos, todos em português. Ele exibe o que a API devolve (`message`, `*_label`, `status_reason`) e não traduz valores de enum por conta própria. Os componentes do Nuxt UI usam o locale `pt_br`.
