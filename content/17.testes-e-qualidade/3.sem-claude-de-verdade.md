**Nenhum teste automatizado chama o Claude de verdade.** Nem os do Laravel, nem os do runner, nem o CI.

## Por quê

- **Custa dinheiro.** Cada investigação real é cobrada pela Anthropic: a de referência (incidente-001) custou cerca de US$ 0,21, e o teto padrão de uma execução é US$ 2. Uma suíte de 572 testes que chamasse a IA custaria dezenas de dólares a cada `php artisan test`. O crédito de desenvolvimento do projeto é pequeno.
- **Não é determinístico.** O modelo responde diferente a cada vez. Um teste que depende da resposta da IA passa e falha sem nenhuma mudança no código.
- **É lento e depende de rede.** Uma investigação leva minutos e precisa da internet; a suíte inteira roda em 16 segundos, offline.

O que os testes provam é o **código do Firewatch** em volta da IA: o que ele manda para o Claude, o que faz com cada linha que volta e como reage a cada desfecho. Para isso basta simular as respostas.

## As travas no Laravel

O Laravel não fala com a API da Anthropic. Quem fala é o Claude Code, dentro do container do runner, que o Laravel sobe com `docker`. Então a trava que importa é a de **processos**:

| Trava | Onde | O que impede |
|---|---|---|
| `Process::preventStrayProcesses()` | `tests/TestCase.php`, em **todo** teste Feature | Qualquer `Process::run()` sem `Process::fake()` lança exceção. Nenhum `docker create`, `docker start` ou `claude` pode rodar por engano |
| `Process::fake(fn …)` | `InvestigateIncidentJobTest` | Responde a cada subcomando do Docker (`image`, `create`, `start`) com uma saída pronta. O `start` devolve um `stream-json` montado no próprio teste |
| Fila síncrona | `phpunit.xml` | O `InvestigateIncident` roda dentro do teste, com o `Process` já simulado; não sobra job para um worker de verdade |
| `Http::preventStrayRequests()` | Testes de integração (Bitbucket, GitHub, Slack, Jira, teste de conexão) | Nenhuma requisição HTTP sai sem `Http::fake()` |
| Credenciais falsas | `config([...])` nos testes | A chave do Claude nos testes é `sk-ant-test-0123456789abcdef` |

::warning
O `phpunit.xml` **não** apaga `FIREWATCH_ANTHROPIC_API_KEY` nem `FIREWATCH_CLAUDE_CODE_OAUTH_TOKEN`. Se o seu `.env` tem uma chave real, ela fica disponível na config durante os testes. O que garante que ela nunca é usada é o `preventStrayProcesses()`: sem processo, não há Claude. Nunca desligue essa trava num teste, e simule sempre o `Process` antes de rodar o job.
::

### Como um teste de investigação simula o Claude

O teste monta, linha por linha, o que o runner escreveria no stdout, e entrega no `docker start`:

```php [tests/Feature/Runner/InvestigateIncidentJobTest.php]
Process::fake(function (PendingProcess $process) use ($stdout, $exitCode, $stderr, $createExitCode, $imageLabels) {
    return match ($process->command[1] ?? null) {
        'image' => Process::result(output: json_encode($imageLabels ?: null)."\n"),
        'create' => Process::result(errorOutput: $createExitCode ? 'Unable to find image' : '', exitCode: $createExitCode),
        'start' => Process::result(output: $stdout, errorOutput: $stderr, exitCode: $exitCode),
        default => Process::result(),
    };
});
```

O `$stdout` é feito com ajudantes que geram eventos no formato real ([Eventos e relatório](/runner/eventos-e-relatorio)): `runner()` para as etapas do container, `delegation()` para o orquestrador passando a vez, `report()` para o relatório final. Assim o teste cobre sucesso, falha dos agentes, timeout, container sem relatório e erros do Docker, sem nenhum container.

## As travas no runner

Os testes da imagem ([Testes do runner](/runner/testes)) precisam rodar o `entrypoint.sh` de verdade, então usam um Claude **falso**:

| Ferramenta | O que é | Custo |
|---|---|---|
| `test/fake-claude` | Um executável no lugar do `claude`, que imprime um `stream-json` roteirizado para cada cenário (`CLAUDE_BIN`) | Zero |
| `test/fake-anthropic-api.py` | Um servidor HTTP que imita a API da Anthropic, para rodar o **Claude Code real** sem chamar a Anthropic (`ANTHROPIC_BASE_URL`) | Zero |
| Cenário `real_api_401` | O Claude Code real com uma chave falsa: a API da Anthropic responde 401 pelo proxy, o que prova a rede | Zero (a chamada é recusada antes de gerar tokens) |

## Quando é preciso o Claude de verdade

Há coisas que só uma execução real mostra: a qualidade das respostas dos agentes, se um prompt novo funciona, a demo de ponta a ponta. Nesses casos:

1. Ensaie primeiro sem IA: o `firewatch:replay-run` mostra a tela ao vivo inteira, e o `FIREWATCH_RUNNER_DRY_RUN=1` exercita o clone e a instalação ([Testar sem gastar créditos](/ambiente-e-setup/testar-sem-creditos)).
2. Rode **uma** investigação, com o repositório cobaia e um teto baixo em Custos e limites.
3. Guarde a saída. Pelo `run-local.sh`, ela fica em `docker/runner/runs/<data>-<incidente>/stream.ndjson` (fora do git). A gravação serve para o `replay-run` e como referência para os testes, como a do `docker/runner/examples/incident-001/`.

Uma execução real é uma verificação manual, não um teste: não entra na suíte nem no CI.

::note
O botão **Simular incidente** do painel **não** é um teste sem custo: ele cria um incidente de verdade e, se as regras acionarem, os agentes rodam e chamam o Claude.
::
