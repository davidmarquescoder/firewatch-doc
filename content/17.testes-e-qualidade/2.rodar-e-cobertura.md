## Rodar os testes do back-end

Os testes rodam **dentro do container `app`**. O PHP do host não tem as extensões `dom` e `mbstring` que o PHPUnit precisa.

```bash
docker compose exec app php artisan test
```

```text
Tests:    572 passed (2484 assertions)
Duration: 16.09s
```

| Para | Comando |
|---|---|
| Uma suíte | `php artisan test --testsuite=Unit` (ou `Feature`) |
| Um arquivo | `php artisan test tests/Feature/Runner/InvestigateIncidentJobTest.php` |
| Uma área | `php artisan test tests/Feature/Outgoing` |
| Testes pelo nome | `php artisan test --filter=watchdog` (casa com parte do nome do método) |
| Parar no primeiro erro | `php artisan test --stop-on-failure` |
| Pelo Composer | `composer test` (limpa o cache de config antes, depois `php artisan test`) |

Não é preciso subir o MySQL, o Redis nem o Reverb: os testes usam SQLite em memória, cache em array e fila síncrona ([Estratégia de testes](/testes-e-qualidade)). Basta o container `app` estar no ar.

::note
Se um teste falhar só na sua máquina, rode `php artisan config:clear`. Um `config:cache` antigo faz o Laravel ignorar o `phpunit.xml` e usar o `.env` de desenvolvimento, com MySQL e Redis de verdade.
::

### Cobertura de código

O container não tem driver de cobertura (nem `pcov` nem `xdebug`), e o CI roda com `coverage: none`. Por isso **não há relatório de porcentagem de cobertura**. O mapa abaixo é feito por área: o que cada arquivo de teste prova.

Para medir, instale o `pcov` no container e rode `php artisan test --coverage`.

## Os outros testes

| Parte | Como rodar | Onde está documentado |
|---|---|---|
| Runner (imagem Docker) | `docker/runner/test/run-scenarios.sh` e `docker/runner/test/run-guard-tests.sh` | [Testes do runner](/runner/testes) |
| Painel (front) | `pnpm lint` e `pnpm typecheck` em `firewatch-front` | [CI e estilo](/testes-e-qualidade/ci-e-estilo) |
| A tela ao vivo, sem IA | `php artisan firewatch:replay-run` | [Testar sem gastar créditos](/ambiente-e-setup/testar-sem-creditos) |

Os testes do Laravel **não** sobem o runner: o Docker é simulado com `Process::fake()`. Mexeu no `entrypoint.sh`, no `tool-guard.sh` ou no egress, rode os scripts do runner também.

### O que não tem teste

| O quê | Por quê / como conferir |
|---|---|
| O painel (`firewatch-front`) | Não há testes de componente nem de ponta a ponta. A garantia é o `typecheck` e o uso |
| Os comandos `add-first` e `make:auth` | Interativos e usados uma vez |
| O agendamento (`routes/console.php`) | Conferir com `php artisan schedule:list` |
| A imagem do runner com o Claude de verdade | De propósito: custa créditos ([Sem Claude de verdade](/testes-e-qualidade/sem-claude-de-verdade)) |
