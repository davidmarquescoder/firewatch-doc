Os três repositórios têm workflows do **GitHub Actions** em `.github/workflows/`. Eles só rodam se o repositório estiver hospedado no GitHub. A maior parte veio dos templates (o esqueleto `laravel/laravel` no back, o template do Nuxt UI no front e na doc) e ainda não foi adaptada ao Firewatch.

| Repositório | Workflow | Quando roda | O que faz |
|---|---|---|---|
| `firewatch-back` | `tests.yml` | push em `main` ou `master`, todo pull request, todo dia à meia-noite (UTC) | `php artisan test` em PHP 8.3, 8.4 e 8.5 |
| `firewatch-back` | `dependabot-auto-merge.yml` | pull request do Dependabot | Faz o merge automático |
| `firewatch-back` | `pull-requests.yml`, `issues.yml` | PR aberto, issue com etiqueta | Workflows de comunidade do Laravel |
| `firewatch-back` | `update-changelog.yml` | release publicada | Atualiza o `CHANGELOG.md` |
| `firewatch-front` | `ci.yml` | todo push | `pnpm install`, `lint` e `typecheck` em Node 24 |
| `firewatch-doc` | `ci.yml` | todo push | O mesmo do front |

## Back-end

### tests.yml

```yaml [.github/workflows/tests.yml]
on:
  push:
    branches:
      - main
      - master
  pull_request:
  schedule:
    - cron: '0 0 * * *'

jobs:
  tests:
    strategy:
      fail-fast: true
      matrix:
        php: [8.3, 8.4, 8.5]
    steps:
      - uses: actions/checkout@… # v7.0.1
      - uses: shivammathur/setup-php@… # v2
        with:
          php-version: ${{ matrix.php }}
          extensions: dom, curl, libxml, mbstring, zip, pcntl, pdo, sqlite, pdo_sqlite
          coverage: none
      - run: composer install --prefer-dist --no-interaction --no-progress
      - run: cp .env.example .env
      - run: php artisan key:generate
      - run: php artisan test
```

- Roda a **mesma suíte** de `php artisan test`, com o `phpunit.xml` (SQLite em memória, fila síncrona): não precisa de MySQL, Redis nem Docker no CI.
- Testa nas três versões do PHP que o `composer.json` aceita (`^8.3`). A imagem de desenvolvimento usa o PHP 8.5.
- As ações são fixadas por **hash de commit**, não por tag, e o checkout usa `persist-credentials: false`: o padrão de segurança do Laravel para Actions.
- O CI não roda o Pint nem mede cobertura (`coverage: none`).

O gatilho de push lista `main` e `master`, porque o nome da branch principal do Firewatch ainda não está fixado; as outras branches são testadas pelos pull requests. O esqueleto do Laravel vinha com `master` e `*.x`, e um push direto em `main` não rodava os testes. Quando a branch principal for definida, deixe só ela.

### Os workflows de comunidade

`pull-requests.yml`, `issues.yml` e `update-changelog.yml` chamam workflows reutilizáveis de `laravel/.github`:

| Workflow | O que faz no repositório do Laravel |
|---|---|
| `pull-requests.yml` | Avisa nos PRs abertos sem a opção de deixar os mantenedores editarem a branch |
| `issues.yml` | Reage à etiqueta "help wanted" nas issues |
| `update-changelog.yml` | A cada release, escreve as notas no `CHANGELOG.md` |

Nenhum dos três faz sentido para um projeto interno. Podem ser removidos.

## Front-end

```yaml [.github/workflows/ci.yml]
on: push

jobs:
  ci:
    strategy:
      matrix:
        os: [ubuntu-latest]
        node: [24]
    steps:
      - uses: actions/checkout@v7
      - uses: pnpm/action-setup@v6
      - uses: actions/setup-node@v7
        with:
          node-version: ${{ matrix.node }}
          cache: pnpm
      - run: pnpm install
      - run: pnpm run lint
      - run: pnpm run typecheck
```

O painel não tem testes automatizados: o CI garante só que o código passa no ESLint e na checagem de tipos do `vue-tsc`. As ações são fixadas por tag de versão.

`pnpm run lint` é `eslint .`. O `eslint.config.mjs` ignora a pasta `.agents/` (scripts das skills de IA usadas no desenvolvimento, com mais de 300 erros de lint que não são do painel):

```js [eslint.config.mjs]
export default withNuxt(
    {
        // AI skill scripts used while developing: not part of the panel.
        // A config object with only "ignores" applies to every other config.
        ignores: ['.agents/**'],
    },
    {
        rules: {
            '@typescript-eslint/no-explicit-any': 'off',
            'vue/html-self-closing': 'off',
            'no-constant-condition': 'off',
        },
    },
);
```

O `ignores` fica num objeto **sozinho** de propósito: junto com `rules`, ele só limitaria aquele bloco, e o ESLint continuaria lendo a pasta.

## Dependências: Dependabot e Renovate

| Repositório | Ferramenta | O que atualiza |
|---|---|---|
| `firewatch-back` | **Dependabot** (`.github/dependabot.yml`) | Só as **GitHub Actions**, toda semana, num PR agrupado, esperando 5 dias depois de cada versão nova (`cooldown`). O `dependabot-auto-merge.yml` faz o merge sozinho |
| `firewatch-front`, `firewatch-doc` | **Renovate** (`renovate.json`) | As dependências do npm, com a configuração do Nuxt (`github>nuxt/renovate-config-nuxt`). Precisa do app do Renovate instalado no repositório |

::note
As dependências do **Composer** não têm atualização automática: o Dependabot do back só olha as Actions. Para receber PRs de pacotes PHP, acrescente um bloco `package-ecosystem: "composer"` ao `dependabot.yml`.
::

## Estilo de código

### PHP: Pint

O back usa o **Laravel Pint** (`laravel/pint` no `require-dev`), sem `pint.json`, ou seja, com o preset **`laravel`**. O `.editorconfig` define 4 espaços, LF e UTF-8 (2 espaços em YAML).

::warning
**Rode o Pint só nos arquivos que você editou.** Hoje 176 dos 302 arquivos PHP de `app/`, `tests/`, `config/`, `routes/` e `database/` não seguem o preset (ordem dos `use`, operadores alinhados…). Um `pint` no projeto inteiro reescreveria todos eles num commit só, misturando estilo com mudança de verdade. E sem caminho ele também tenta varrer `.docker/mysql/` e falha por permissão.
::

```bash
docker compose exec app ./vendor/bin/pint app/Jobs/InvestigateIncident.php tests/Feature/Runner/InvestigateIncidentJobTest.php
```

Para só conferir, sem alterar: `./vendor/bin/pint --test <arquivos>`. O Pint não roda no CI.

### Front: ESLint e Prettier

| Ferramenta | Configuração | Roda onde |
|---|---|---|
| **ESLint** | `eslint.config.mjs`: a config do `@nuxt/eslint`, ignorando `.agents/`, sem `no-explicit-any`, `vue/html-self-closing` e `no-constant-condition` | `pnpm lint` e o CI |
| **Prettier** | `.prettierrc.json`: ponto e vírgula, aspas simples, 80 colunas, **4 espaços**, script e style do Vue indentados | Só no editor: o `.vscode/settings.json` formata ao salvar com a extensão do Prettier. O pacote `prettier` não está instalado, e o CI não confere a formatação |
| **eslint-plugin-better-tailwindcss** | | Instalado, mas não está ligado no `eslint.config.mjs` |

O `.editorconfig` do front diz 2 espaços, enquanto o Prettier e o código usam 4. Quem formata é o Prettier, então vale o que está no `.prettierrc.json`.

### Commits e textos

Do `CLAUDE.md` do projeto: nomes de código, tabelas e **mensagens de commit em inglês**; textos da interface em português. Os comentários do código seguem o inglês; as mensagens que o usuário lê (erros da API, motivos de falha, a timeline) são em português.

## Changelog

O `CHANGELOG.md` do back é o **do esqueleto do Laravel** (`laravel/laravel`, versões 13.x): lista mudanças do template, não do Firewatch. O workflow `update-changelog.yml` o atualizaria a cada release publicada no GitHub. O front e a doc não têm changelog.

O histórico do Firewatch está, por enquanto, nos códigos de tarefa espalhados pelo código e pela documentação (`PL-093` auditoria, `PL-094` budget…) e no [Histórico das migrations](/modelo-de-dados/historico-das-migrations). Para começar um changelog do projeto, apague o conteúdo herdado e o workflow do Laravel, e registre as mudanças por versão do Firewatch.

## Antes de entregar uma mudança

| Mexeu em | Rode |
|---|---|
| Back-end (PHP) | `php artisan test` e `pint` nos arquivos editados |
| Runner (`docker/runner`) | Os scripts de `docker/runner/test/` ([Testes do runner](/runner/testes)) |
| Painel | `pnpm lint` e `pnpm typecheck` |
| Tela ao vivo, sem gastar IA | `php artisan firewatch:replay-run` |
| Documentação | Os links e os diagramas no servidor da doc |
