O back-end lê as variáveis do arquivo `firewatch-back/.env` (copie de `.env.example`). As variáveis próprias do FireWatch estão agrupadas em `config/firewatch.php`, e esta página segue a ordem dele.

::warning
Depois de editar o `.env`, reinicie os processos que já estão rodando (`docker compose restart app queue runner-worker reverb scheduler`). Se você rodou `php artisan config:cache`, rode `php artisan config:clear` ou gere o cache de novo.
::

## Incidentes · `firewatch.incidents`

| Variável | Padrão | O que faz |
|---|---|---|
| `FIREWATCH_INCIDENT_REOPEN_AFTER_HOURS` | `72` | Janela de deduplicação. Um incidente encerrado continua somando ocorrências enquanto o erro se repete; se ficar em silêncio por mais que isso, a próxima ocorrência abre um incidente novo (regressão). |
| `FIREWATCH_INCIDENT_MAX_RETRIES` | `3` | Máximo de reexecuções manuais por incidente. Cada uma gasta créditos. |

## Painel · `firewatch.panel`

Usado para montar links para o painel no PR, no Slack e no Jira.

| Variável | Padrão | O que faz |
|---|---|---|
| `FIREWATCH_PANEL_URL` | valor de `FRONTEND_URL` | URL base do painel. Vazio nas duas = mensagens sem link. |
| `FIREWATCH_PANEL_INCIDENT_PATH` | `/incidents/{id}` | Caminho da tela do incidente; `{id}` é trocado pelo id. |

## Custos · `firewatch.budget`

São só os **valores iniciais**. Depois que alguém salva a tela **Custos e limites** do painel, os valores ficam na tabela `app_settings` e têm prioridade sobre o `.env`.

| Variável | Padrão | O que faz |
|---|---|---|
| `FIREWATCH_CLAUDE_MAX_BUDGET_USD` | `2` | Teto de gasto por execução, em US$. Vai para o Claude Code como `--max-budget-usd`. |
| `FIREWATCH_MONTHLY_BUDGET_USD` | vazio | Teto do mês (calendário, no fuso da aplicação, hoje UTC). Vazio = sem teto mensal. |
| `FIREWATCH_BUDGET_ALERT_PERCENT` | `80` | Percentual do teto mensal em que o time é alertado (há sempre um alerta também em 100%). |
| `FIREWATCH_BUDGET_MIN_RUN_USD` | `0.05` | Abaixo desse saldo no mês, nenhuma execução começa (falha com o kind `budget`). |

## Runner · `firewatch.runner`

### Fila e concorrência

| Variável | Padrão | O que faz |
|---|---|---|
| `FIREWATCH_RUNNER_QUEUE_CONNECTION` | `investigations` | Conexão de fila das investigações. É dedicada porque o `retry_after` dela precisa ser maior que a execução mais longa. |
| `FIREWATCH_RUNNER_QUEUE` | `investigations` | Nome da fila (também usado pela conexão em `config/queue.php`). |
| `FIREWATCH_RUNNER_QUEUE_RETRY_AFTER` | `4200` | Em `config/queue.php`. Segundos até a fila considerar o job perdido e entregá-lo a outro worker. Mantenha acima de `FIREWATCH_RUNNER_MAX_DURATION` + `FIREWATCH_RUNNER_KILL_GRACE`. |
| `FIREWATCH_RUNNER_MAX_CONCURRENT` | `2` | Máximo de runners ao mesmo tempo. Também define quantos listeners o `runner-worker` sobe. |
| `FIREWATCH_RUNNER_SLOT_WAIT_SECONDS` | `30` | Intervalo entre tentativas quando não há slot livre. |
| `FIREWATCH_DOCKER_BINARY` | `docker` | Binário do Docker usado pelo `DockerRunner`. |
| `FIREWATCH_RUNNER_IMAGE_CONTRACT` | `1` | Contrato que a imagem do runner precisa ter no label `br.com.firewatch.runner.contract`. Só muda junto com uma versão incompatível do runner. |
| `DOCKER_GID` | `984` | Usado só pelo `docker-compose.yml`: grupo do socket do Docker no host. |

### Rede

| Variável | Padrão | O que faz |
|---|---|---|
| `FIREWATCH_RUNNER_NETWORK` | `restricted` | `restricted`: rede interna + proxy com allowlist. `none`: sem rede. `open`: sem restrição (só para depuração). |
| `FIREWATCH_RUNNER_NETWORK_NAME` | `firewatch-runner-net` | Rede Docker dos runners no modo `restricted`. |
| `FIREWATCH_RUNNER_SETUP_PROXY` | `http://firewatch-runner-egress:3128` | Proxy da fase de clone e instalação. |
| `FIREWATCH_RUNNER_AGENT_PROXY` | `http://firewatch-runner-egress:3129` | Proxy da fase do Claude Code e dos testes (só `api.anthropic.com`). |

### Recursos

| Variável | Padrão | O que faz |
|---|---|---|
| `FIREWATCH_RUNNER_CPUS` | `2` | `--cpus` do container. |
| `FIREWATCH_RUNNER_MEMORY` | `4g` | `--memory` e `--memory-swap` (sem swap). Estourar = kind `out_of_memory`. |
| `FIREWATCH_RUNNER_PIDS` | `1024` | `--pids-limit`. |

### Timeouts

Em segundos. O runner aplica esses limites sozinho e sempre devolve relatório (código 124).

| Variável | Padrão | O que faz |
|---|---|---|
| `FIREWATCH_RUNNER_INSTALL_TIMEOUT` | `900` | Instalação de dependências. |
| `FIREWATCH_RUNNER_CLAUDE_TIMEOUT` | `1800` | Execução do Claude Code. |
| `FIREWATCH_RUNNER_TEST_TIMEOUT` | `600` | Suíte de testes de verificação. |
| `FIREWATCH_RUNNER_MAX_DURATION` | `3600` | Execução inteira. |
| `FIREWATCH_RUNNER_KILL_GRACE` | `120` | Folga do Laravel depois do tempo total antes de dar `docker kill`. |
| `FIREWATCH_RUNNER_STALE_QUEUED_MINUTES` | `180` | Um incidente na fila sem execução há mais que isso falha como `stale`. |
| `FIREWATCH_RUNNER_STALE_GRACE_MINUTES` | `10` | Uma execução ainda "rodando" esse tempo depois do timeout total falha como `stale`. |

### Claude

| Variável | Padrão | O que faz |
|---|---|---|
| `FIREWATCH_ANTHROPIC_API_KEY` | vazio | Chave da API da Anthropic. Tem prioridade sobre o token OAuth. |
| `FIREWATCH_CLAUDE_CODE_OAUTH_TOKEN` | vazio | Alternativa: token de assinatura do Claude (`claude setup-token`). |
| `FIREWATCH_CLAUDE_MODEL` | vazio | Modelo usado pelo Claude Code. Vazio = padrão do Claude Code. |
| `FIREWATCH_RUNNER_DRY_RUN` | `false` | `1` = clona e instala, mas nunca chama o Claude. Sem custo; o incidente termina como `dry_run`. |

::note
Preencha **uma** das credenciais do Claude. Sem nenhuma (e sem `DRY_RUN`), a execução falha logo ao subir o runner, com o kind `configuration`.
::

### Repositório

| Variável | Padrão | O que faz |
|---|---|---|
| `FIREWATCH_BITBUCKET_CLONE_URL` | `https://bitbucket.org/%s.git` | URL de clone; `%s` é o slug do repositório da aplicação. |
| `FIREWATCH_GITHUB_CLONE_URL` | `https://github.com/%s.git` | Idem para o GitHub. Para GitHub Enterprise, use a URL do seu host. |

O usuário git que acompanha o token é fixo por tipo de conector: `x-token-auth` no Bitbucket e `x-access-token` no GitHub.

## Integrações de saída · `firewatch.outgoing`

Esta seção **não tem variáveis**. Ela mapeia cada tipo de conector para a classe que faz a entrega:

| Tipo | Interface | Classe |
|---|---|---|
| `bitbucket` | `RepositoryProvider` | `BitbucketRepositoryProvider` |
| `github` | `RepositoryProvider` | `GitHubRepositoryProvider` |
| `slack` | `Notifier` | `SlackNotifier` |
| `jira` | `IssueTracker` | `JiraIssueTracker` |

Um tipo sem classe aqui é registrado na timeline como "não disponível" e a entrega segue para o próximo. As configurações de cada API ficam em `config/services.php`:

| Variável | Padrão | O que faz |
|---|---|---|
| `GITHUB_API_URL` | `https://api.github.com` | API do GitHub. Enterprise: `https://<host>/api/v3`. |
| `GITHUB_TIMEOUT` | `30` | Timeout das chamadas ao GitHub, em segundos. |
| `JIRA_TIMEOUT` | `15` | Timeout das chamadas ao Jira, em segundos. |
| `JIRA_ISSUE_TYPES` | `Bug,Problema,Erro,Defeito,Task,Tarefa` | Tipos de card preferidos, em ordem, quando o conector não define `issue_type`: vale o primeiro que o projeto tem ([Jira](/saida/jira#tipo-do-card)). |

## Tempo real · `firewatch.realtime`

| Variável | Padrão | O que faz |
|---|---|---|
| `FIREWATCH_REALTIME_ENABLED` | `true` | Liga o broadcast de eventos e status para o painel. Uma falha de broadcast nunca interrompe a investigação. |
| `FIREWATCH_REALTIME_MAX_CONTENT_LENGTH` | `4000` | Conteúdo de `AgentEvent` acima disso é cortado no WebSocket. O texto completo fica no banco. |

## Variáveis do Laravel que o FireWatch usa

Não são `FIREWATCH_*`, mas precisam estar certas para o sistema funcionar:

| Variável | Valor em desenvolvimento | Para quê |
|---|---|---|
| `APP_URL` | `http://localhost:8000` | URL da API. |
| `FRONTEND_URL` | `http://localhost:5000` | URL do painel (CORS, Sanctum e links). |
| `SANCTUM_STATEFUL_DOMAINS` | `localhost:5000,127.0.0.1:5000` | Domínios que recebem sessão por cookie. |
| `APP_TIME_ZONE` | `America/Sao_Paulo` | **Sem efeito hoje**: está no `.env.example`, mas o `config/app.php` fixa `'timezone' => 'UTC'`. Datas e o mês do budget são contados em UTC. |
| `DB_*` | `DB_HOST=db` | Conexão com o MySQL do compose. |
| `REDIS_HOST` | `redis` | Redis do compose. |
| `QUEUE_CONNECTION` / `CACHE_STORE` / `SESSION_DRIVER` | `redis` | Filas, cache e sessão. |
| `BROADCAST_CONNECTION` | `reverb` | Broadcast pelo Reverb. |
| `REVERB_APP_ID` / `REVERB_APP_KEY` / `REVERB_APP_SECRET` | gere valores aleatórios | Credenciais do app no Reverb. A `KEY` também vai para o painel. |
| `REVERB_HOST` / `REVERB_PORT` / `REVERB_SCHEME` | `reverb` / `8080` / `http` | Onde o **Laravel** encontra o Reverb (rede interna do compose). |
| `REVERB_ALLOWED_ORIGINS` | `localhost,127.0.0.1` | Hosts do painel que podem abrir o WebSocket. |
| `REVERB_MAX_REQUEST_SIZE` | `100000` | Tamanho máximo de cada broadcast, em bytes. |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REDIRECT_URI` | opcional | Login com Google. |

::tip
As credenciais do Reverb são só valores aleatórios combinados entre o back-end e o painel. Para gerar: `openssl rand -hex 16` (uma vez para a key e outra para o secret) e um número qualquer para o `REVERB_APP_ID`. Evite o `reverb:install` num projeto já configurado: ele reescreve arquivos de configuração.
::

## `.env` do painel · `firewatch-front`

Copie `firewatch-front/.env.example` para `.env`.

| Variável | Valor em desenvolvimento | Para quê |
|---|---|---|
| `NUXT_PUBLIC_SITE_URL` | `http://localhost:5000` | URL pública do painel. |
| `NUXT_PUBLIC_SANCTUM_BASE_URL` | `http://localhost:8000` | API vista pelo **navegador**. Também é a base da autenticação dos canais privados (`/api/broadcasting/auth`). |
| `NUXT_SANCTUM_BASE_URL` | `http://localhost:8000` | API vista pelo **servidor Nuxt** (SSR). |
| `NUXT_PUBLIC_SANCTUM_ORIGIN` | `http://localhost:5000` | Origem do painel no navegador. |
| `NUXT_SANCTUM_ORIGIN` | `http://localhost:5000` | Origem do painel no SSR. |
| `NUXT_PUBLIC_ECHO_KEY` | igual a `REVERB_APP_KEY` | Chave do app no Reverb. |
| `NUXT_PUBLIC_ECHO_HOST` | `localhost` | Host do Reverb visto pelo **navegador** (não use `reverb` aqui). |
| `NUXT_PUBLIC_ECHO_PORT` | `8080` | Porta do Reverb. |
| `NUXT_PUBLIC_ECHO_SCHEME` | `http` | `https` em produção (`wss`). |
| `NUXT_PUBLIC_ECHO_LOG_LEVEL` | `1` | `0` = só erros … `3` = informativo. |

::note
O painel sempre roda na porta **5000** (`devServer.port` no `nuxt.config.ts`). Se mudar, atualize `FRONTEND_URL`, `SANCTUM_STATEFUL_DOMAINS` e `REVERB_ALLOWED_ORIGINS` no back-end.
::
