O FireWatch roda em três projetos lado a lado:

| Pasta | O que é | Como roda em desenvolvimento |
|---|---|---|
| `firewatch-back` | API Laravel, filas, Reverb, runner | `docker compose` |
| `firewatch-front` | Painel Nuxt | `pnpm dev` no host (porta **5000**) |
| `firewatch-doc` | Esta documentação | `pnpm dev` no host (porta **3000**) |

## Pré-requisitos

::card-group
  :::card{icon="i-simple-icons-docker" title="Docker Engine + Compose v2"}
  Para os serviços do back-end e para os containers do runner. O runner-worker usa o Docker do **host** pelo socket `/var/run/docker.sock`.
  :::

  :::card{icon="i-simple-icons-nodedotjs" title="Node.js 22 + pnpm"}
  Para o painel e a documentação. O `packageManager` dos projetos Nuxt pede pnpm 12.
  :::

  :::card{icon="i-simple-icons-git" title="git"}
  Para clonar os projetos. O runner tem o próprio git dentro da imagem.
  :::

  :::card{icon="i-lucide-cpu" title="Recursos da máquina"}
  Cada runner usa até **2 CPUs e 4 GB** de RAM, e o padrão é rodar **2 ao mesmo tempo**. Reserve ao menos 8 GB livres além do resto da stack.
  :::
::

Também são necessários, para uma investigação real:

- **Credencial do Claude**: uma chave da API da Anthropic ou um token OAuth gerado com `claude setup-token`.
- **Repositório da aplicação alvo** no Bitbucket ou no GitHub, com um token de acesso.
- Opcionais: workspace do **Slack** (bot token), projeto no **Jira** (e-mail + API token) e uma integração no **Sentry**.

::tip
Dá para subir tudo e testar o fluxo inteiro **sem nenhuma dessas credenciais**. Veja [Testar sem gastar créditos](/ambiente-e-setup/testar-sem-creditos).
::

### Grupo do socket do Docker

O serviço `runner-worker` precisa poder usar o Docker do host. Descubra o grupo dono do socket e coloque o número em `DOCKER_GID` no `.env` do back-end:

```bash
stat -c %g /var/run/docker.sock
```

Todos os serviços Laravel (`app`, `queue`, `runner-worker`, `reverb`, `scheduler`) usam a **mesma imagem** (`Dockerfile` na raiz do back-end, PHP 8.5-FPM com Node 22, Chromium e `docker-cli`) e montam o código em `/var/www`. Uma mudança no código vale para todos depois de reiniciar o processo.

### `app` · `firewatch-app`

PHP-FPM da API. Não expõe porta: quem recebe as requisições é o nginx. É nele que você roda os comandos `artisan` e `composer`:

```bash
docker compose exec app php artisan migrate
```

### `nginx` · `firewatch-nginx`

`nginx:alpine` na porta **8000** do host, com a configuração de `docker/nginx/laravel.conf` (raiz em `public/`, PHP repassado para `app:9000`). É a URL da API: `http://localhost:8000`.

### `db` · `firewatch-db`

`mysql:8.3`. Os dados ficam em `./.docker/mysql/dbdata` (persistem entre `down`/`up`). Exposto no host na porta **3388**, para clientes como DBeaver. Usuário, senha e banco vêm de `DB_USERNAME`, `DB_PASSWORD` e `DB_DATABASE`.

### `redis` · `firewatch-redis`

`redis:latest`, sem porta no host. Guarda filas, cache, sessões e os locks de deduplicação, slots de runner e alertas de budget.

### `queue` · `firewatch-queue`

`php artisan queue:listen --timeout=360` na fila padrão. Roda as entregas (`DeliverIncidentOutcome`: PR, Slack, Jira) e os alertas de budget. O `--timeout` fica acima dos 300 s da entrega, senão o listener mataria o job no meio ([Filas e Horizon](/filas-agendamentos-e-comandos)).

::note
`queue:listen` recarrega o código a cada job, então não precisa reiniciar o serviço ao editar o código. Em produção, troque por `queue:work` ou pelo Horizon.
::

### `runner-worker` · `firewatch-runner-worker`

Worker das investigações (`InvestigateIncident`). Sobe **um listener por vaga** (`FIREWATCH_RUNNER_MAX_CONCURRENT`, padrão 2) na conexão e fila `investigations`, com `--timeout=0`, porque uma execução pode durar até uma hora.

É o **único serviço com acesso ao socket do Docker** (volume `/var/run/docker.sock` e `group_add: DOCKER_GID`). Depende do `runner-egress`, porque os runners só saem por ele.

### `reverb` · `firewatch-reverb`

`php artisan reverb:start` na porta **8080**. O painel conecta aqui pelo navegador; o Laravel publica aqui pela rede interna (`REVERB_HOST=reverb`).

### `scheduler` · `firewatch-scheduler`

`php artisan schedule:work`. A cada 5 minutos roda `firewatch:fail-stale-incidents`; às 03:30 limpa a trilha de auditoria antiga.

### `phpmyadmin` · `firewatch-myadmin`

Interface web do MySQL em `http://localhost:6060`. Só para desenvolvimento.

### `runner` (perfil `runner`)

Não sobe com `docker compose up`. Existe só para construir a imagem `firewatch-runner:latest` a partir de `docker/runner`. Veja [Imagens do runner](/ambiente-e-setup/imagens-do-runner).

### `runner-egress` · `firewatch-runner-egress`

Proxy Squid de saída dos runners. Está nas duas redes (`public_network` e `runner_network`) e monta as allowlists de `docker/runner/egress/` como somente leitura. Porta 3128 para clone e instalação; 3129 para o Claude Code e os testes.

### Redes

| Rede | Tipo | Quem está nela |
|---|---|---|
| `public_network` | bridge | Todos os serviços do compose |
| `firewatch-runner-net` | bridge **internal** (sem saída para a internet) | `runner-egress` e os containers `firewatch-run-*` |

## Subindo tudo

```bash
cd firewatch-back
docker compose up -d
docker compose --profile runner build runner
```

```bash
cd firewatch-front
pnpm install
pnpm dev
```

| Endereço | O quê |
|---|---|
| `http://localhost:5000` | Painel |
| `http://localhost:8000/api/health-check` | API (deve responder `API is running`) |
| `http://localhost:8000/horizon` | Painel do Horizon (as métricas só aparecem para jobs processados por `php artisan horizon`; com `queue:listen` ele fica vazio) |
| `ws://localhost:8080` | Reverb |
| `http://localhost:6060` | phpMyAdmin |

A configuração do `.env` e o primeiro usuário estão nas próximas páginas: [Variáveis de ambiente](/ambiente-e-setup/variaveis-de-ambiente) e [Primeiro acesso](/ambiente-e-setup/primeiro-acesso).
