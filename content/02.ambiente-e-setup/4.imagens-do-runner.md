Cada **aplicação** aponta para uma imagem de runner que tem os runtimes do projeto dela (campo **imagem do runner**; vazio = `firewatch-runner:latest`). Todas as imagens partem da mesma base e respeitam o mesmo **contrato** (variáveis de ambiente, eventos NDJSON e `report.json`).

| Imagem | Conteúdo | Tamanho aproximado |
|---|---|---|
| `firewatch-runner:latest` | Base: PHP 8.5, Node 22, git, Claude Code | 1,7 GB |
| `firewatch-runner:python` | Base + Python 3 com virtualenv e pytest | 1,9 GB |
| `firewatch-runner-egress:latest` | Proxy Squid (não é runner, mas também é construída aqui) | 220 MB |

## Imagem base

Duas formas equivalentes, a partir de `firewatch-back`:

::code-group
```bash [compose]
docker compose --profile runner build runner
```

```bash [docker build]
docker build -t firewatch-runner:latest docker/runner
```
::

O `Dockerfile` (em `docker/runner/`) faz, em ordem:

1. Parte de `php:<PHP_VERSION>-cli-bookworm` e copia os binários do Node da imagem oficial `node:<NODE_VERSION>-bookworm-slim`.
2. Instala git, curl, jq, ripgrep, tini e as extensões PHP (com `install-php-extensions`), mais o Composer 2.
3. Habilita npm, pnpm e Yarn 1 (corepack), já baixados no build, para o runner não depender de download na hora.
4. Instala o Claude Code CLI (`@anthropic-ai/claude-code`).
5. Cria o usuário sem privilégios `runner` (o Claude Code recusa rodar com permissões amplas como root) e as pastas `/workspace`, `/runner/input` e `/runner/output`.
6. Copia o `entrypoint.sh` como `firewatch-run` e o `tool-guard.sh` como `firewatch-tool-guard`, e define o entrypoint `tini -- firewatch-run`.

::note
O proxy de saída é construído junto com o `docker compose up -d` (serviço `runner-egress`). Para reconstruir só ele: `docker compose build runner-egress`.
::

## Variar a stack PHP/Node · build args

Para mudar versões ou extensões sem trocar de linguagem:

| Build arg | Padrão | Exemplo |
|---|---|---|
| `PHP_VERSION` | `8.5` | `8.4` (qualquer tag `php:<v>-cli-bookworm`) |
| `NODE_VERSION` | `22` | `20` (qualquer tag `node:<v>-bookworm-slim`) |
| `PHP_EXTENSIONS` | `bcmath exif gd intl pcntl pdo_mysql pdo_pgsql redis sockets zip` | `"bcmath intl pdo_mysql zip mongodb"` |
| `EXTRA_APT_PACKAGES` | vazio | `"sqlite3 imagemagick"` |
| `CLAUDE_CODE_VERSION` | `latest` | `2.1.322` |

```bash
docker build -t firewatch-runner:php8.4-node20 \
  --build-arg PHP_VERSION=8.4 --build-arg NODE_VERSION=20 \
  --build-arg PHP_EXTENSIONS="bcmath intl pdo_mysql pdo_pgsql zip" \
  --build-arg EXTRA_APT_PACKAGES="sqlite3" \
  docker/runner
```

::tip
Fixe `CLAUDE_CODE_VERSION` para builds reprodutíveis. Com `latest`, cada rebuild pode trazer uma versão diferente do Claude Code.
::

## Outra linguagem · imagem por stack

Para linguagens que a base não tem, crie uma imagem que **estende** a base. Ela herda o `firewatch-run`, o usuário `runner`, o Claude Code e o contrato. O exemplo pronto é `docker/runner/stacks/python`:

```bash
docker build -t firewatch-runner:latest docker/runner
docker build -t firewatch-runner:python docker/runner/stacks/python
```

A base precisa existir antes, porque a stack faz `FROM firewatch-runner:latest`. A imagem Python instala `python3`, `venv`, `pip` e `build-essential`, cria um virtualenv em `/opt/venv` (no `PATH`, com pytest) e volta para o usuário `runner`.

Para uma nova stack (Go, Ruby, Java…), copie `stacks/python` e mantenha estas regras:

1. `ARG BASE_IMAGE=firewatch-runner:latest` e `FROM ${BASE_IMAGE}`.
2. `USER root` para instalar e **`USER runner` no final**.
3. `LABEL br.com.firewatch.runner.stack="<nome>"`.
4. Nenhum `ENTRYPOINT` ou `CMD` próprio: o da base é o contrato.

```dockerfile [stacks/go/Dockerfile]
ARG BASE_IMAGE=firewatch-runner:latest
FROM ${BASE_IMAGE}

LABEL br.com.firewatch.runner.stack="go"

USER root
RUN apt-get update \
    && apt-get install -y --no-install-recommends golang \
    && apt-get clean && rm -rf /var/lib/apt/lists/*

USER runner
```

Se a detecção automática não cobrir a stack, configure na aplicação o **comando de instalação** e o **comando de testes** explícitos (ex.: `go mod download` e `go test ./...`).

## Convenção de tags

| Tag | Conteúdo |
|---|---|
| `firewatch-runner:latest` | Base: PHP 8.5, Node 22 |
| `firewatch-runner:php<versão>-node<versão>` | Variação por build args |
| `firewatch-runner:<stack>` | Imagem por stack (`python`, …) |

## Detecção automática de instalação e testes

Com **comando de instalação** e **comando de testes** em `auto` (o padrão), o runner olha os arquivos do repositório:

| Arquivo no repositório | Instalação | Testes |
|---|---|---|
| `composer.json` | `composer install` (+ `.env` e `key:generate` se tiver `artisan`) | `php artisan test`, ou `composer test` |
| `pnpm-lock.yaml` / `yarn.lock` / `package-lock.json` / `package.json` | `pnpm` / `yarn` / `npm ci` / `npm install` | `npm test` (se houver `scripts.test`) |
| `requirements*.txt` | `pip install -r …` | `python3 -m pytest` |
| `pyproject.toml` / `setup.py` | `pip install -e '.[test,dev]'` | `python3 -m pytest` |

Antes de instalar, o runner confere se a imagem tem os runtimes que o projeto pede. Se não tiver (por exemplo, um projeto Python na imagem base), falha logo com código 4 e a mensagem "A imagem do runner não tem o runtime exigido pelo projeto". Uma imagem errada na aplicação aparece como erro claro, kind `install`.

Os valores `none` pulam a etapa; qualquer outro texto é usado como comando.

## Conferir uma imagem

Toda imagem tem o label do contrato (`1` hoje) e o da stack. O Firewatch confere o do contrato antes de cada investigação e só usa imagens que já estão no host: ele **nunca** baixa uma imagem. Construa ou baixe a imagem no servidor antes de apontá-la numa aplicação ([A imagem](/investigacao/docker-runner#a-imagem)).

```bash
docker image inspect -f '{{index .Config.Labels "br.com.firewatch.runner.contract"}} {{index .Config.Labels "br.com.firewatch.runner.stack"}}' firewatch-runner:python
```

Para entrar numa imagem e depurar:

```bash
docker run --rm -it --entrypoint bash firewatch-runner:latest
```
