Cada investigação real chama o Claude e custa dinheiro (a execução de referência do incidente-001 custou cerca de **US$ 0,21**). Para desenvolver e ensaiar, o FireWatch tem caminhos que testam cada parte **sem nenhum custo de IA**.

| O que você quer testar | Use | Container? | Claude? | Integrações? |
|---|---|---|---|---|
| Painel, timeline ao vivo, Reverb | [`firewatch:replay-run`](#firewatchreplay-run) | Não | Não | Não |
| Pipeline Laravel + runner (clone e instalação) | [`FIREWATCH_RUNNER_DRY_RUN=1`](#dry-run-pelo-laravel) | Sim | Não | Não |
| Runner sozinho, no terminal | [`run-local.sh`](#run-localsh) com `DRY_RUN=1` | Sim | Não | Não |
| Runner: todos os desfechos, rede, timeouts, fluxo obrigatório | [`run-scenarios.sh` + fake-claude](#fake-claude-e-cenários) | Sim | Falso | Não |
| Guarda de ferramentas por agente | [`run-guard-tests.sh`](#guarda-de-ferramentas) | Sim | Real, contra API falsa | Não |
| Regras do back-end | [`php artisan test`](#testes-do-back-end) | Não | Não | Falsas |

::warning
O botão **Simular incidente** do painel **não** é gratuito: ele cria um incidente real e, se o trigger acionar, os agentes rodam e chamam o Claude. Use `DRY_RUN` ou o `replay-run` quando só quiser ver a tela funcionando.
::

## `firewatch:replay-run`

Reproduz uma execução **gravada** dos agentes pela mesma engrenagem da execução real (`RunnerStreamMonitor` → `AgentEvent` → Reverb), sem container, sem IA e sem integrações. É o jeito de testar e ensaiar a tela do incidente ao vivo.

```bash
docker compose exec app php artisan firewatch:replay-run
```

Por padrão ele:

1. Lê `docker/runner/examples/incident-001/replay.ndjson` (78 linhas, montado a partir do caso real do incidente-001).
2. Cria um incidente novo na primeira aplicação ativa, com os dados da primeira linha do arquivo (`{"type":"replay","incident":{…}}`).
3. Mostra o link do incidente no painel. Abra e acompanhe.
4. Envia um evento a cada 600 ms. O status avança de **Investigando** para **Corrigindo** e **Testando**, como numa execução real.
5. Fecha a execução com o relatório gravado. **Não abre PR, não chama Slack nem Jira.**

| Opção | O que faz |
|---|---|
| `stream` (argumento) | Outro arquivo NDJSON com a saída de um runner (ex.: o `stream.ndjson` de uma execução do `run-local.sh`). |
| `--incident=<id>` | Reexecuta num incidente existente, que precisa estar **Recebido** ou **Falhou**. |
| `--application=<id ou identificador>` | Aplicação do incidente criado. |
| `--delay=<ms>` | Pausa entre os eventos (padrão `600`; `0` = o mais rápido possível). |
| `--pr-url=<url>` | Marca o incidente como **PR aberto** com esse link no final. Nenhum PR é criado. |
| `--force` | Permite rodar em produção (bloqueado por padrão). |

```bash
docker compose exec app php artisan firewatch:replay-run --delay=300 --pr-url=https://bitbucket.org/exemplo/repo/pull-requests/1
```

::note
Os incidentes do ensaio são registros reais no banco e entram nas métricas. Apague-os depois do ensaio.
::

## Dry run pelo Laravel

Com `FIREWATCH_RUNNER_DRY_RUN=1` no `.env` do back-end, o caminho inteiro roda de verdade (webhook, trigger, fila, slot, container, clone e instalação de dependências), mas o runner **para antes de chamar o Claude**.

```bash [.env]
FIREWATCH_RUNNER_DRY_RUN=1
```

```bash
docker compose restart runner-worker
```

O incidente termina como **Falhou** com o kind `dry_run` ("Execução de teste") e nenhuma integração de saída é acionada. Serve para validar a configuração de uma aplicação nova (token do repositório, slug, branch base, imagem do runner e comando de instalação) antes de gastar créditos. Nesse modo, nem a credencial do Claude é exigida.

## `run-local.sh`

Roda o runner **direto no terminal**, sem Laravel, contra uma pasta de incidente. Usa o `launch.sh` por baixo, com os mesmos limites, isolamento e rede restrita do Laravel.

Prepare o arquivo de variáveis uma vez:

```bash
cp docker/runner/runner.env.example docker/runner/runner.env
```

Preencha em `runner.env`: `REPO_URL` (HTTPS, sem credencial na URL), `REPO_USERNAME` (`x-token-auth` para tokens de acesso do Bitbucket), `REPO_TOKEN` e `BASE_BRANCH`. O arquivo está no `.gitignore`, e o `REPO_TOKEN` é entregue ao container pela entrada padrão, nunca como variável.

```bash
docker/runner/run-local.sh docker/runner/examples/incident-001 -e DRY_RUN=1
```

::warning
Sem `-e DRY_RUN=1` e com uma credencial do Claude no `runner.env`, o `run-local.sh` faz uma **investigação real** e gasta créditos.
::

Cada execução fica em `docker/runner/runs/<data>-<incidente>/`:

| Arquivo | Conteúdo |
|---|---|
| `workspace/repo/` | Repositório clonado, com as alterações dos agentes |
| `output/report.json` | Relatório final |
| `stream.ndjson` | Eventos do runner e do Claude Code (pode virar entrada do `replay-run`) |
| `stderr.log` | Logs de clone, instalação e testes |

O terminal mostra só as etapas (`[clone] completed: …`) e, no fim, o código de saída. Outras variáveis úteis: `RUNNER_IMAGE` (ex.: `firewatch-runner:python`), `RUNNER_NETWORK`, `RUNNER_CPUS`, `RUNNER_MEMORY` e `WORK_BRANCH`.

## fake-claude e cenários

O `docker/runner/test/fake-claude` é um **Claude Code falso**: um script que emite um `stream-json` no mesmo formato do real e simula o trabalho do agente conforme `FAKE_SCENARIO`. O runner usa ele no lugar do binário real quando recebe `CLAUDE_BIN=/runner/test/fake-claude`.

O `run-scenarios.sh` roda o runner inteiro com o fake-claude em vários cenários e confere código de saída, status do relatório, o evento `report` no stdout e a chegada dos subagentes ao Claude:

```bash
docker/runner/test/run-scenarios.sh
```

```bash
docker/runner/test/run-scenarios.sh fix no_test timeout_claude
```

| Cenário | Simula | Esperado |
|---|---|---|
| `fix` | Correção real do incidente-001 + relatório `fixed` | exit 0, `fixed` |
| `break_tests` | Correção + teste que sempre falha | exit 6 |
| `agent_failed` | Agente desiste | exit 7 |
| `no_report` | Altera código, mas não escreve relatório | exit 7 |
| `api_error` | Chave inválida | exit 5 |
| `net_probe` | Agente tenta sair para Packagist e example.com | exit 7; só a Anthropic responde |
| `real_api_401` | **Claude Code real** com chave inválida, pela rede restrita | exit 5, custo zero |
| `timeout_claude` / `timeout_tests` / `timeout_total` | Travamentos | exit 124 |
| `agents_invalid` / `policy_invalid` | `agents.json` ou `policy.json` inválidos | exit 2 |
| `no_test` | Corrige sem escrever teste | exit 8 |
| `test_passes_before` | Teste que passa mesmo sem a correção | exit 8 |
| `unexpected_error` | Erro não previsto depois do Claude Code | exit 1, com relatório |

O script substitui a credencial por `fake-key-nao-usada`, então **nunca gasta créditos**, mesmo com uma chave real no `runner.env`. Os cenários `fix`, `break_tests`, `no_test` e `test_passes_before` aplicam o patch do incidente-001, então o `runner.env` precisa apontar para o **repositório cobaia** (`flowstock-back`). As saídas ficam em `docker/runner/runs/test-<data>/<cenário>/`, e o script sai com erro se algum cenário falhar.

## Guarda de ferramentas

```bash
docker/runner/test/run-guard-tests.sh
```

Testa o hook que limita comandos e arquivos por agente (`tool-guard.sh`), em duas partes:

1. **Casos unitários**: alimenta o guarda com o JSON do hook e confere permitir ou recusar para cada agente (por exemplo, `git push` sempre recusado).
2. **Integração**: sobe uma **API da Anthropic falsa** no host (`fake-anthropic-api.py`, porta 18090) e roda o **Claude Code real** contra ela. A API manda o Chefe delegar ao Detetive e o Detetive tentar escrever; o teste confere que a escrita foi recusada e a leitura passou.

Precisa de `python3` no host. Não precisa de nenhuma credencial.

## Testes do back-end

```bash
docker compose exec app php artisan test
```

Rodam com SQLite em memória, fila síncrona e broadcast desligado (`phpunit.xml`). O Docker e as APIs externas são simulados com `Process::fake()` e `Http::fake()`, então nenhum container sobe e nenhuma API é chamada.
