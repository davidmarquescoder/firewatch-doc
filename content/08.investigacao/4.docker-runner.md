`App\Services\Runner\DockerRunner` sobe **um container `firewatch-runner` por execução** e entrega o stdout dele, linha a linha, ao job. Ele reproduz os mesmos limites e o mesmo isolamento do `docker/runner/launch.sh`, usado para rodar o runner na mão. O que acontece **dentro** do container (clone, instalação, Claude Code, verificação) está em `docker/runner/README.md` e `docker/runner/EVENTS.md`. As imagens estão em [Imagens do runner](/ambiente-e-setup/imagens-do-runner).

## O ciclo do container

O worker roda num container que fala com o Docker do **host** pelo socket. Um bind mount apontaria para caminhos do host, e não do worker, então os arquivos de entrada são **copiados**:

::mermaid
---
code: |
  sequenceDiagram
    participant J as InvestigateIncident
    participant D as DockerRunner
    participant H as Docker do host
    participant C as Container firewatch-run-<id>
    J->>D: run(run, input, branch, onLine)
    D->>H: docker image inspect (existe no host? label do contrato?)
    D->>D: input->writeTo(storage/app/private/runner/<id>)
    D->>H: docker create --pull never (limites, rede, --env NOME)
    D->>H: docker cp input/. → /runner/input
    D->>H: docker start --attach --interactive
    D-->>C: token do repositório pelo stdin
    C-->>D: stdout NDJSON, linha a linha
    D-->>J: onLine(linha)
    C-->>D: sai com o código de saída
    D->>H: docker rm --force (sempre)
    D->>D: apaga o diretório de entrada (sempre)
    D-->>J: RunnerResult
---
::

| Passo | Comando | Timeout | Se falhar |
|---|---|---|---|
| Conferir a imagem | `docker image inspect --format '{{json .Config.Labels}}' <imagem>` | 60 s | `RunnerLaunchException`: imagem ausente no host, sem o label do contrato ou com outro contrato (ver abaixo). Nada foi criado, então não há limpeza |
| Gravar a entrada | `RunnerInput::writeTo()` em `storage/app/private/runner/<run>` | | Exception → `failed()` do job |
| Criar | `docker create …` | 120 s | `RunnerLaunchException` "Não foi possível criar o container do runner: …" |
| Copiar | `docker cp <dir>/input/. <container>:/runner/input` | 120 s | `RunnerLaunchException` "Não foi possível copiar o incidente e os agentes para o runner: …" |
| Rodar | `docker start --attach [--interactive]` | `hardTimeout()` | Tempo esgotado: `docker kill` e `RunnerResult` com `timedOut` |
| Limpar | `docker rm --force` e apagar o diretório | 60 s | Roda num `finally`, aconteça o que acontecer |

O nome do container é `firewatch-run-<id do AgentRun>`. Ele recebe os labels `br.com.firewatch.runner=1` e `br.com.firewatch.application=<id>`, úteis para achar containers perdidos:

```bash
docker ps -a --filter label=br.com.firewatch.runner=1
```

## Limites e isolamento

`createArguments()` monta o `docker create`:

| Argumento | Padrão | Variável | Para quê |
|---|---|---|---|
| `--cpus` | `2` | `FIREWATCH_RUNNER_CPUS` | Limite de CPU |
| `--memory` e `--memory-swap` | `4g` | `FIREWATCH_RUNNER_MEMORY` | Limite de RAM. Swap igual à memória significa **sem swap extra**. Estourar mata o container (código 137) |
| `--pids-limit` | `1024` | `FIREWATCH_RUNNER_PIDS` | Impede um fork bomb |
| `--ulimit nofile=4096:8192` | fixo | | Limite de arquivos abertos |
| `--cap-drop ALL` | fixo | | Nenhuma capability do Linux |
| `--security-opt no-new-privileges` | fixo | | Nada dentro do container ganha privilégios (setuid) |
| `--interactive` | fixo | | Mantém o stdin aberto para o token do repositório |
| `--pull never` | fixo | | Nunca baixa a imagem de um registry |
| Imagem | `firewatch-runner:latest` | `runner_image` da aplicação | A imagem com os runtimes da aplicação alvo |

### A imagem

A imagem recebe o token de clone e a credencial do Claude, então o `DockerRunner` só sobe uma imagem que o administrador do host colocou lá de propósito. `verifyImage()` roda antes de qualquer outro passo:

| Situação | Motivo do incidente (`failed`, kind `configuration`) |
|---|---|
| A imagem não existe no host | "A imagem do runner "…" não existe neste servidor. O Firewatch não baixa imagens: construa ou baixe a imagem no host antes de usá-la." |
| Sem o label `br.com.firewatch.runner.contract` | "A imagem "…" não é uma imagem de runner do Firewatch (sem o label br.com.firewatch.runner.contract)." |
| Contrato diferente do esperado | "A imagem "…" segue o contrato 2 do runner, e o Firewatch espera o contrato 1. Reconstrua a imagem a partir do firewatch-runner atual." |

O contrato esperado vem de `FIREWATCH_RUNNER_IMAGE_CONTRACT` (padrão `1`). O `--pull never` no `docker create` fecha a outra porta: mesmo que a imagem suma entre a conferência e a criação, o Docker não a busca num registry. Quem edita uma aplicação só escolhe entre as imagens que já estão no host ([Imagens do runner](/ambiente-e-setup/imagens-do-runner)).

### Rede

| `FIREWATCH_RUNNER_NETWORK` | Argumento | Uso |
|---|---|---|
| `restricted` (padrão) | `--network firewatch-runner-net` | Rede interna sem saída direta. Tudo passa pelo proxy de saída `firewatch-runner-egress` |
| `none` | `--network none` | Sem rede nenhuma (só serve se o repositório e as dependências já estiverem na imagem) |
| `open` | nenhum | Rede livre. **Só para depuração** |

Outro valor gera `RunnerLaunchException` "Rede do runner inválida". Na rede `restricted`, o container recebe dois proxies, um para cada fase:

| Variável no container | Padrão | Fase |
|---|---|---|
| `FIREWATCH_SETUP_PROXY` | `http://firewatch-runner-egress:3128` | Clone e instalação de dependências |
| `FIREWATCH_AGENT_PROXY` | `http://firewatch-runner-egress:3129` | Claude Code: só a API da Anthropic fica acessível |

## Variáveis do container

`environment()` monta as variáveis que o runner lê (veja `docker/runner/runner.env.example`):

| Variável | Valor |
|---|---|
| `REPO_URL` | URL de clone do tipo do conector (`https://bitbucket.org/%s.git` ou `https://github.com/%s.git`) com o `repository_slug` |
| `REPO_USERNAME` | `x-token-auth` (Bitbucket) ou `x-access-token` (GitHub), de `firewatch.runner.repository.usernames` |
| `REPO_TOKEN_STDIN` | `1` quando há token, que chega pelo stdin |
| `BASE_BRANCH`, `WORK_BRANCH` | A branch base da aplicação e a [branch de trabalho](/investigacao) |
| `INSTALL_COMMAND`, `TEST_COMMAND` | Os comandos da aplicação (`auto` deixa o runner detectar) |
| `CLAUDE_MODEL` | `FIREWATCH_CLAUDE_MODEL` (vazio = padrão do Claude Code) |
| `CLAUDE_MAX_BUDGET_USD` | O `budget_usd` do run: o teto por execução, reduzido ao que sobra do mês |
| `INSTALL_TIMEOUT`, `CLAUDE_TIMEOUT`, `TEST_TIMEOUT`, `RUNNER_MAX_DURATION` | Os [timeouts](/investigacao/timeouts-e-reexecucao) |
| `DRY_RUN` | `1` com `FIREWATCH_RUNNER_DRY_RUN`: clona e instala, mas não chama o Claude |
| `ANTHROPIC_API_KEY` **ou** `CLAUDE_CODE_OAUTH_TOKEN` | A primeira credencial configurada. Fora do dry run, sem nenhuma das duas, a execução para antes do Docker |

Antes de qualquer comando do Docker, `environment()` recusa com `RunnerLaunchException` (tipo `configuration`):

- "A aplicação não tem repositório configurado (conector e repositório)."
- "O conector "X" (Slack) não é um conector de repositório."
- "Nenhuma credencial do Claude configurada (FIREWATCH_ANTHROPIC_API_KEY ou FIREWATCH_CLAUDE_CODE_OAUTH_TOKEN)."

## Segredos

::warning
**Nenhum segredo aparece na linha de comando.** O `docker create` recebe só os nomes (`--env ANTHROPIC_API_KEY`, sem valor). Os valores vão no ambiente do processo do Docker CLI, que os copia para o container. Assim, eles não aparecem no `ps` do host.
::

O **token do repositório** é tratado de forma ainda mais restrita: ele **não** vira variável do container, porque o ambiente inicial fica legível em `/proc/1/environ` e no `docker inspect`. Ele é escrito no **stdin** do `docker start --interactive`. O runner o lê, clona o repositório e o descarta **antes** de instalar dependências ou chamar os agentes.

| Token usado no clone | Quando |
|---|---|
| `runner_token` do conector | Quando configurado: um token **só de leitura**, o escopo mínimo |
| `access_token` do conector | Caso contrário: o mesmo token de escrita que o Laravel usa para criar a branch e o PR |

O runner nunca recebe credenciais de produção nem segredos de outros conectores. `InvestigateIncidentJobTest` confere que o ambiente do container não leva nenhum segredo do FireWatch ou de outro conector.

## Lendo o stdout

`attach()` inicia o processo e trata cada pedaço de saída:

- **stdout**: acumula num buffer e chama `onLine()` a cada `\n`. Uma última linha sem `\n` é entregue no fim.
- **stderr**: guarda só as **últimas 40 linhas** (`STDERR_TAIL_LINES`), com logs do git, da instalação e dos testes, para diagnóstico.

O processo tem timeout de `hardTimeout()` = `RUNNER_MAX_DURATION` + `FIREWATCH_RUNNER_KILL_GRACE` (3600 + 120 = **3720 s**). O runner se encerra sozinho em `RUNNER_MAX_DURATION` e ainda escreve o relatório. A folga só existe para isso. Se o container passar do limite, o Laravel faz `docker kill` e devolve um `RunnerResult` com `timedOut = true`.

## RunnerResult

```php [app/Services/Runner/RunnerResult.php]
final readonly class RunnerResult
{
    public function __construct(
        public ?int $exitCode,     // null quando o FireWatch matou o container
        public bool $timedOut,     // passou do hardTimeout()
        public string $stderrTail, // últimas 40 linhas do stderr
    ) {}

    public function lastErrorLine(): ?string; // última linha não vazia do stderr
}
```

O job só usa o `RunnerResult` quando o container terminou **sem** o evento `report`: o `timedOut` e o `exitCode` viram um relatório de falha montado pelo FireWatch, e o `lastErrorLine()` (mascarado, até 300 caracteres) entra no motivo. Veja [Resultado e falhas](/investigacao/resultado-e-falhas).

## Testes

Em `InvestigateIncidentJobTest`: o container é criado com limites, isolamento e o token só no stdin; os modos de rede; a preferência pelo `runner_token`; nenhum segredo no ambiente; a imagem conferida no host antes do container; imagem ausente, sem label, com outros labels ou com outro contrato nunca chega ao `docker create`; aplicação sem repositório e sem credencial do Claude falham antes do Docker; uma falha do Docker é reportada e o container é removido; container sem relatório; timeout; e dry run sem credencial do Claude.
