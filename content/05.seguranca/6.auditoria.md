A trilha de auditoria responde três perguntas: **quem configurou o quê**, **quem disparou cada ação manual** e **o que os agentes fizeram em cada execução**. Ela usa o **`spatie/laravel-activitylog`** (^5.1), grava na tabela `activity_log` e passa tudo pelo [mascaramento](/seguranca/mascaramento) antes de salvar.

::mermaid
---
code: |
  flowchart LR
    M[Modelos com LogsActivity<br/>created / updated / deleted] --> A
    E[Eventos manuais no booted<br/>password_changed, credentials_updated] --> A
    L[AuditLogger<br/>action / agentRun] --> A
    A[MaskedLogActivityAction<br/>SensitiveDataMasker] --> DB[(activity_log)]
    DB --> API[GET /api/v1/audit-log<br/>AuditLogResource]
    API --> P[Painel: /audit]
    S[Scheduler 03:30<br/>activitylog:clean] -. apaga > 365 dias .-> DB
caption: Toda gravação passa pela ação mascarada, configurada em config/activitylog.php.
---
::

## As quatro seções (`AuditLogEnum`)

Cada registro tem um `log_name`, que vem de `App\Enums\Audit\AuditLogEnum`:

| Valor | Rótulo | O que entra |
|---|---|---|
| `configuration` | Configuração | Mudanças em conectores, aplicações, perfis de agentes, usuários, organizações e custos |
| `incident` | Incidentes | Ciclo de vida de incidentes e execuções (mudanças de status) |
| `action` | Ações manuais | Testar conexão, simular, reexecutar, pedido pelo Slack, alerta de custo |
| `agent` | Agentes | Um resumo por execução: ações por agente, tentativas bloqueadas e arquivos |

A API só devolve registros dessas quatro seções. Qualquer outro `log_name` (como o `default` do pacote) fica de fora.

## Mudanças em modelos

Os modelos usam a trait `LogsActivity` e definem o que registrar em `getActivitylogOptions()`. O pacote grava `created`, `updated` e `deleted` com os valores antigos e novos em `attribute_changes`.

| Modelo | Seção | Campos registrados |
|---|---|---|
| `Connector` | `configuration` | Fillable, **exceto** `credentials` e `last_verified_at` |
| `Application` | `configuration` | Fillable |
| `AgentProfile` | `configuration` | Fillable (inclusive o prompt de sistema) |
| `AppSetting` | `configuration` | `key`, `value` (o teto de custo) |
| `User` | `configuration` | `name`, `email`, `active`, `must_change_password` |
| `Organization` | `configuration` | Fillable |
| `Incident` | `incident` | `status`, `status_reason`, `failure_kind`, `severity`, `pr_url`, `jira_key` |
| `AgentRun` | `incident` | `status`, `exit_code`, `failure_stage`, `failure_reason`, `cost_usd` |

Todos usam `logOnlyDirty()` (só o que mudou). Os de configuração também usam `dontLogEmptyChanges()`, para não gravar um `updated` vazio.

### Eventos com cuidado especial

Dois campos nunca podem aparecer com o valor, nem mascarado. Eles ficam fora do `logOnly` e geram um evento próprio no `booted()` do modelo:

| Evento | Modelo | Gravado |
|---|---|---|
| `password_changed` | `User` | "Senha alterada", sem nenhum valor |
| `credentials_updated` | `Connector` | Os **nomes** dos campos que mudaram (`changed_fields`), por exemplo "Credenciais alteradas: access_token" |
| `created` | `Connector` | Além do registro normal, `configured_fields` com os nomes das credenciais configuradas (`beforeActivityLogged()`) |

## O AuditLogger

`App\Services\Audit\AuditLogger` grava o que não é mudança de modelo.

### `action()`: ações manuais

```php
app(AuditLogger::class)->action(
    event: 'connector_tested',
    subject: $connector,
    description: 'Conexão testada com sucesso',
    properties: ['ok' => true, 'message' => '…'],
);
```

O **autor** (`causer`) é o usuário logado, quando há um. Sem usuário (webhook, fila, Slack), o registro é do **sistema**.

| Evento | Onde | Assunto |
|---|---|---|
| `connector_tested` | `ConnectorController::test()` | Conector; `ok` e mensagem |
| `incident_simulated` | `ApplicationController::simulateIncident()` | Incidente; aplicação e se foi criado ou deduplicado |
| `incident_retried` | `IncidentController::retry()` | Incidente |
| `slack_investigation_requested` | `SlackCommandController` | Incidente; id e nome do usuário do Slack, conector |
| `budget_alert` | Job `SendBudgetAlert` | Nenhum; limite, gasto, teto e mês |
| `role_changed` | `UserController::update()` | Usuário; papel antigo (`old`) e novo (`new`). Papéis ficam nas tabelas do `spatie/laravel-permission`, fora da auditoria do modelo |

### `agentRun()`: o que os agentes fizeram

Chamado pelo `AgentRun` quando a execução termina e o relatório é aplicado. Grava **um** registro por execução, no log `agent`, com o evento `agent_run_finished` e `causedByAnonymous()`: quem agiu foram os agentes, não quem estava logado (importante no replay e nos testes).

| Propriedade | Conteúdo |
|---|---|
| `actions` | Contagem por agente e tipo: `read_file`, `edit_file`, `run_command`, `test_result` |
| `actions_total` | Soma das ações |
| `denials` | Até 50 tentativas bloqueadas pelo guarda (agente, ferramenta, entrada, motivo) |
| `denials_total` | Total de bloqueios, sem o corte |
| `policy_enforced` | Se o guarda de permissões estava ativo |
| `files` | Até 100 arquivos alterados (caminho e status) |
| `tests`, `status`, `work_branch`, `incident_id` | Resultado da execução |

A descrição fica como "Agentes executaram 37 ação(ões), 2 bloqueada(s) pelo guarda". O passo a passo completo continua em `agent_events` (a timeline do incidente); a auditoria guarda o resumo que precisa sobreviver por um ano.

## Mascaramento antes de gravar

O `config/activitylog.php` troca a ação de gravação do pacote:

```php [config/activitylog.php]
'actions' => [
    'log_activity' => \App\Services\Audit\MaskedLogActivityAction::class,
    'clean_log'    => CleanActivityLogAction::class,
],
```

`MaskedLogActivityAction` estende a `LogActivityAction` e sobrescreve `transformChanges()`. Antes de salvar, passa pelo `SensitiveDataMasker`:

- `attribute_changes` e `properties` com `maskArray()`: valores em chaves sensíveis viram `[redacted]` e textos são mascarados;
- `description` com `maskString()`.

Isso vale para **todo** registro, inclusive os gravados com `activity()` direto. O `AuditLogResource` ainda mascara de novo o **nome do assunto** exibido (o título de um incidente pode ter um e-mail, por exemplo).

## A API

`GET /api/v1/audit-log` (`AuditLogController`) é **somente leitura**: não existe rota para editar ou apagar registros.

| Filtro | Valores |
|---|---|
| `log` | `configuration`, `incident`, `action`, `agent` |
| `subject_type` | `connector`, `application`, `agent_profile`, `user`, `organization`, `incident`, `agent_run`, `app_setting` |
| `subject_id` | UUID do item |
| `causer_id` | UUID do usuário |
| `causer=system` | Só registros sem usuário |
| `event` | `created`, `updated`, `credentials_updated`… |
| `search` | Texto na descrição |
| `from`, `to` | Período (`to` ≥ `from`) |
| `per_page` | 1 a 100, padrão 25 |

```json
{
  "id": 1842,
  "log": "configuration",
  "log_label": "Configuração",
  "event": "credentials_updated",
  "description": "Credenciais alteradas: access_token",
  "subject": { "type": "connector", "id": "9d3c…", "label": "Bitbucket da empresa", "deleted": false },
  "causer": { "id": "7a1f…", "name": "Ana Souza" },
  "changes": { "old": {}, "new": {} },
  "properties": { "changed_fields": ["access_token"] },
  "created_at": "2026-11-16T14:02:11-03:00"
}
```

- `causer: null` significa **sistema** (webhook, fila, agentes, Slack).
- Com `include_soft_deleted_subjects = true`, um item apagado continua com o nome na trilha e vem com `deleted: true`.

O painel mostra a trilha em **Auditoria** (`pages/audit/index.vue`, composable `useAuditLog()`).

## Retenção e limpeza diária

| Configuração | Valor |
|---|---|
| `activitylog.clean_after_days` | `365` |
| Agendamento | `activitylog:clean --force`, todo dia às **03:30**, `withoutOverlapping()` (`routes/console.php`) |
| Liga/desliga | `ACTIVITYLOG_ENABLED` (padrão `true`) |

O comando do pacote apaga os registros com mais de 365 dias. O `--force` é necessário porque o comando pede confirmação em produção. Como qualquer tarefa agendada, depende do serviço `scheduler` do `docker-compose` (`firewatch-scheduler`, que roda `php artisan schedule:work`) estar no ar.

Para rodar na hora ou com outra janela:

```bash
docker compose exec app php artisan activitylog:clean --days=90 --force
```
