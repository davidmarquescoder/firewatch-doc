Os três middlewares próprios ficam em `app/Http/Middleware` e são registrados como **aliases** em `bootstrap/app.php`:

```php [bootstrap/app.php]
$middleware->alias([
    'ensure-password-change' => EnsurePasswordChange::class,
    'ensure-user-active'     => EnsureUserIsActive::class,
    'verify-webhook'         => VerifyIncomingWebhook::class,
]);
```

| Alias | Onde é usado |
|---|---|
| `ensure-user-active` | Grupo `/api/v1/*` (exceto `/auth`) e `POST /api/broadcasting/auth` |
| `ensure-password-change` | Os mesmos |
| `verify-webhook` | `POST /api/webhooks/{connector}` e `POST /api/slack/commands/{connector}` |

## Ordem no painel

::mermaid
---
code: |
  flowchart LR
    R[Requisição /api/v1/*] --> S{auth:sanctum}
    S -- sem sessão --> E401[401]
    S --> A{ensure-user-active}
    A -- active = false --> E403a[403 conta desativada]
    A --> P{ensure-password-change}
    P -- must_change_password --> E403b[403 troque a senha]
    P --> C[Controller]
caption: A ordem importa. Um usuário desativado recebe "conta desativada" mesmo que também precise trocar a senha.
---
::

## EnsureUserIsActive

Bloqueia contas desativadas (`users.active = false`).

| Situação | Status | `message` | `code` |
|---|---|---|---|
| Sem usuário na requisição | `401` | Usuário não autenticado. | |
| `active = false` | `403` | `auth.inactive` | `user_inactive` |
| Ativo | segue | | |

O login (por senha e pelo Google) já recusa contas desativadas. Este middleware cobre o resto: quem foi desativado **com a sessão aberta** perde o acesso na próxima chamada, e o Reverb recusa os canais. `GET /api/v1/auth` não passa por aqui, então a sessão antiga ainda lê os próprios dados até expirar ou sair.

## EnsurePasswordChange

Força a troca de senha quando `users.must_change_password = true` (padrão `false`).

| Situação | Status | `message` | `code` |
|---|---|---|---|
| `must_change_password = true` | `403` | `auth.password_change.required` | `password_change_required` |
| Caso contrário | segue | | |

A saída é `PUT /api/v1/auth/password`, que fica **fora** deste middleware (mas dentro de `auth:sanctum` e `ensure-user-active`, com limite de 6 chamadas por minuto):

```json
{
  "current_password": "senha-atual",
  "password": "nova-senha-forte",
  "password_confirmation": "nova-senha-forte"
}
```

| Regra | Erro |
|---|---|
| `current_password` precisa conferir com a senha atual | `422` em `current_password` |
| `password`: no mínimo 8 caracteres, confirmada e diferente da atual | `422` em `password` |

Com sucesso, a senha é gravada (hash), `must_change_password` volta para `false`, o token CSRF é renovado e a resposta traz `data.user` atualizado.

::note
O painel ainda não tem a tela de troca de senha. Quando tiver, basta reagir ao `403` com `code: password_change_required` levando o usuário para ela.
::

Quando a senha muda, o `User` registra o evento `password_changed` na auditoria, sem o valor (veja [Auditoria](/seguranca/auditoria)).

## VerifyIncomingWebhook

::tip
Os detalhes de cada verificador, os cabeçalhos e os motivos de recusa estão em [Verificação de assinatura](/entrada/verificacao). Aqui fica o resumo.
::

Protege as rotas que recebem chamadas de fora (Sentry, webhook genérico e o comando `/firewatch` do Slack). Essas rotas não têm sessão: quem prova a origem é a **assinatura ou o token** do conector.

```php [routes/api.php]
Route::post('/webhooks/{connector}', WebhookController::class)
    ->middleware(['verify-webhook', 'throttle:120,1,webhooks']);

Route::post('/slack/commands/{connector}', SlackCommandController::class)
    ->middleware(['verify-webhook', 'throttle:60,1,slack-commands']);
```

### Passo a passo

1. **Resolve o conector** pelo UUID da URL. Se não existir ou o tipo não recebe webhooks (`ConnectorTypeEnum::receivesWebhooks()`: Sentry, webhook genérico e Slack) → `404` "Webhook não encontrado.".
2. **Verifica a assinatura** com o verificador do tipo, escolhido pelo `WebhookVerifierFactory`. Falhou → `401` "Assinatura do webhook inválida." e um `Log::warning` com o motivo, o id do conector e o IP.
3. **Confere o status**: conector `inactive` → `403` "Conector desativado.". A assinatura é checada **antes**, para que um terceiro não descubra quais conectores existem e estão desligados.
4. Guarda o conector no atributo `webhook_connector` da requisição (e o método usado em `webhook_auth_method`) e segue para o controller, que não precisa buscar nada de novo.

As respostas são **vagas de propósito**: o motivo exato (cabeçalho ausente, timestamp fora da janela, assinatura diferente) só vai para o log, pelo `VerificationResult::$reason`, que nunca contém segredos.

### Verificadores

Todos implementam `WebhookVerifier`, comparam com `hash_equals()` (tempo constante) e **falham fechado**: sem segredo configurado, a requisição é recusada.

| Tipo | Classe | Credencial | Como valida | Anti-replay |
|---|---|---|---|---|
| `sentry` | `SentryWebhookVerifier` | `client_secret` | `Sentry-Hook-Signature` = HMAC-SHA256 hex do corpo bruto | Não (formato do Sentry) |
| `generic_webhook` | `GenericWebhookVerifier` | `secret` | Assinatura **ou** token (abaixo) | Sim, na assinatura: 300 s |
| `slack` | `SlackRequestVerifier` | `signing_secret` | `X-Slack-Signature` = `v0=` + HMAC-SHA256 de `v0:<timestamp>:<corpo>` | Sim: 300 s |

O webhook genérico aceita duas formas; se o cabeçalho de assinatura estiver presente, ele vence:

| Forma | Cabeçalhos | Quando usar |
|---|---|---|
| Assinatura (recomendada) | `X-Firewatch-Timestamp: <unix>` e `X-Firewatch-Signature: sha256=<HMAC de "<timestamp>.<corpo>">` | Sempre que a ferramenta conseguir assinar |
| Token | `Authorization: Bearer <secret>` ou `X-Firewatch-Token: <secret>` | Ferramentas que não assinam. Só com HTTPS |

```bash
# Exemplo de chamada assinada ao webhook genérico
BODY='{"title":"Erro de teste","application":"minha-app"}'
TS=$(date +%s)
SIG=$(printf '%s.%s' "$TS" "$BODY" | openssl dgst -sha256 -hmac "$SECRET" -hex | awk '{print $2}')

curl -X POST "https://firewatch.exemplo.com/api/webhooks/$CONNECTOR_ID" \
  -H "Content-Type: application/json" \
  -H "X-Firewatch-Timestamp: $TS" \
  -H "X-Firewatch-Signature: sha256=$SIG" \
  -d "$BODY"
```

O método estático `GenericWebhookVerifier::sign()` gera a mesma assinatura e é usado nos testes. O botão **Simular incidente** do painel não passa por aqui: ele chama uma rota autenticada (`/api/v1/application/{id}/simulate-incident`) e registra o evento direto.

::note
Um conector Slack sem `signing_secret` continua mandando notificações, mas **todo** comando `/firewatch` recebe `401`: o segredo é opcional no cadastro só porque o comando é opcional.
::
