As credenciais dos conectores (tokens do Bitbucket e do GitHub, segredo do Sentry, bot token do Slack, API token do Jira…) seguem uma regra do projeto que não se negocia: **ficam no banco, criptografadas; nunca em código, nunca em logs, nunca devolvidas pela API em texto puro.**

## Quais credenciais cada tipo tem

Definidas em `ConnectorTypeEnum::requiredCredentials()` e `optionalCredentials()`. `allowedCredentials()` junta as duas listas.

| Tipo | Obrigatórias | Opcionais | Usadas por |
|---|---|---|---|
| `sentry` | `client_secret` | | `SentryWebhookVerifier` (assinatura) |
| `generic_webhook` | `secret` | | `GenericWebhookVerifier` (assinatura ou token) |
| `bitbucket` | `access_token` | `runner_token` | `BitbucketRepositoryProvider` (branch, push, PR); runner (clone) |
| `github` | `access_token` | `runner_token` | `GitHubRepositoryProvider`; runner (clone) |
| `slack` | `bot_token` | `signing_secret` | `SlackNotifier`; `SlackRequestVerifier` (comando `/firewatch`) |
| `jira` | `email`, `api_token` | | `JiraIssueTracker` (Basic auth) |

Cada valor aceita até 4096 caracteres. O **Testar conexão** dos conectores de entrada recusa segredos com menos de 16 caracteres (`IncomingWebhookConnectionTester::MIN_SECRET_LENGTH`), e o painel tem um botão para gerar um segredo forte.

## Como são guardadas

```php [app/Models/Connector/Connector.php]
#[Hidden(['credentials'])]
class Connector extends Model
{
    protected function casts(): array
    {
        return [
            'credentials' => 'encrypted:array',
            // …
        ];
    }
}
```

| Camada | Proteção |
|---|---|
| **Banco** | `connectors.credentials` é `text` com o array inteiro criptografado (`encrypted:array`): AES-256-CBC com a `APP_KEY`, com MAC. Um dump do banco sem a `APP_KEY` não revela nada |
| **Serialização** | `#[Hidden]`: `toArray()`/`toJson()` do modelo nunca incluem o campo, mesmo que alguém devolva o modelo cru |
| **Leitura no código** | `$connector->credential('access_token')` lê **uma** chave, sem espalhar o array |
| **Auditoria** | Fora do `logOnly`; só nomes dos campos (veja abaixo) |
| **Logs** | O teste de conexão registra só a **classe** da exceção, porque a mensagem pode ecoar a requisição |

::warning
**A `APP_KEY` é a chave das credenciais.** Trocar ou perder a `APP_KEY` torna todas as credenciais salvas ilegíveis: os conectores passam a falhar e precisam ser recadastrados. Gere uma vez ([Primeiro acesso](/ambiente-e-setup/primeiro-acesso)) e guarde junto dos outros segredos de produção. Se precisar girar a chave, use `APP_PREVIOUS_KEYS` com a chave antiga, para o Laravel continuar lendo o que já foi gravado.
::

O mesmo cast protege o `incidents.raw_payload`, o payload original de cada erro recebido.

## Gravação: criar e atualizar

**Criar** (`CreateConnectorAction`): guarda só as chaves de `allowedCredentials()` do tipo e descarta valores vazios. Uma chave desconhecida enviada pelo cliente é ignorada.

**Atualizar** (`UpdateConnectorAction` + `UpdateConnectorRequest`): é um **merge** sobre o que já está salvo.

| Enviado em `credentials` | Resultado |
|---|---|
| Chave ausente | Valor atual mantido |
| Chave com valor novo | Substitui (rotação de um segredo só) |
| Chave opcional com `null` ou `""` | Removida |
| Chave obrigatória vazia | `422` (regra `sometimes|required`) |
| `type` | Proibido: o tipo define as credenciais e não muda |

Isso permite que o painel **gire um segredo sem conhecer os outros**, já que a API nunca os devolve. No formulário (`ConnectorFormSlideover.vue`), campo já configurado aparece com o placeholder `••••••••••••  (valor atual mantido)`, e só os campos preenchidos entram no payload.

## O que a API devolve

O `ConnectorResource` troca o array de credenciais por um mapa **chave → configurada?**, com todas as chaves aceitas pelo tipo:

```json
{
  "id": "9d3c…",
  "type": "bitbucket",
  "name": "Bitbucket da empresa",
  "settings": { "workspace": "minha-empresa" },
  "status": "active",
  "credentials": {
    "access_token": true,
    "runner_token": false
  },
  "last_error": null,
  "last_verified_at": "2026-11-16T13:40:02.000000Z"
}
```

O painel usa esses booleanos para o aviso "Credenciais obrigatórias não configuradas" no card e para o placeholder do formulário. **Não existe rota** que devolva o valor de uma credencial, nem mascarado.

O resultado do **Testar conexão** (`POST /api/v1/connector/{id}/test`) também não traz segredos: só se deu certo, uma mensagem e detalhes como a lista de repositórios e se o `runner_token` é somente leitura (`read_only`) ou não está configurado.

## Rotação na auditoria

Trocar uma credencial gera o evento `credentials_updated` com **os nomes** dos campos alterados:

```json
{
  "event": "credentials_updated",
  "description": "Credenciais alteradas: access_token",
  "properties": { "changed_fields": ["access_token"] }
}
```

Na criação, o registro `created` leva `configured_fields`. Mesmo que um valor escapasse por outro caminho, a [auditoria](/seguranca/auditoria) passa tudo pelo `SensitiveDataMasker`, e `credential` está na lista de chaves sensíveis.

## Credenciais que vão para o runner

O runner é o lugar mais exposto: é onde os agentes executam comandos. Ele recebe **só duas** credenciais:

| Credencial | Como chega | Quanto tempo fica |
|---|---|---|
| Token do repositório | Pela **entrada padrão** do container (`REPO_TOKEN_STDIN=1`), nunca por variável de ambiente | Usado no clone via `GIT_ASKPASS`; o `entrypoint.sh` faz `unset` antes de instalar dependências e de iniciar os agentes |
| Chave do Claude | `ANTHROPIC_API_KEY` ou `CLAUDE_CODE_OAUTH_TOKEN`, da configuração do FireWatch (não de um conector) | Toda a execução, porque o Claude Code precisa dela |

Detalhes que fecham as brechas:

- **`runner_token` primeiro.** O `DockerRunner::repositoryToken()` usa o `runner_token` (somente leitura, escopo mínimo) quando existe e só cai no `access_token` se ele faltar. O token de escrita fica com o Laravel, que é quem cria a branch e abre o PR.
- **Nada na linha de comando.** Variáveis vão como `--env NOME`, sem valor, lidas do ambiente do processo `docker`; assim não aparecem no `ps`.
- **Nada no ambiente inicial.** O token do repositório não vai por `-e` porque o ambiente inicial fica legível em `/proc/1/environ` e no `docker inspect`, mesmo depois de um `unset`.
- **Mascaramento na saída.** URLs com credenciais e prefixos de token (`ATCTT`, `ghp_`, `sk-ant-`…) são mascarados no stream dos agentes antes de virar evento (veja [Mascaramento](/seguranca/mascaramento)).

## Checklist para um conector novo

1. Declare as chaves em `requiredCredentials()` / `optionalCredentials()` do `ConnectorTypeEnum`.
2. Leia sempre com `$connector->credential('chave')`, nunca com `$connector->credentials`.
3. Não coloque a credencial em mensagens de exceção, `Log::*` ou `report`.
4. Se o token tiver prefixo conhecido, inclua o padrão no `SensitiveDataMasker` e um teste.
5. No painel, declare o campo em `credentials` do tipo em `utils/connectorTypes.ts`. Todo campo que não é `inputType: 'email'` usa o `ConnectorSecretInput` (valor oculto); `generatable: true` adiciona o botão de gerar segredo.
